DARS 02 · GIT ASOSLARI

Git'ning yuragi: 3 hudud va commit aylanasi

Bu darsdan keyin fayllaringiz Git ichida qayerda turishini bilasiz va tahrirla → add → commit aylanasini ishonch bilan bajarasiz.

📱 O'qish ≈ 7 daqiqa 💻 Amaliyot ≈ 10 daqiqa Kerak: Dars 01

Nega bu muhim

Jamoada har bir commit — bitta mantiqiy o'zgarish bo'lgani ma'qul (toza tarix). Buning siri — staging area. Uni tushunsangiz, commitlaringiz tartibli va hamkasblaringizga tushunarli bo'ladi. Toza tarix esa keyinchalik xatoni topish va ortga qaytarishni osonlashtiradi.

Eslatma

O'tgan darsda siz haqiqiy git commit qildingiz (e6a5f3b)! Aslida fayllaringiz uchta "hudud" orqali o'tdi. Keling, o'sha sirni ochamiz. 🔍

Uchta hudud (the three areas)

Git'da fayllaringiz uchta joyda "yashaydi". Bir marta commit qilganda, ular shu yo'lni bosib o'tadi:

Ish papkasi

Working Directory
Siz tahrirlab turgan fayllar. Hozir ko'rinadigan papka.
→git add

Saralash joyi

Staging Area
Keyingi commitga tanlangan o'zgarishlar. "Oraliq savat".
→git commit

Ombor (tarix)

Repository
Doimiy saqlangan tarix — yashirin .git papkasi.
  • Working Directory — fayllarni yaratasiz va tahrirlaysiz. Bu — oddiy papkangiz, uni fayl menejerida ham ko'rasiz.1
  • Staging Area — git add bilan qaysi o'zgarishlarni keyingi commitga qo'shishni tanlaysiz. Bu haqiqiy papka emas — bu Git ichidagi ro'yxat (shuning uchun ba'zan index deb ham ataladi).
  • Repository — git commit bilan tanlanganlar doimiy tarixga yoziladi. Bu ma'lumot loyihangizdagi yashirin .git papkasida turadi; uni o'chirmang — tarix o'sha yerda.

Restoran metaforasi 🍽️

Uchta hududni eslab qolishning oson yo'li:

  • Working directory = oshxona. Bu yerda pishirasiz, tuzatasiz, xato qilasiz.
  • Staging area = podnos. Tayyor bo'lgan taomlarni podnosga tanlab qo'yasiz — hammasini emas, bitta buyurtmaga tegishlisini.
  • Repository = mijoz stoli. Podnosdagi narsa stolga chiqdi — endi u rasman "berilgan" va yozib qo'yilgan.

Fayl qanday holatlarda bo'ladi?

Git har bir faylni to'rt holatdan birida ko'radi. git status aynan shuni aytadi:1

  • untracked — yangi fayl, Git uni hali umuman kuzatmaydi. (git status: "Untracked files")
  • modified — Git kuzatadigan fayl o'zgardi, lekin hali add qilinmagan. ("Changes not staged for commit")
  • staged — add qilingan, keyingi commitga tayyor. ("Changes to be committed")
  • committed — tarixga xavfsiz yozilgan. git status tinch: "nothing to commit, working tree clean".

Commit aylanasi (har kungi ish)

Kundalik Git ishi shu oddiy aylanadan iborat:

  1. Faylni tahrirla → Working Directory
  2. git add <fayl> — saralash joyiga qo'y → Staging
  3. git commit -m "izoh" — tarixga saqla → Repository
  4. (keyinroq) git push — GitHub'ga yukla

Kuniga o'nlab marta shu aylanani aylanasiz. Boshqa hamma narsa — branch, merge, pull request — shu aylananing atrofiga quriladi.

Nega "saralash joyi" (staging) kerak?

Tasavvur qiling: bugun 3 ta faylni o'zgartirdingiz —

  • login.js va login.css — login sahifasini tuzatdingiz;
  • README.md — yo'l-yo'lakay imlo xatosini to'g'irladingiz.

Agar hammasini bitta commitga qo'shsangiz, tarixda "login + imlo" degan chalkash qadam paydo bo'ladi. git add bilan aynan o'sha 2 tasini tanlab, alohida toza commit qilasiz, keyin README'ni alohida.2

Natijada tarix o'qiladigan bo'ladi: har commit — bitta fikr. Ertaga login buzilsa, o'sha bitta commitni topib ortga qaytarasiz, README'ga tegmasdan.

Sizning ko'zoynagingiz: git status va git log

  • git status — hozir fayllar qaysi hududda (untracked? modified? staged?). U shuningdek "endi nima qilsangiz bo'ladi"ni ham maslahat beradi.
  • git log — shu paytgacha qilingan barcha commitlar tarixi. git log --oneline — qisqa, har commit bitta qatorda.

Chalkashib qolsangiz — doim git status deng. Bu buyruq hech narsani o'zgartirmaydi, faqat ko'rsatadi: xohlagancha ishlatavering. 🧭

Amaliyot: ikkinchi commitingizni qiling

Kurs papkangizda (~/Projects/Learn/Git) mashq.txt nomli fayl bor. Uni tarixga qo'shamiz — va har qadamda git status bilan faylning hududi qanday o'zgarayotganini o'z ko'zingiz bilan ko'rasiz.

  1. Boshlang'ich holatni ko'ring

    Fayl hali Git uchun begona — "untracked" bo'lishi kerak.

    git status Untracked files: mashq.txt

    Kutilgan natija: mashq.txt "Untracked files" ro'yxatida. Ya'ni: fayl working directoryda, Git uni hali kuzatmaydi.

  2. Faylni saralash joyiga qo'ying

    Bu — "podnosga qo'yish". Hali tarixga yozilmadi.

    git add mashq.txt

    Kutilgan natija: jimlik (= muvaffaqiyat).

  3. Hudud o'zgarganini tekshiring

    Bu darsning eng muhim qadami — o'zgarishni ko'rish.

    git status Changes to be committed: new file: mashq.txt

    Kutilgan natija: endi "Changes to be committed" — fayl staging areaga o'tdi. Rangi ham qizildan yashilga o'zgaradi.

  4. Tarixga saqlang

    -m = message (izoh). Izoh nima o'zgarganini aytsin: "fayl qo'shildi" emas, "mashq fayli qo'shildi".

    git commit -m "Amaliyot fayli qo'shildi" [main 1a2b3c4] Amaliyot fayli qo'shildi 1 file changed, 1 insertion(+)

    Kutilgan natija: commit hash (masalan 1a2b3c4) va nechta fayl o'zgargani. Bu — sizning ikkinchi qo'lda qilgan commitingiz. 🎉

  5. Tarixni ko'ring

    Endi tarixda bir nechta commit bor — o'zingiz qurgan tarix.

    git log --oneline 1a2b3c4 Amaliyot fayli qo'shildi 08ade4d DARS 02 qo'shildi: 3 hudud va commit aylanasi e6a5f3b Birinchi commit: kurs sayti va DARS 01

    Kutilgan natija: commitlar yangisidan eskisiga qarab ro'yxat. Chiqish uchun q bosing.

  6. Yakuniy tekshiruv

    Toza working tree — "hammasi saqlangan" degani.

    git status nothing to commit, working tree clean

    Kutilgan natija: "working tree clean". Bu Git'dagi eng tinchlantiruvchi jumla. 😌

Foydali qo'shimchalar

git add . — joriy papkadagi hamma o'zgarishni qo'shadi (tez, lekin ehtiyot bo'ling: keraksiz fayl ham tushib qolishi mumkin).
git status -s — qisqa ko'rinish (?? = untracked, A = added, M = modified).
git restore --staged <fayl> — noto'g'ri add qilsangiz, podnosdan qaytarib olish.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda mashq.txt faylini tarixga qo'shasiz va har qadamda git status bilan faylning hududi qanday o'zgarishini kuzatasiz: status → add → status → commit → log. Kompyuterda ochganingizda 6 qadamlik yo'riqnoma, Copy tugmasi va kutilgan natijalar chiqadi.

Tekshirib ko'ramiz (quiz)

SAVOL 1 git add faylni qayerdan-qayerga o'tkazadi?

To'g'ri — git add o'zgarishni ish papkasidan saralash joyiga qo'yadi. Repository'ga esa keyin git commit olib o'tadi.

SAVOL 2 Nega staging area (saralash joyi) kerak?

Aynan — staging sizga tanlash imkonini beradi: hamma narsani emas, balki bitta mavzuga oid o'zgarishlarni toza commit qilasiz.

SAVOL 3 Holat va tarixni ko'rish uchun qaysi buyruqlar?

To'g'ri — git status hozirgi holatni, git log esa commitlar tarixini ko'rsatadi. Bular sizning "ko'zoynagingiz".

SAVOL 4 Yangi yaratilgan, hali add qilinmagan fayl qanday ataladi?

To'g'ri — untracked. git add dan keyin u staged bo'ladi, git commit dan keyin esa committed.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 1-darsni takrorlash (eski bilimni qayta eslash uni mustahkamlaydi).

Uchta hudud qaysilar — tartibi bilan?

Working Directory → Staging Area → Repository. Orasidagi buyruqlar: git add, keyin git commit.

Restoran metaforasida podnos nima edi?

Staging area — bitta buyurtmaga tegishli taomlarni tanlab qo'yadigan joy. Oshxona = working directory, stol = repository.

Faylning to'rt holati qaysilar?

untracked → modified → staged → committed.

Nega hammasini bitta commitga tashlash yomon?

Tarix chalkashadi. Har commit bitta fikr bo'lsa, xatoni topish ham, faqat o'sha o'zgarishni ortga qaytarish ham oson bo'ladi.

Chalkashib qoldingiz. Birinchi navbatda qaysi buyruq?

git status. U hech narsani o'zgartirmaydi — faqat holatni ko'rsatadi va keyingi qadamni maslahat beradi.

↩︎ Takrorlash: commit ichida qaysi 4 narsa saqlanadi?

Snapshot · muallif (ism + email) · vaqt · izoh. (Dars 01)

↩︎ Takrorlash: --global nimani anglatadi?

"Shu kompyuterdagi barcha loyihalar uchun" — ~/.gitconfig fayliga yoziladi.

Cho'ntak xulosasi
  • Uch hudud: Working → git add → Staging → git commit → Repository.
  • Fayl holatlari: untracked → modified → staged → committed.
  • Staging = tanlash: har commit bitta fikr bo'lsin.
  • git status = hozir qayerdaman · git log --oneline = tarix.
  • Git'da jimlik = muvaffaqiyat; "working tree clean" = hammasi saqlangan.
