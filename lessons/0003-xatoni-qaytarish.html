DARS 03 · MODUL A · POYDEVOR

Xato qildim: ko'rish va ortga qaytarish

Bu darsdan keyin siz Git'dan qo'rqmaysiz. Uch hududning har birida qilingan xatoni qanday qaytarishni bilasiz — va qaytarishdan oldin nima o'zgarganini o'z ko'zingiz bilan ko'rasiz.

📱 O'qish ≈ 7 daqiqa 💻 Amaliyot ≈ 12 daqiqa Kerak: Dars 02

Nega bu dars aynan hozir

Missiyangizning birinchi jumlasi — jamoada qo'rqmasdan ishlash. Qo'rquv esa bitta savoldan tug'iladi: "buzib qo'ysam-chi?" Orqaga qaytishni bilsangiz, bu savol kuchini yo'qotadi. Shundan keyin bemalol tajriba qilasiz — o'rganish ham ana shunda tezlashadi.

Asosiy haqiqat: commit qilingan narsa xavfsiz

Git haqida eslab qolishingiz kerak bo'lgan eng muhim gap:

Oltin qoida

Commit qilingan narsani yo'qotish juda qiyin. Commit qilinmagan narsani yo'qotish esa oson.1

Ya'ni: git commit — bu shunchaki "saqlash" emas, bu xavfsizlik yostig'i. Qanchalik tez-tez commit qilsangiz, shunchalik kam xavf ostidasiz. Bugundan boshlab qoidangiz shu bo'lsin: biror narsa ishlab turibdimi — commit qiling.

1-qadam har doim bir xil: avval KO'RING

Hech qachon "ko'r-ko'rona" qaytarmang. Git'da ko'rish uchun to'rtta asbob bor — ularning hech biri hech narsani o'zgartirmaydi, shuning uchun xohlagancha ishlatavering:

BuyruqNimani ko'rsatadi
git status Fayllar qaysi hududda — ya'ni xato qayerda sodir bo'lgan.
git diff Hali add qilinmagan o'zgarishlar — satrma-satr nima o'zgargani.2
git diff --staged add qilingan, lekin hali commit qilinmagan o'zgarishlar.
git show Oxirgi commit ichida nima bo'lganini. git show a1b2c3d — aniq bir commitni.
git diff chiqishini o'qish

- bilan boshlangan qator — o'chirilgan (qizil). + bilan boshlangani — qo'shilgan (yashil). Boshqa qatorlar shunchaki atrofdagi kontekst. Uzun bo'lsa q bilan chiqasiz.

2-qadam: xato qaysi hududda?

Mana darsning yuragi. 2-darsdagi uch hudud esingizdami? Qaytarish usuli ham aynan shu uchtaga bo'linadi. Xato qayerda bo'lsa — o'sha hududning buyrug'ini ishlatasiz:

Ish papkasi

Working Directory
Faylni tahrirlab xato qildim, hali add qilmadim

↩︎ git restore fayl

Saralash joyi

Staging Area
Keraksiz faylni add qilib yubordim

↩︎ git restore --staged fayl

Ombor (tarix)

Repository
Commit qildim, lekin izohi xato

↩︎ git commit --amend

Uchtasining farqi — batafsil

BuyruqNima qiladi
git restore fayl.txt Fayldagi saqlanmagan o'zgarishlarni o'chirib, uni oxirgi saqlangan holatiga qaytaradi. ⚠️ Xavfli: bu o'zgarishlar butunlay yo'qoladi — Git ularni hech qayerda saqlamagan edi. Avval git diff bilan ko'ring!
git restore --staged fayl.txt Faylni saralash joyidan chiqaradi — «podnosdan qaytarib olish». ✓ Xavfsiz: faylning o'zi va o'zgarishlaringiz joyida qoladi, faqat holati staged dan modified ga qaytadi.
git commit --amend -m "yangi izoh" Oxirgi commitni almashtiradi: izohini tuzatadi, yoki unutilgan faylni qo'shib qo'yadi (avval git add qiling). ✓ Xavfsiz — lekin faqat hali push qilinmagan commit uchun. Nega — 4-darsda ko'ramiz.
Ikkalasi ham «restore», lekin bittasi xavfli

git restore fayl va git restore --staged fayl — nomi bir xil, ta'siri butunlay boshqa. Farqni eslab qolishning yo'li: --staged bo'lsa — faqat holat o'zgaradi, matn tegilmaydi (xavfsiz). --staged bo'lmasa — matnning o'zi qaytariladi (o'zgarishlar yo'qoladi).

Amaliyot: uch xil xatoni o'zingiz qaytaring

Bu safar biz ataylab xato qilamiz va uchalasini ham qaytaramiz. Hech narsa buzilmaydi — hammasi mashq.txt fayli ustida bo'ladi.

Terminalda kurs papkangizga o'ting:

cd ~/Projects/Learn/Git

  1. Avval 2-darsning qarzini uzamiz

    mashq.txt hali commit qilinmagan edi. Qaytarish mashqi uchun fayl kuzatilayotgan bo'lishi shart.

    git add mashq.txt && git commit -m "Amaliyot fayli qo'shildi"

    Kutilgan natija: 1 file changed, 1 insertion(+). Endi mashq.txt tarixda. ✅

  2. Ataylab «xato» qiling

    >> — faylga yangi qator qo'shadi (mavjud matnni o'chirmaydi). Matn muharririda qo'lda yozsangiz ham bo'ladi.

    echo "Bu qator xato edi." >> mashq.txt

    Kutilgan natija: jimlik. Faylga bitta qator qo'shildi.

  3. Qaytarishdan OLDIN ko'ring

    Bu odatni birinchi kundan shakllantiring: avval ko'r, keyin qaytar.

    git diff --- a/mashq.txt +++ b/mashq.txt Salom! Bu mening birinchi Git amaliyot faylim. +Bu qator xato edi.

    Kutilgan natija: + belgili yashil qator — aynan siz qo'shgan matn. Chiqish uchun q.

  4. 🔴 1-xato: ish papkasidagi o'zgarishni qaytaring

    Bu — «xavfli» variant. Ammo hozir aynan shuni xohlaymiz: o'zgarish keraksiz edi.

    git restore mashq.txt

    Kutilgan natija: jimlik. Endi git diff deng — bo'sh chiqadi. Qator yo'qoldi, fayl asl holiga qaytdi. 1-g'alaba. 🎉

  5. 🟠 2-xato: keraksiz narsani add qiling

    Endi ikkinchi hudud — saralash joyidagi xato.

    echo "Bu ham keraksiz." >> mashq.txt && git add mashq.txt

    Kutilgan natija: jimlik. git status deng — «Changes to be committed» ko'rinadi. Fayl stagingda.

  6. Podnosdan qaytarib oling

    Diqqat: bu buyruq matnni o'chirmaydi, faqat holatini qaytaradi.

    git restore --staged mashq.txt

    Kutilgan natija: git status endi «Changes not staged for commit» deydi — fayl staged dan modified ga qaytdi, matn esa joyida. 2-g'alaba. 🎉

  7. Tozalab qo'ying

    Keyingi mashq uchun fayl toza bo'lsin — 1-usulni yana ishlatamiz.

    git restore mashq.txt

    Kutilgan natija: git status → «working tree clean».

  8. 🟡 3-xato: yomon izoh bilan commit qiling

    Ataylab foydasiz izoh yozamiz — keyin tuzatamiz.

    echo "Uchinchi mashq qatori." >> mashq.txt && git commit -am "asdf"

    Kutilgan natija: [main ...] asdf. -am = add + commit birga (faqat kuzatilayotgan fayllar uchun ishlaydi).

  9. Oxirgi commit izohini tuzating

    Tarix — hamkasblaringiz o'qiydigan hujjat. «asdf» hech kimga hech narsa aytmaydi.

    git commit --amend -m "Mashq fayliga uchinchi qator qo'shildi"

    Kutilgan natija: git log --oneline deng — «asdf» yo'q, o'rnida yangi izoh turibdi. 3-g'alaba. 🎉

  10. Nima qilganingizni ko'ring

    git show — oxirgi commit ichidagi aniq o'zgarish.

    git show

    Kutilgan natija: commit ma'lumoti (muallif, sana, izoh) va ostida +Uchinchi mashq qatori. Chiqish: q.

Bilib qo'ying

git restore — Git 2.23 dan beri bor. Internetdagi eski maqolalarda shu ish uchun git checkout -- fayl va git reset HEAD fayl yozilgan bo'ladi. Ular hamon ishlaydi, lekin restore ancha tushunarliroq — biz shuni ishlatamiz.3

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda mashq.txt ustida ataylab uch xil xato qilasiz va uchalasini ham qaytarasiz: ish papkasidagi o'zgarish → git restore, keraksiz add → git restore --staged, yomon commit izohi → git commit --amend. 10 qadam, hammasi xavfsiz.

Tekshirib ko'ramiz (quiz)

SAVOL 1 Qaytarishdan oldin birinchi navbatda nima qilasiz?

To'g'ri — avval ko'r, keyin qaytar. git diff va git status hech narsani o'zgartirmaydi, shuning uchun xavfsiz.

SAVOL 2 Keraksiz faylni add qilib yubordingiz. Nima qilasiz?

Aynan — --staged faylni staging'dan chiqaradi. Matningiz va o'zgarishlaringiz butunlay saqlanib qoladi.

SAVOL 3 Qaysi buyruq o'zgarishlaringizni butunlay yo'qotishi mumkin?

To'g'ri. --stagedsiz restore — yagona xavfli buyruq: commit qilinmagan o'zgarish qaytmaydi. Shuning uchun undan oldin git diff.

SAVOL 4 Git'da nimani yo'qotish eng qiyin?

To'g'ri — commit qilingan narsa xavfsiz. Shuning uchun tez-tez commit qiling: har commit — orqaga qaytish nuqtasi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — oldingi darslarni takrorlash.

Git'ning «oltin qoidasi» nima edi?

Commit qilingan narsani yo'qotish juda qiyin, commit qilinmaganini esa oson. Shuning uchun tez-tez commit qiling.

Uch hudud, uch qaytarish — qaysi biri qaysiga?

Working directory → git restore fayl · Staging → git restore --staged fayl · Oxirgi commit → git commit --amend.

Bu uchtadan qaysi biri xavfli — va nega?

git restore fayl (--stagedsiz). Chunki u commit qilinmagan o'zgarishni o'chiradi — Git uni hech qayerda saqlamagan, demak qaytarib bo'lmaydi.

git diff va git diff --staged farqi?

git diff — hali add qilinmagan o'zgarishlar. git diff --staged — add qilingan, lekin hali commit qilinmagan o'zgarishlar.

git diff chiqishida + va - nima?

+ — qo'shilgan qator (yashil), - — o'chirilgan qator (qizil).

↩︎ Takrorlash: uchta hudud qaysilar — tartibi bilan?

Working Directory → Staging Area → Repository. (Dars 02)

↩︎ Takrorlash: commit ichida qaysi 4 narsa saqlanadi?

Snapshot · muallif (ism + email) · vaqt · izoh. (Dars 01)

Cho'ntak xulosasi
  • Oltin qoida: commit qilingan narsa xavfsiz. Tez-tez commit qiling.
  • Avval ko'r: git status · git diff · git diff --staged · git show — hech biri hech narsani buzmaydi.
  • Keyin qaytar — xato qaysi hududda bo'lsa, o'sha hududning buyrug'i bilan:
  • Ish papkasi → git restore fayl  ⚠️ o'zgarish yo'qoladi
  • Staging → git restore --staged fayl  ✓ xavfsiz
  • Oxirgi commit → git commit --amend -m "..."  ✓ xavfsiz (push'dan oldin)
