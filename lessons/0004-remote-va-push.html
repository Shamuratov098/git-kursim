Remote va push: ishim GitHub'da

Bu darsdan keyin siz kompyuteringizdagi commitlarni GitHub'ga o'z qo'lingiz bilan chiqarasiz — va natijasini bir necha daqiqada telefoningizda ko'rasiz.

📱 O'qish ≈ 7 daqiqa 💻 Amaliyot ≈ 10 daqiqa Kerak: Dars 03

Nega bu muhim

Shu paytgacha butun ishingiz bitta kompyuterda edi. Kompyuter buzilsa — hammasi ketadi; hamkasbingiz ko'rmoqchi bo'lsa — ko'ra olmaydi. push shu ikkala muammoni ham bir vaqtda yechadi. Va bu — pull requestning (jamoa ishining yuragi) birinchi sharti.

Remote (origin)
Internetdagi nusxa

Chapdagi uchtasi — kompyuteringizda, oxirgisi — internetda. git push aynan shu chegaradan o'tkazadi.

Atamalar: remote va origin

  • remote — loyihangizning internetdagi nusxasi (bizda: GitHub'dagi repo). Git'ga bir nechta remote qo'shish mumkin, lekin odatda bittasi bo'ladi.1
  • origin — o'sha remote'ning nomi. Sehrli so'z emas, shunchaki kelishilgan odatiy nom: «asosiy manzil».
  • origin/main — bu siz oxirgi marta ko'rgan GitHub holatining xatcho'pi (belgisi). Git'ning GitHub'dagi main haqidagi xotirasi — va u faqat siz aloqaga chiqqanda yangilanadi.
Sizda allaqachon bor

Kurs repongiz GitHub'da: Shamuratov098/git-kursim. Ya'ni git init ham, remote ulash ham allaqachon bajarilgan — bugun siz faqat pushni o'rganasiz. Yangi loyihada remote'ni noldan ulash 5-darsda bo'ladi.

git push aslida nima jo'natadi?

Bu yerda yangi boshlovchilar eng ko'p adashadigan nuqta bor:

Eng muhim ogohlantirish

push faqat commit qilingan narsani jo'natadi. Faylni tahrirlab, add va commit qilmasdan push qilsangiz — GitHub'da hech narsa o'zgarmaydi. Git sizga xato ham ko'rsatmaydi, chunki uning nazarida jo'natadigan yangi commit yo'q.

Shuning uchun tartib doim bir xil: add → commit → push.

Aniqroq aytganda, push — bu «GitHub'da yo'q commitlarimni ol» degani. U butun faylni emas, faqat yetishmayotgan commitlarni jo'natadi.

Buyruqning bo'laklari

git push

Odatda shuncha. Lekin birinchi marta (yangi branch yoki yangi repo uchun) Git qayerga jo'natishni bilmaydi va uzunroq shakl kerak bo'ladi:

git push -u origin main
  • origin — qaysi remote'ga;
  • main — qaysi branch'ni;
  • -u — «buni eslab qol». Shundan keyin oddiy git push yetarli bo'ladi.2

Sizning main branch'ingizda -u allaqachon o'rnatilgan — shuning uchun siz doim qisqa git push yozasiz.

Parol so'ralmaydi

Kompyuteringizda gh (GitHub CLI) orqali kirish allaqachon sozlangan, shuning uchun git push sizdan parol so'ramaydi. GitHub 2021-yildan beri parolni qabul qilmaydi — uning o'rniga token ishlatiladi, va gh buni siz uchun boshqaradi.3

Push'dan keyin: --amend qilmang

3-darsda git commit --amend ni o'rgangan edik — u oxirgi commitni almashtiradi. Endi sababini tushunasiz: commit push qilingandan keyin u boshqalarda ham bor. Uni almashtirsangiz, sizning tarixingiz ular ko'rgan tarixdan farq qila boshlaydi va Git chalkashadi.

Sodda qoida

Push qilingunga qadar — tarixni tuzatish mumkin (--amend). Push qilingandan keyin — tuzatmaymiz, ustiga yangi commit qo'shamiz.

Amaliyot: o'z commitlaringizni GitHub'ga chiqaring

3-darsda qilgan commitlaringiz hozircha faqat kompyuteringizda. Ularni GitHub'ga chiqaramiz — va sayt yangilanganini telefoningizda ko'rasiz.

cd ~/Projects/Learn/Git

  1. Remote kimligini ko'ring

    Git qayerga jo'natishini bilamizmi?

    git remote -v origin https://github.com/Shamuratov098/git-kursim.git (fetch) origin https://github.com/Shamuratov098/git-kursim.git (push)

    Kutilgan natija: ikki qator — biri olish (fetch), biri jo'natish (push) uchun. Manzil bir xil.

  2. Nechta commit «kutib turibdi»?

    Git o'zi aytib beradi: siz GitHub'dan qancha oldindasiz.

    git status On branch main Your branch is ahead of 'origin/main' by 2 commits.

    Kutilgan natija: «ahead of 'origin/main' by N commits». Bu N ta commit hali faqat sizda.

  3. Xatcho'pni ko'z bilan ko'ring

    Tarixda origin/main qayerda turganini ko'rish — push nima qilishini oldindan tushunishning eng yaxshi yo'li.

    git log --oneline -4 9f8e7d6 (HEAD -> main) Mashq fayliga uchinchi qator qo'shildi 3c4d5e6 Amaliyot fayli qo'shildi 1a2b3c4 (origin/main) DARS 03 va 04 qo'shildi

    Kutilgan natija: HEAD -> main yuqorida, origin/main esa pastroqda. Ana shu farq — jo'natiladigan commitlar.

  4. Jo'nating

    Mana shu — darsning asosiy buyrug'i.

    git push Enumerating objects: 8, done. To https://github.com/Shamuratov098/git-kursim.git 1a2b3c4..9f8e7d6 main -> main

    Kutilgan natija: oxirgi qatorda main -> main. Parol so'ralmaydi. G'alaba! 🎉

  5. Xatcho'p ko'chganini tekshiring

    Endi origin/main sizning oxirgi commitingizga yetib oldi — GitHub va kompyuteringiz bir xil holatda.

    git log --oneline -3 9f8e7d6 (HEAD -> main, origin/main) Mashq fayliga uchinchi qator...

    Kutilgan natija: HEAD -> main va origin/main endi bir qatorda.

  6. Git ham tasdiqlasin

    git status Your branch is up to date with 'origin/main'. nothing to commit, working tree clean

    Kutilgan natija: «up to date». Hammasi joyida. 😌

  7. GitHub'da o'z ko'zingiz bilan ko'ring

    Commitlaringiz endi internetda — muallif sifatida siz ko'rinasiz (1-darsdagi email sozlamasi shuning uchun kerak edi).

    xdg-open https://github.com/Shamuratov098/git-kursim/commits/main

    Kutilgan natija: brauzerda commitlar ro'yxati ochiladi — yozgan izohlaringiz va yoningizda avataringiz.

  8. 📱 Telefoningizda tekshiring

    GitHub Pages saytni 1–2 daqiqada qayta quradi. Bu — push'ning real natijasi.

    https://shamuratov098.github.io/git-kursim/

    Kutilgan natija: telefoningizda kurs sayti ochiladi va yangi darslar ko'rinadi. Siz push qilganingiz uchun. 🎉📱

Bundan keyingi odatingiz

Kompyuterda biror ish qilganingizdan keyin uch buyruq — va ishingiz xavfsiz hamda telefoningizda:

git add . && git commit -m "izoh" && git push

Boshida uchtasini alohida yozgan ma'qul — git status bilan har qadamni ko'rib boring.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda git remote -v bilan origin'ni ko'rasiz, git log da origin/main xatcho'pi qayerda turganini topasiz, keyin git push qilasiz va xatcho'p ko'chganini kuzatasiz. Oxirida — GitHub'da commitlaringizni va telefoningizda yangilangan saytni ko'rasiz.

Tekshirib ko'ramiz (quiz)

SAVOL 1 Faylni tahrirlab, darrov git push qildingiz. GitHub'da nima o'zgaradi?

To'g'ri — bu eng ko'p uchraydigan chalkashlik. push faqat commit qilingan narsani ko'radi. Tartib doim: add → commit → push.

SAVOL 2 origin nima?

Aynan — origin shunchaki nom. U sizning GitHub'dagi repongizga ishora qiladi. Sehrli so'z emas, kelishuv.

SAVOL 3 Commitni push qildingiz, keyin izohida xato ko'rdingiz. Nima qilasiz?

To'g'ri. Push qilingan commit boshqalarda ham bor — uni almashtirish tarixni ikkiga bo'lib yuboradi. Qoida: push'gacha tuzat, push'dan keyin ustiga qo'sh.

SAVOL 4 origin/main nimani bildiradi?

To'g'ri — bu xotira, jonli aloqa emas. U faqat siz push, pull yoki fetch qilganingizda yangilanadi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — oldingi darslarni takrorlash.

To'liq rasm: to'rt joy va uch buyruq?

Working Directory →git add→ Staging Area →git commit→ Local Repository →git push→ GitHub (remote).

push nimani jo'natadi — va nimani jo'natmaydi?

Faqat commit qilingan narsani jo'natadi. Tahrirlangan, lekin commit qilinmagan o'zgarishlarni ko'rmaydi ham — GitHub'da hech narsa o'zgarmaydi.

origin va origin/main farqi?

origin — remote'ning nomi (manzil). origin/main — o'sha remote'dagi main branch'ini oxirgi ko'rganingizdagi holat xatcho'pi.

-u (yoki --set-upstream) nima uchun?

«Bu branch qayerga push bo'lishini eslab qol» degani. Bir marta git push -u origin main deysiz, keyin doim qisqa git push yetarli.

Push'dan keyin commit izohini tuzatsa bo'ladimi?

Yo'q. --amend — faqat push'gacha. Push'dan keyin tuzatishni yangi commit bilan qo'shasiz.

↩︎ Takrorlash: ish papkasidagi xatoni qanday qaytarasiz?

git restore fayl — lekin avval git diff bilan ko'ring, chunki o'zgarish yo'qoladi. (Dars 03)

↩︎ Takrorlash: nega commit email'i GitHub email'iga mos bo'lishi kerak?

Shunda commitlar GitHub'da sizning profilingizga bog'lanadi — jamoada «kim nima qildi» aniq ko'rinadi. (Dars 01)

Cho'ntak xulosasi
  • To'liq yo'l: Working →add→ Staging →commit→ Local repo →push→ GitHub.
  • remote = internetdagi nusxa · origin = uning odatiy nomi.
  • origin/main = GitHub'ni oxirgi ko'rgan holatingiz xatcho'pi.
  • push faqat commit qilingan narsani jo'natadi.
  • Birinchi marta: git push -u origin main · keyin doim: git push.
  • --amend — faqat push'gacha. Keyin: yangi commit.
