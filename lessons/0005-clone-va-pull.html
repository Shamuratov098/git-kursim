Clone va pull: ishimni qaytarib olish

Bu darsdan keyin siz GitHub'dagi loyihani istalgan kompyuterga ko'chirib olasiz va boshqalar qo'shgan yangiliklarni o'zingizga tortib olasiz. Ko'prik endi ikki tomonlama ishlaydi.

📱 O'qish ≈ 7 daqiqa 💻 Amaliyot ≈ 12 daqiqa Kerak: Dars 04

Nega bu muhim

Jamoaga qo'shilishning birinchi qadami aynan shu: sizga repo havolasi beriladi, siz uni clone qilasiz va ishga kirishasiz. Keyin esa har kuni hamkasblaringiz o'z ishlarini push qilib turadi — pull bo'lmasa, siz eskirgan kod ustida ishlaysiz va oxirida chalkashlik chiqadi.

Ko'prik ikki tomonlama

O'tgan darsda siz yuqoriga jo'natishni o'rgandingiz. Bugun — pastga olish:

Jamoaning umumiy nusxasi

Uchta yangi buyruq shu yo'nalishga tegishli — lekin ular bir xil emas:

  • git clone — loyiha sizda umuman yo'q. Noldan olasiz. Bir marta bajariladi.
  • git fetch — loyiha bor. Yangiliklarni keltiradi, lekin fayllaringizga tegmaydi.
  • git pull — loyiha bor. Yangiliklarni keltiradi va ishingizga qo'shadi.

git clone — bitta buyruqda to'rt ish

git clone https://github.com/foydalanuvchi/loyiha.git

Bu buyruq sirtdan oddiy ko'rinadi, lekin ichida to'rtta ish birdan bajariladi:1

  1. Yangi papka yaratadi (odatda repo nomi bilan).
  2. Loyihaning butun tarixini — hamma commitlarni — ko'chiradi. Faqat oxirgi holatni emas!
  3. origin nomli remote'ni avtomatik sozlaydi.
  4. Mahalliy main ni origin/main ga bog'laydi.
Shuning uchun clone'da -u kerak emas

4-darsda git push -u origin main ni ko'rgan edik — «qayerga push qilishni eslab qol». Clone qilingan loyihada bu allaqachon bajarilgan (4-band). Shuning uchun u yerda birinchi kundan qisqa git push ishlaydi.

«Distributed» degani shu edi

1-darsda Git tarqoq (distributed) tizim deganmiz. Mana isboti: clone sizga butun tarixni beradi. Internet uzilsa ham eski commitlarni ko'rasiz, taqqoslaysiz, ortga qaytasiz — hech kimdan so'ramasdan.

Papkaga boshqa nom bermoqchi bo'lsangiz, oxiriga yozasiz:

git clone https://github.com/foydalanuvchi/loyiha.git yangi-nom

pull = fetch + merge

Bu darsning eng muhim jumlasi. Tushunish uchun 4-darsdagi xatcho'p tushunchasini eslaylik: origin/main — bu GitHub'ni oxirgi ko'rganingizdagi holat. U o'zi yangilanmaydi.

BuyruqNima qiladi
git fetch GitHub bilan aloqaga chiqadi va origin/main xatcho'pini yangilaydi. Sizning fayllaringizga tegmaydi. ✓ Butunlay xavfsiz — «avval ko'ray-chi» uchun.
git merge Xatcho'pdagi yangi commitlarni sizning ishingizga qo'shadi — fayllaringiz o'zgaradi.
git pull Ikkalasi birga. Kundalik ishda odatda shuni ishlatasiz.2

Ya'ni fetch — «xabarni olib kel», merge — «olib kelinganini ishimga qo'sh». pull shu ikkisini bitta buyruqda bajaradi.

Nega bu farq muhim

Ishonchingiz komil bo'lmasa — avval git fetch, keyin git log --oneline main..origin/main bilan nima kelayotganini ko'ring, keyin qo'shing. Bu — 3-darsdagi «avval ko'r, keyin qil» odatining davomi.

Kundalik qoida: ish boshlashdan oldin pull

Jamoada bitta oddiy odat ko'p muammoni oldini oladi:

Har kuni, ishni boshlashdan oldin

1. O'z ishingizni commit qiling (yoki hech narsa o'zgartirmagan bo'ling) → 2. git pull → 3. endi ishlang.

Sabab: eskirgan kod ustida ishlasangiz, oxirida sizning va hamkasbingizning o'zgarishlari to'qnashadi — bu merge conflict deyiladi (8-darsda uni hal qilishni o'rganamiz). Muntazam pull to'qnashuvlarni kichik va oson saqlaydi.

Agar terminal g'alati tahrirlagichga o'tib qolsa

git pull ba'zan merge izohini so'rab, matn tahrirlagichni ochadi. Vahima qilmang: Ctrl+X (nano) yoki Esc keyin :wq va Enter (vim) bilan chiqasiz. Bunday holat bo'lsa — menga yozing, birga ko'ramiz.

Amaliyot: «ikkinchi kompyuter» yasab ko'ramiz

Ikkinchi kompyuter kerak emas — kurs repongizni ikkinchi papkaga clone qilamiz. U «hamkasbingizning kompyuteri» rolini o'ynaydi. Keyin bir papkada o'zgarish qilib push qilasiz va ikkinchisida pull bilan olasiz.

Ikki papka — chalkashmang

~/Projects/Learn/Git — asl papkangiz (kurs shu yerda).
~/Projects/Learn/Git-nusxa — bugun yasaydigan nusxa.
Har qadamda qaysi papkada ekaningizga e'tibor bering — buyruqlarda yozib qo'ydim.

  1. Nusxa yasaladigan joyga o'ting

    Clone joriy papka ichida yangi papka yaratadi.

    cd ~/Projects/Learn

    Kutilgan natija: jimlik. pwd deng — /home/dostonbek/Projects/Learn chiqishi kerak.

  2. Clone qiling

    Oxiridagi Git-nusxa — yaratiladigan papka nomi.

    git clone https://github.com/Shamuratov098/git-kursim.git Git-nusxa Cloning into 'Git-nusxa'... Receiving objects: 100% ... done.

    Kutilgan natija: «Cloning into 'Git-nusxa'...» va «done». Yangi papka paydo bo'ldi. 1-g'alaba. 🎉

  3. Nusxaga kirib, nima kelganini ko'ring

    Diqqat: butun tarix keldi — faqat oxirgi holat emas.

    cd Git-nusxa && git log --oneline 4c20049 Kurs arxitekturasi va DARS 03-04 qo'shildi 08ade4d DARS 02 qo'shildi: 3 hudud va commit aylanasi e6a5f3b Birinchi commit: kurs sayti va DARS 01

    Kutilgan natija: barcha commitlar — birinchisidan oxirgisigacha. Chiqish: q.

  4. Remote avtomatik sozlanganini tekshiring

    Siz git remote add qilmadingiz — clone o'zi qildi.

    git remote -v && git status origin https://github.com/Shamuratov098/git-kursim.git (fetch) Your branch is up to date with 'origin/main'.

    Kutilgan natija: origin joyida va main allaqachon origin/main ga bog'langan.

  5. Endi «hamkasb» rolini o'ynang — ASL papkaga qayting

    Bu — boshqa odam o'z kompyuterida ish qilgani.

    cd ~/Projects/Learn/Git

    Kutilgan natija: jimlik. Endi asl papkadasiz.

  6. «Hamkasb» o'zgarish qilib push qilsin

    Tanish uchlik: add → commit → push (Dars 02 va 04).

    echo "Bu qatorni hamkasbim qo'shdi." > hamkasb.txt && git add hamkasb.txt && git commit -m "Hamkasb fayli qo'shildi" && git push

    Kutilgan natija: commit ma'lumoti va oxirida main -> main. O'zgarish endi GitHub'da.

  7. Nusxaga qayting — u hali bexabar

    Eng qiziq qadam: nusxa hali bexabar.

    cd ~/Projects/Learn/Git-nusxa && git status Your branch is up to date with 'origin/main'.

    Kutilgan natija: «up to date» — lekin bu yolg'on! GitHub'da yangi commit bor. Git shunchaki eski xatcho'pga qarab turibdi.

  8. fetch bilan xatcho'pni yangilang

    Mana shu — fetch nima qilishini ko'rsatadigan qadam. Fayllaringizga hali tegilmaydi.

    git fetch && git status Your branch is behind 'origin/main' by 1 commit, and can be fast-forwarded.

    Kutilgan natija: endi «behind by 1 commit» deydi! Xatcho'p yangilandi. ls deng — hamkasb.txt hali yo'q. 2-g'alaba. 🎉

  9. Nima kelayotganini oldindan ko'ring

    «Avval ko'r, keyin qil» — 3-darsdagi odat.

    git log --oneline main..origin/main 7a8b9c0 Hamkasb fayli qo'shildi

    Kutilgan natija: sizda yo'q, lekin GitHub'da bor commitlar ro'yxati. Hozir bitta.

  10. Endi qo'shing

    pull = shu paytgacha qilganingiz (fetch) + qo'shish (merge).

    git pull Updating 4c20049..7a8b9c0 Fast-forward hamkasb.txt | 1 +

    Kutilgan natija: «Fast-forward» — ya'ni sizda ziddiyat yo'q edi, Git shunchaki oldinga siljidi. Endi ls deng — hamkasb.txt paydo bo'ldi! 3-g'alaba. 🎉

  11. Faylni o'qing va yakunlang

    cat hamkasb.txt && git status Bu qatorni hamkasbim qo'shdi. Your branch is up to date with 'origin/main'.

    Kutilgan natija: matn ko'rinadi va endi «up to date» — bu safar rostdan. 😌

Nusxa papkani nima qilaman?

Hozircha qoldiring — 6-darsda (branch) yana asqotadi. Keyinroq kerak bo'lmasa, o'chirishni birga qilamiz: papka o'chirish buyruqlari qaytarib bo'lmaydigan buyruqlar, shuning uchun uni yolg'iz bajarmang.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda kurs repongizni ikkinchi papkaga (Git-nusxa) clone qilasiz — u «hamkasbingizning kompyuteri» bo'ladi. Keyin asl papkada o'zgarish qilib push qilasiz, nusxaga qaytib git status ning «up to date» deb aldashini ko'rasiz, fetch bilan xatcho'pni yangilaysiz va pull bilan faylni olasiz. 11 qadam.

Tekshirib ko'ramiz (quiz)

SAVOL 1 git pull aslida qaysi ikki buyruqning yig'indisi?

To'g'ri — fetch yangiliklarni keltiradi, merge ularni ishingizga qo'shadi. pull ikkalasini bitta buyruqda bajaradi.

SAVOL 2 git fetch qilsangiz, fayllaringizga nima bo'ladi?

Aynan — shuning uchun fetch butunlay xavfsiz. U «xabarni olib keladi», lekin ishingizga tegmaydi.

SAVOL 3 git clone loyihaning nimasini olib keladi?

To'g'ri — bu Git'ning tarqoq (distributed) tabiati. Har bir nusxada to'liq tarix bor, shuning uchun internetsiz ham ishlaysiz.

SAVOL 4 Jamoada ish kunini qanday boshlaysiz?

To'g'ri. Eskirgan kod ustida ishlash — merge conflictning asosiy sababi. Muntazam pull to'qnashuvlarni kichik saqlaydi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — oldingi darslarni takrorlash.

pull = ... + ... ?

git fetch (yangiliklarni keltirish) + git merge (ularni ishingizga qo'shish).

clone bitta buyruqda qaysi 4 ishni qiladi?

1) Papka yaratadi · 2) butun tarixni ko'chiradi · 3) origin remote'ni sozlaydi · 4) main ni origin/main ga bog'laydi.

Nega clone qilingan loyihada git push -u kerak emas?

Chunki clone bog'lanishni (upstream) allaqachon o'rnatib bergan. Birinchi kundan qisqa git push ishlaydi.

git status «up to date» dedi. Bu har doim rostmi?

Yo'q! U xatcho'pga (origin/main) qarab gapiradi, GitHub'ga emas. Xatcho'p esa faqat fetch/pull qilganda yangilanadi. Ishonch uchun avval git fetch.

Jamoada har kuni ishni nimadan boshlaysiz?

O'z ishingizni commit qilib, keyin git pull. Shunda eng yangi kod ustida ishlaysiz va to'qnashuvlar kichik qoladi.

↩︎ Takrorlash: push nimani jo'natmaydi?

Commit qilinmagan o'zgarishlarni. push faqat commit qilingan narsani ko'radi. (Dars 04)

↩︎ Takrorlash: staging'ga xato qo'ygan faylni qanday qaytarasiz?

git restore --staged fayl — xavfsiz, matn joyida qoladi. (Dars 03)

Cho'ntak xulosasi
  • git clone <url> — loyiha sizda yo'q edi. Bir marta. Papka + butun tarix + origin + bog'lanish, hammasi birdan.
  • git fetch — xatcho'pni yangilaydi, fayllarga tegmaydi (xavfsiz).
  • git merge — kelgan commitlarni ishingizga qo'shadi.
  • git pull = fetch + merge. Kundalik buyruq.
  • git status ning «up to date»i — xatcho'pga qarab aytilgan gap.
  • Kundalik odat: commit → pull → keyin ishla.
