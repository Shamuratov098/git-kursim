DARS 06 · MODUL C · BRANCH

Branch: alohida yo'lda ishlash

Bu darsdan keyin siz asosiy kodga umuman tegmasdan yangi ish boshlaysiz, istalgan vaqt yo'llar orasida almashasiz — va nima bo'lganda ham main ishlab turaveradi.

📱 O'qish ≈ 8 daqiqa 💻 Amaliyot ≈ 12 daqiqa Kerak: Dars 05

Nega bu muhim

Jamoada hamma bitta main ustida ishlasa — har kim bir-birining yarim tayyor kodini oladi va hech narsa ishlamaydi. Shuning uchun qoida: main doim ishlaydigan holatda turadi, har bir yangi ish esa o'z branchida bajariladi. Bu — pull requestning ham shartli poydevori: PR aslida «mening branch'imni ko'rib chiqing» degani.

Branch nima — va nima EMAS

Ko'pchilik boshida branch'ni «kodning nusxasi» yoki «alohida papka» deb tasavvur qiladi. Bu noto'g'ri, va aynan shu tasavvur keyinchalik chalkashlik keltiradi.

To'g'ri tasavvur

Branch — bu bitta commitga ishora qiluvchi, ko'chib yuruvchi yorliq (pointer).1 Xolos. Hech qanday nusxa ko'chirilmaydi.

Shuning uchun Git'da branch yaratish bir zumda bo'ladi — u atigi bitta kichik fayl yozadi. 10 000 fayllik loyihada ham shunday. Boshqa eski tizimlarda branch yaratish butun papkani ko'chirishni anglatardi va daqiqalab vaqt olardi.

Buni rasmda ko'ramiz

Faraz qilaylik, sizda uchta commit bor va siz maindasiz:

c1
c2
c3 mainHEAD

1-holat: main c3 ga ishora qilyapti, siz shu yerdasiz.

Endi git switch -c login deysiz. Nima o'zgaradi? Deyarli hech narsa — shunchaki yangi yorliq paydo bo'ladi, o'sha commitning ustida:

c1
c2
c3 mainloginHEAD

2-holat: ikkala yorliq ham c3 da. Fayllaringiz o'zgarmadi — hali hech qanday farq yo'q.

Endi login branch'ida ishlab, bitta commit qilasiz. Mana endi yo'llar ajraladi — lekin faqat sizning yorlig'ingiz siljiydi:

c1
c2
c3 main
c4 loginHEAD

3-holat: login oldinga ketdi, main esa joyida qoldi — ya'ni buzilmadi.

HEAD — «men hozir qayerdaman»

Yana bitta yorliq bor: HEAD. U siz turgan branchni ko'rsatadi. git switch aslida shu HEADni bir branch'dan boshqasiga ko'chiradi.1

Uchta buyruq — hammasi shu

BuyruqNima qiladi
git branch Branch'lar ro'yxati. Yulduzcha * — hozir qaysi birida turganingiz. ✓ Xavfsiz, faqat ko'rsatadi.
git switch -c login Yaratadi va darhol o'tadi. -c = create. Eng ko'p ishlatiladigan shakl.
git switch main Mavjud branch'ga o'tadi. -c yo'q — chunki yaratmaymiz.
git switch - Oldingi branch'ga qaytadi. Ikki branch orasida tez almashish uchun qulay.
git branch -d login Branch yorlig'ini o'chiradi (ishi tugagach). Buni 7-darsda, merge'dan keyin ishlatamiz.
Eski maqolalarda checkout ko'rasiz

git checkout login — xuddi shu ish, eski usul. Muammosi: checkout juda ko'p turli ishni bajarardi va boshlovchini chalkashtirardi. Git 2.23 dan beri u ikkiga bo'lingan: switch (branch almashish) va restore (faylni qaytarish — 3-darsda ko'rgan edik). Biz yangi, tushunarli usulni ishlatamiz.2

Diqqat: switch qilganda fayllaringiz o'zgaradi

Bu — darsning eng kutilmagan qismi, shuning uchun oldindan aytib qo'yaman.

«Fayllarim yo'qoldi!» — yo'q, yo'qolmadi

git switch main deganingizda, papkangiz o'sha branch'dagi holatga aylanadi. login branch'ida yaratgan fayl ko'rinmay qoladi — chunki main u haqda hech narsa bilmaydi.

Bu xato emas, xususiyat. git switch login desangiz, fayl o'sha zahoti qaytadi. Fayllar Git ichida bexatar turibdi.

Shundan kelib chiqadigan oddiy qoida:

Branch almashishdan oldin

Ishingizni commit qiling. Commit qilinmagan o'zgarish bo'lsa, Git ba'zan almashishga ruxsat bermaydi (ish yo'qolmasligi uchun). Commit qilingan narsa esa har doim xavfsiz — 3-darsdagi oltin qoida.

Branch nomini qanday tanlash kerak

  • Probel bo'lmasin — chiziqcha ishlating: login-sahifasi.
  • Nima qilayotganingizni ayting: login-sahifasi, email-xatosini-tuzatish. test, yangi, branch2 — hamkasbingizga hech narsa aytmaydi.
  • Ko'p jamoalarda old qo'shimcha ishlatiladi: feature/login, fix/email-xatosi. Ish joyingizdagi odatga qarab moslashasiz.

Amaliyot: branch yasab, ichida ishlab, qaytib keling

Mashqni nusxa papkada qilamiz — 5-darsda yasagan Git-nusxada. Shunda asl kurs papkangiz toza qoladi.

Nusxa papkangiz yo'qmi?

Agar ~/Projects/Learn/Git-nusxa yo'q bo'lsa, avval 5-darsning 1–2-qadamini bajaring (bitta git clone buyrug'i). Yoki menga ayting — birga qilamiz.

  1. Nusxa papkaga o'ting va hozirgi holatni ko'ring

    Yulduzcha * — siz turgan branch.

    cd ~/Projects/Learn/Git-nusxa && git branch * main

    Kutilgan natija: bitta branch — main, yulduzcha bilan. Hozircha yolg'iz yo'l.

  2. Yangi branch yarating va unga o'ting

    -c = create. Ikki ish bitta buyruqda.

    git switch -c mashq-branch Switched to a new branch 'mashq-branch'

    Kutilgan natija: «Switched to a new branch». Bir zumda — hech narsa ko'chirilmadi. 1-g'alaba. 🎉

  3. Ikkala yorliq ham bir joyda ekanini ko'ring

    Rasmdagi 2-holat — ajralish hali boshlanmadi.

    git branch && git log --oneline -1 main * mashq-branch f1fb65f (HEAD -> mashq-branch, origin/main, main) DARS 05...

    Kutilgan natija: yulduzcha endi mashq-branchda, va oxirgi commitda uchala yorliq ham ko'rinadi.

  4. Branch ichida ish qiling

    Bu fayl faqat shu branch'da bo'ladi.

    echo "Bu fayl faqat mashq-branch da bor." > branch-mashq.txt && git add branch-mashq.txt && git commit -m "Branch mashq fayli qo'shildi"

    Kutilgan natija: 1 file changed, 1 insertion(+).

  5. Yo'llar ajralganini ko'ring

    Rasmdagi 3-holat: sizning yorlig'ingiz oldinga ketdi, main joyida qoldi.

    git log --oneline -2 a1b2c3d (HEAD -> mashq-branch) Branch mashq fayli qo'shildi f1fb65f (origin/main, main) DARS 05 qo'shildi: clone va pull

    Kutilgan natija: mashq-branch yuqorida, main bir pog'ona pastda. Ajralish sodir bo'ldi. 2-g'alaba. 🎉

  6. 🪄 Endi eng qiziq qismi: mainga qayting

    Diqqat bilan kuzating — papkangiz o'zgaradi.

    git switch main && ls Switched to branch 'main' assets index.html lessons reference ...

    Kutilgan natija: branch-mashq.txt ro'yxatda YO'Q! U yo'qolmadi — shunchaki main u haqda bilmaydi. Vahima qilmang. 😄

  7. Faylni qaytarib oling

    - = «oldingi branch'ga qayt» (qulay qisqartma).

    git switch - && ls Switched to branch 'mashq-branch' assets branch-mashq.txt index.html lessons ...

    Kutilgan natija: branch-mashq.txt qaytdi. Fayl hech qayerga ketmagan edi. 3-g'alaba. 🎉

  8. Ikki branch farqini bitta buyruqda ko'ring

    «Mening branch'imda main'da yo'q nima bor?»

    git log --oneline main..mashq-branch a1b2c3d Branch mashq fayli qo'shildi

    Kutilgan natija: faqat sizning yangi commitingiz. Bu — keyingi darsda mainga qo'shiladigan ish.

Mashqni shu holda qoldiring

mashq-branchni o'chirmang va mainga qo'shmang — 7-darsda (merge) aynan shu branch bilan ishlaymiz. Tayyor mashq holati qolgani ma'qul.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda Git-nusxa papkada mashq-branch yaratasiz, unda fayl yaratib commit qilasiz, keyin mainga o'tib faylning yo'qolganini — va qaytganingizda qaytganini ko'rasiz. Aynan shu qadam «branch nima» degan savolni bir umrga yopadi. 8 qadam.

Tekshirib ko'ramiz (quiz)

SAVOL 1 Git'da branch aslida nima?

To'g'ri — shuning uchun branch yaratish bir zumda bo'ladi. Hech narsa ko'chirilmaydi, atigi kichik yorliq yoziladi.

SAVOL 2 Branch'da commit qilsangiz, mainga nima bo'ladi?

Aynan — faqat siz turgan branch siljiydi. main tegilmaydi, shuning uchun u ishlaydigan holatda qoladi.

SAVOL 3 Branch almashdingiz va faylingiz ko'rinmay qoldi. Nima bo'ldi?

To'g'ri, va bu darsdagi eng muhim tinchlantiruvchi gap. Papka siz turgan branch holatiga aylanadi. git switch - desangiz hammasi qaytadi.

SAVOL 4 Branch almashishdan oldin nima qilish kerak?

To'g'ri. Commit qilingan narsa xavfsiz (3-dars, oltin qoida). Saqlanmagan o'zgarish bo'lsa, Git ba'zan almashishga ruxsat ham bermaydi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — oldingi darslarni takrorlash.

Branch nima — bir jumlada?

Bitta commitga ishora qiluvchi ko'chib yuruvchi yorliq. Nusxa emas — shuning uchun yaratish bir zumda bo'ladi.

HEAD nimani ko'rsatadi?

Siz hozir turgan branchni. git switch aslida HEADni bir branch'dan boshqasiga ko'chiradi.

Yaratish + o'tish uchun qaysi buyruq? Faqat o'tish uchun-chi?

Yaratish + o'tish: git switch -c nom (-c = create). Mavjudiga o'tish: git switch nom. Oldingisiga qaytish: git switch -.

Branch'da commit qildingiz. main qayerda qoladi?

Joyida — eski commitda. Faqat siz turgan branch siljiydi. Shuning uchun main hech qachon buzilmaydi.

Switch qildingiz, fayl ko'rinmay qoldi. Xatomi?

Yo'q — papka o'sha branch holatiga aylandi. Fayl Git ichida bexatar. Qaytib o'tsangiz darrov ko'rinadi.

↩︎ Takrorlash: pull = ... + ... ?

git fetch + git merge. (Dars 05)

↩︎ Takrorlash: Git'ning oltin qoidasi nima edi?

Commit qilingan narsani yo'qotish juda qiyin, commit qilinmaganini esa oson. (Dars 03)

Cho'ntak xulosasi
  • Branch = ko'chib yuruvchi yorliq (pointer), nusxa emas. Yaratish bir zumda.
  • HEAD = siz turgan branch.
  • git branch — ro'yxat (* = hozirgi joy).
  • git switch -c nom — yarat va o't · git switch nom — o't · git switch - — oldingisiga qayt.
  • Branch'da commit qilsangiz — faqat o'sha branch siljiydi, main joyida qoladi.
  • Switch qilganda fayllar o'zgaradi — bu normal. Avval commit qiling.
  • Nom: probelsiz va mazmunli — login-sahifasi, fix/email-xatosi.
