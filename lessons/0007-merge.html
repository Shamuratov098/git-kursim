DARS 07 · MODUL C · BRANCH

Merge: ishni asosiyga qo'shish

Bu darsdan keyin siz branch'da tugatgan ishingizni mainga qo'sha olasiz — va Git buni ikki xil usulda bajarishini, qay birini nega tanlaganini tushunasiz.

📱 O'qish ≈ 8 daqiqa 💻 Amaliyot ≈ 14 daqiqa Kerak: Dars 06

Nega bu muhim

Branch'da ishlash — ishning yarmi. Uni asosiyga qo'shmasangiz, hech kim ko'rmaydi va u hech qayerga ketmaydi. Merge — ishni yakunlash amali. Jamoada esa pull request aslida shu merge'ni so'rash demakdir — shuning uchun merge'ni tushunmasdan PR'ni tushunib bo'lmaydi.

Eng ko'p qilinadigan xato: yo'nalishni chalkashtirish

Buni darsning boshida aytaman, chunki deyarli har bir yangi boshlovchi shu yerda adashadi.

Qoida: avval qabul qiluvchiga o'ting

git merge har doim siz turgan branch'ga qo'shadi. Ya'ni «kimga qo'shmoqchi bo'lsangiz — o'shanga o'ting, keyin beruvchining nomini yozing».

git switch main # 1. qabul qiluvchiga o'tdim
git merge login # 2. beruvchini qo'shdim

Agar teskarisini qilsangiz (loginda turib git merge main), Git xato bermaydi — u shunchaki main'ni login'ga qo'shadi. Bu ham foydali amal, lekin siz xohlagan narsa emas.

Git merge'ni ikki xil bajaradi

Qaysi biri bo'lishini Git o'zi hal qiladi — vaziyatga qarab. Ikkalasini ham bilib qo'ysangiz, terminal chiqishini o'qiy olasiz.

1-holat: Fast-forward — «shunchaki oldinga surish»

Siz branch ochganingizdan beri main qimirlamagan bo'lsa, hech narsani birlashtirishning hojati yo'q. Git shunchaki main yorlig'ini oldinga suradi:1

c1
c2
c3 main
c4 login

Merge'dan oldin: main c3 da qolgan, login c4 da.

c1
c2
c3
c4 mainloginHEAD

Merge'dan keyin: main c4 ga «yetib oldi». Yangi commit yaratilmadi.

Terminalda buni shunday ko'rasiz:

git merge login Updating f1fb65f..a1b2c3d Fast-forward login.txt | 1 +
Tanish so'z

Fast-forwardni siz allaqachon ko'rgansiz — 5-darsda git pull qilganingizda xuddi shu yozuv chiqqan edi. Sabab bir xil: pull ichida ham merge bor.

2-holat: Merge commit — «ikki yo'lni bog'lash»

Endi boshqacha vaziyat: siz loginda ishlayotganingizda, kimdir (yoki o'zingiz) mainga ham commit qilib qo'ydi. Ikkala yo'l ham siljidi — yo'llar ajraldi:

Ikkala branch ham c3 dan keyin o'z yo'liga ketdi.

Endi Git yorliqni «surib qo'ya olmaydi» — ikkala tomonda ham yangi ish bor. Shuning uchun u yangi commit yaratadi: uning ikkita ota-onasi (parent) bo'ladi.1 Bu — merge commit:

Bo'sh doira — merge commit (c6). U ikkala tarixni birlashtiradi va main endi shu yerda.

Terminalda esa boshqacha yozuv chiqadi:

git merge login Merge made by the 'ort' strategy. login.txt | 1 +
ort nima degani?

Bu Git ishlatadigan birlashtirish algoritmining nomi (Git 2.34 dan beri standart). Uni yodlashning hojati yo'q — shunchaki «Merge made by...» yozuvini ko'rsangiz, merge commit yaratildi deb tushunavering.

Merge commit yomonmi?

Yo'q. Ba'zilar tarixni «toza» qilish uchun undan qochadi (rebase bilan — bu kurs doirasidan tashqarida). Lekin merge commit rostgo'y: u aslida nima bo'lganini ko'rsatadi. Ko'p jamoalar aynan shuning uchun uni ma'qul ko'radi.

Merge tugagach: branch'ni o'chirish

Ish mainga qo'shildi — endi login yorlig'i keraksiz:

git branch -d login Deleted branch login (was a1b2c3d).
Commitlaringiz yo'qolmaydi

Siz faqat yorliqni o'chirdingiz — commitlar main ichida qolaveradi (6-dars: branch = yorliq, nusxa emas). Bundan tashqari -d xavfsiz: agar branch hali merge qilinmagan bo'lsa, Git o'chirishdan bosh tortadi va sizni ogohlantiradi.

Tugagan branch'larni o'chirib borish yaxshi odat — aks holda bir yildan keyin git branch ellikta eski nom ko'rsatadi va kerakligini topa olmaysiz.

Amaliyot: ikkala merge turini ham o'z ko'zingiz bilan ko'ring

Mashq yana nusxa papkada. 6-darsda yasagan mashq-branch hali mainga qo'shilmagan holda turibdi — aynan shundan boshlaymiz.

Nusxa papkadan push QILMANG

Git-nusxa — mashq maydoni. U yerdan git push qilsangiz, mashq commitlari haqiqiy kurs repongizga tushib qoladi va chalkashlik chiqadi. Bu darsda push umuman yo'q — hammasi mahalliy.

A qism — Fast-forward

  1. Nusxa papkaga o'ting va holatni ko'ring

    Ikkita branch bo'lishi kerak, yulduzcha mashq-branchda.

    cd ~/Projects/Learn/Git-nusxa && git branch main * mashq-branch

    Kutilgan natija: ikki branch. Agar mashq-branch yo'q bo'lsa — 6-darsning amaliyotini bajaring.

  2. Qabul qiluvchiga o'ting

    Darsning asosiy qoidasi: avval mainga o'tamiz.

    git switch main && ls assets index.html lessons reference ...

    Kutilgan natija: branch-mashq.txt yo'q — u hali faqat branch'da (6-darsdagi «sehr»).

  3. Merge qiling

    main qimirlamagan edi → Git yorliqni suradi.

    git merge mashq-branch Updating f1fb65f..a1b2c3d Fast-forward branch-mashq.txt | 1 +

    Kutilgan natija: Fast-forward so'zi. Tahrirlagich ochilmaydi. 1-g'alaba. 🎉

  4. Fayl endi mainda ekanini tekshiring

    ls && git log --oneline -2 assets branch-mashq.txt index.html ... a1b2c3d (HEAD -> main, mashq-branch) Branch mashq fayli qo'shildi

    Kutilgan natija: fayl paydo bo'ldi va ikkala yorliq bir commitda turibdi.

  5. Keraksiz branch'ni o'chiring

    Ish qo'shildi — yorliq endi kerak emas.

    git branch -d mashq-branch && git branch Deleted branch mashq-branch (was a1b2c3d). * main

    Kutilgan natija: «Deleted branch» va endi faqat main. Fayl esa joyida — commitlar yo'qolmadi.

B qism — Merge commit

Endi ataylab ajralish yasaymiz: ikkala tomonda ham commit qilamiz.

  1. Yangi branch ochib, unda commit qiling

    Bu — «sizning ishingiz».

    git switch -c ikkinchi-mashq && echo "Branch tomonidan." > ikkinchi.txt && git add ikkinchi.txt && git commit -m "Ikkinchi mashq fayli"

    Kutilgan natija: «Switched to a new branch» va 1 file changed.

  2. Endi mainga o'tib, U YERDA ham commit qiling

    Mana shu qadam ajralishni yaratadi — «hamkasbingiz» main'ga ish qo'shdi.

    git switch main && echo "Main tomonidan." > asosiy.txt && git add asosiy.txt && git commit -m "Main da to'g'ridan-to'g'ri o'zgarish"

    Kutilgan natija: commit yaratildi. Endi ikkala yo'l ham c3 dan keyin ajralgan — rasmdagi holat.

  3. Merge qiling — bu safar boshqacha bo'ladi

    --no-edit = izohni Git o'zi yozsin, tahrirlagich ochilmasin. (Bu bo'lmasa terminal matn tahrirlagichga o'tib ketadi.)

    git merge ikkinchi-mashq --no-edit Merge made by the 'ort' strategy. ikkinchi.txt | 1 +

    Kutilgan natija: «Fast-forward» emas, balki «Merge made by...». Yangi merge commit yaratildi. 2-g'alaba. 🎉

  4. 🎨 Tarixni grafik ko'rinishda ko'ring

    Mana darsning eng chiroyli qismi: rasmdagi ajralishni o'z terminalingizda ko'rasiz.

    git log --oneline --graph -4 * e5f6a7b (HEAD -> main) Merge branch 'ikkinchi-mashq' |\ | * c3d4e5f (ikkinchi-mashq) Ikkinchi mashq fayli * | b2c3d4e Main da to'g'ridan-to'g'ri o'zgarish |/

    Kutilgan natija: |\ va |/ belgilari — ajralish va birlashish. Ikkala fayl ham papkada: ls bilan tekshiring. 3-g'alaba. 🎉

  5. Tozalab qo'ying

    Ish qo'shildi, yorliq keraksiz.

    git branch -d ikkinchi-mashq && git branch Deleted branch ikkinchi-mashq (was c3d4e5f). * main

    Kutilgan natija: faqat main qoldi, lekin git log --oneline --graph da ajralish tarixi saqlanib qoladi.

Ikkalasining farqini his qildingizmi?

A qismda Git yorliqni surdi (Fast-forward), B qismda esa yangi commit yaratdi (Merge made by...). Farq bitta narsada: main shu orada qimirladimi yoki yo'qmi.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyot ikki qismdan iborat. A: 6-darsdagi mashq-branchni mainga qo'shasiz — Fast-forward chiqadi. B: ataylab ajralish yasaysiz (ikkala tomonda commit) va merge qilasiz — bu safar merge commit yaratiladi. Oxirida git log --graph bilan ajralishni o'z terminalingizda ko'rasiz. 10 qadam.

Tekshirib ko'ramiz (quiz)

SAVOL 1 loginni mainga qo'shmoqchisiz. Qanday qilasiz?

To'g'ri — merge har doim siz turgan branch'ga qo'shadi. Avval qabul qiluvchiga o'ting, keyin beruvchining nomini yozing.

SAVOL 2 Terminalda «Fast-forward» chiqdi. Bu nima degani?

Aynan — main siz branch ochganingizdan beri qimirlamagan, shuning uchun birlashtirishga hojat qolmadi.

SAVOL 3 Merge commit qachon yaratiladi?

To'g'ri. Ikkala tomonda ham yangi ish bo'lsa, Git yorliqni sura olmaydi — ikkita ota-onali yangi commit yaratadi.

SAVOL 4 git branch -d login qilsangiz, commitlaringizga nima bo'ladi?

To'g'ri — siz faqat yorliqni o'chirdingiz (6-dars: branch = yorliq). Merge qilinmagan bo'lsa, -d umuman o'chirmaydi va sizni ogohlantiradi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — oldingi darslarni takrorlash.

Merge qilishdan oldin qaysi branch'da turish kerak?

Qabul qiluvchida — ya'ni ishni qabul qiladigan branch'da. git switch main, keyin git merge login.

Fast-forward qachon bo'ladi?

Siz branch ochganingizdan beri main qimirlamagan bo'lsa. Git shunchaki yorliqni oldinga suradi — yangi commit yaratilmaydi.

Merge commit'ning nimasi boshqacha?

Uning ikkita ota-onasi (parent) bor — u ikkala tarixni bog'laydi. Terminalda «Merge made by the 'ort' strategy» deb chiqadi.

Branch'ni o'chirsam, ishim yo'qoladimi?

Yo'q — siz faqat yorliqni o'chirasiz, commitlar main ichida qoladi. Bundan tashqari -d merge qilinmagan branch'ni o'chirishdan bosh tortadi.

Tarixni grafik ko'rinishda qanday ko'rasiz?

git log --oneline --graph. |\ — ajralish, |/ — birlashish.

↩︎ Takrorlash: branch nima — bir jumlada?

Bitta commitga ishora qiluvchi ko'chib yuruvchi yorliq, nusxa emas. (Dars 06)

↩︎ Takrorlash: push nimani jo'natmaydi?

Commit qilinmagan o'zgarishlarni. (Dars 04)

Cho'ntak xulosasi
  • Yo'nalish: avval git switch main (qabul qiluvchi), keyin git merge login (beruvchi).
  • Fast-forward — main qimirlamagan → yorliq oldinga suriladi, yangi commit yo'q.
  • Merge commit — ikkala tomon ham siljigan → ikkita ota-onali yangi commit yaratiladi («Merge made by...»).
  • Tahrirlagich ochilmasin desangiz: git merge branch --no-edit.
  • git log --oneline --graph — ajralishni ko'rish.
  • git branch -d login — tugagan yorliqni o'chirish (commitlar qoladi; merge qilinmagan bo'lsa Git ruxsat bermaydi).
Keyingi darsda

Bu darsda hammasi silliq ketdi, chunki ikki tomon turli fayllarni o'zgartirdi. Agar ikkovi ham bitta faylning bitta joyini o'zgartirsa — Git qaysi birini olishni bilmaydi va sizdan so'raydi. Bu merge conflict. Qo'rqinchli emas, lekin uni ko'rish kerak — 8-darsda ataylab yasab, hal qilamiz.
