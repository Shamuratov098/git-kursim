DARS 08 · MODUL C · BRANCH

Merge conflict: ziddiyatni hal qilish

Bu darsdan keyin siz konfliktni ataylab yasaysiz va o'z qo'lingiz bilan hal qilasiz. Shundan so'ng u sizni hech qachon qo'rqitmaydi — chunki nima bo'layotganini aniq bilasiz.

📱 O'qish ≈ 8 daqiqa 💻 Amaliyot ≈ 15 daqiqa Kerak: Dars 07

Nega bu muhim

Missiyangizda shunday yozilgan: «merge conflict chiqsa, vahima qilmasdan hal qilish». Bu — yangi dasturchilarni eng ko'p qo'rqitadigan narsa, va aynan shuning uchun ko'pchilik branch ishlatishdan qochadi. Bugun uni ataylab chaqiramiz, ochib ko'ramiz — va u oddiy ish ekanini ko'rasiz.

Avvalo: konflikt — bu xato emas

Konflikt chiqishi Git buzilgani yoki siz noto'g'ri ish qilganingizni anglatmaydi. Aksincha — bu Git'ning ehtiyotkorligi.

Nima bo'lyapti aslida

Ikki kishi bir joyni har xil o'zgartirgan. Git hech qachon o'zi tanlab qo'ymaydi — chunki qay biri to'g'ri ekanini faqat odam biladi. Shuning uchun u to'xtaydi va sizdan so'raydi.1

Tasavvur qiling, Git o'zi tanlab qo'yganida — kimningdir ishi jimgina yo'q bo'lardi. Konflikt aslida sizni himoya qilyapti.

Birinchi bilishingiz kerak bo'lgan buyruq

Nazariyaga o'tishdan oldin, sizga xotirjamlik beradigan narsani aytay. Konflikt o'rtasida istalgan vaqt orqaga qayta olasiz:

git merge --abort

Bu buyruq merge boshlangunga qadar bo'lgan holatga qaytaradi. Hech narsa yo'qolmaydi, hech narsa buzilmaydi. Chalkashib ketsangiz — shuni yozing va toza boshdan boshlang. Amaliyotda buni ataylab sinab ko'ramiz.

Konflikt qachon chiqadi — va qachon CHIQMAYDI

Ko'pchilik o'ylaganidan ancha kam holatda chiqadi:

VaziyatNatija
Har xil fayllar ✓ Konflikt yo'q. Git ikkalasini ham oladi. 7-darsda aynan shunday bo'ldi — shuning uchun hammasi silliq ketgan edi.
Bitta fayl, turli joylari ✓ Odatda konflikt yo'q. Git o'zgarishlarni qo'shib qo'yadi. Masalan biri faylning boshini, ikkinchisi oxirini o'zgartirgan bo'lsa.
Bitta fayl, bitta joyi ⚠️ Konflikt. Git qaysi variantni olishni bilmaydi va sizdan so'raydi.

Ya'ni konflikt uchun ikki tomon aynan bir xil qatorlarni boshqacha o'zgartirgan bo'lishi kerak. Kundalik ishda bu unchalik tez-tez bo'lmaydi — ayniqsa muntazam pull qilib tursangiz.

Konflikt chiqqanda Git nima qiladi

Uchta narsa sodir bo'ladi:

  1. Merge to'xtaydi — yarim holatda qoladi (commit qilinmagan).
  2. Fayl ichiga belgilar qo'yiladi — ikkala variant ham yonma-yon yoziladi.
  3. git status sizga aniq aytadi nima qilish kerakligini.

Terminalda shunday ko'rinadi:

git merge login Auto-merging salom.txt CONFLICT (content): Merge conflict in salom.txt Automatic merge failed; fix conflicts and then commit the result.

E'tibor bering: Git qaysi faylda ekanini aniq aytdi. Bir nechta fayl bo'lsa, hammasini sanab beradi.

Belgilarni o'qishni o'rganamiz

Faylni ochsangiz, shunday manzarani ko'rasiz. Bu — darsning eng muhim rasmi:

salom.txt — konflikt holatida
<<<<<<< HEAD
Salom, dunyo!sizdagi
=======
Assalomu alaykum, dunyo!kelayotgan
>>>>>>> login

Har bir belgining ma'nosi bor:

  • <<<<<<< HEAD — «bu yerdan boshlab — siz turgan branchdagi variant». HEAD tanish (6-dars): «men hozir qayerdaman».
  • ======= — ikki variantni ajratuvchi chiziq. Bu shunchaki chegara, matnning bir qismi emas.
  • >>>>>>> login — «bu yergacha — kelayotgan branchdagi variant». Oxirida branch nomi yozilgan.
Eng ko'p qilinadigan xato

Belgilarni fayl ichida qoldirib ketish. <<<<<<< va ======= — bu Git yozgan vaqtinchalik belgilar, sizning matningizning qismi emas. Ularni albatta o'chirish kerak. Aks holda kodingizga axlat qatorlar tushib qoladi (va odatda dastur ishlamay qoladi).

Muhim: sizdan tanlash emas, YAKUNIY MATN so'ralyapti

Ko'pchilik «ikkitasidan birini tanlashim kerak» deb o'ylaydi. Bu noto'g'ri. Git sizdan faqat bitta narsani kutadi: fayl oxir-oqibat qanday bo'lishi kerak?

Ya'ni sizda to'rt yo'l bor:

  • O'zingiznikini qoldirish;
  • Kelayotganini qoldirish;
  • Ikkalasini ham qoldirish (ikki qator qilib);
  • Butunlay yangi matn yozish — ikkalasini birlashtirgan uchinchi variant.

Masalan, hal qilingandan keyin fayl shunday bo'lishi mumkin:

salom.txt — hal qilingan
Assalomu alaykum, dunyo!tanlandi

Belgilar yo'q, ortiqcha qator yo'q — faqat siz xohlagan yakuniy matn.

Hal qilishning uch qadami

  1. Faylni tahrirlang — belgilarni o'chiring, kerakli matnni qoldiring.
  2. git add <fayl> — «men buni hal qildim» degani.
  3. git commit — merge yakunlanadi.
git addning yangi ma'nosi

Odatda git add — «bu o'zgarishni keyingi commitga qo'sh» (2-dars). Konflikt paytida esa u qo'shimcha ma'no oladi: «bu fayldagi ziddiyat hal qilindi». Git aynan shu signalni kutadi.

VS Code ishlatsangiz

VS Code konflikt bo'lgan faylni ochsangiz, belgilar ustida tugmalar chiqadi: Accept Current Change (sizdagi), Accept Incoming Change (kelayotgan), Accept Both Changes (ikkalasi). Bir bosishda belgilar ham o'chadi. Qulay — lekin avval belgilarni qo'lda hal qilib ko'ring, mexanizmni tushunish uchun.

Amaliyot: konfliktni ataylab yasab, hal qilamiz

Yana nusxa papkada ishlaymiz — bu xavfsiz mashq maydoni.

Nusxa papkadan push QILMANG

Bu darsda ham push yo'q — hammasi mahalliy. Git-nusxadagi commitlar haqiqiy kurs repongizga tushmasligi kerak.

A qism — konflikt yasaymiz

  1. Nusxa papkaga o'ting va umumiy fayl yarating

    Bu — ikkala branch ham o'zgartiradigan «umumiy nuqta».

    cd ~/Projects/Learn/Git-nusxa && git switch main && echo "Salom!" > salom.txt && git add salom.txt && git commit -m "Salom fayli qo'shildi"

    Kutilgan natija: 1 file changed. Endi mainda salom.txt bor.

  2. Branch ochib, o'sha qatorni o'zgartiring

    > (bitta) — faylni butunlay qayta yozadi. >> (ikkita) esa oxiriga qo'shardi.

    git switch -c salom-branch && echo "Assalomu alaykum, dunyo!" > salom.txt && git commit -am "Salomlashish uzaytirildi"

    Kutilgan natija: yangi branch va commit. Bu — «hamkasbingizning» varianti.

  3. mainga qayting va AYNAN o'sha qatorni boshqacha o'zgartiring

    Mana shu qadam konfliktni muqarrar qiladi: bir fayl, bir qator, ikki xil matn.

    git switch main && echo "Salom, dunyo!" > salom.txt && git commit -am "Salomlashishga dunyo qo'shildi"

    Kutilgan natija: commit yaratildi. Endi ikki tomonda ikki xil variant bor.

  4. 💥 Merge qiling — konflikt chiqadi

    Qo'rqmang, hammasi rejaga muvofiq.

    git merge salom-branch Auto-merging salom.txt CONFLICT (content): Merge conflict in salom.txt Automatic merge failed; fix conflicts and then commit the result.

    Kutilgan natija: CONFLICT so'zi. Tabriklayman — siz birinchi konfliktingizni yasadingiz! 1-g'alaba. 🎉

  5. Git nima deyayotganini o'qing

    git status — konflikt paytidagi eng yaxshi do'stingiz.

    git status You have unmerged paths. Unmerged paths: both modified: salom.txt

    Kutilgan natija: «both modified» — ikkala tomon ham o'zgartirgan. Git yana nima qilish kerakligini ham yozib beradi.

  6. Fayl ichini ko'ring — belgilar shu yerda

    Nazariy qismdagi rasm bilan solishtiring.

    cat salom.txt <<<<<<< HEAD Salom, dunyo! ======= Assalomu alaykum, dunyo! >>>>>>> salom-branch

    Kutilgan natija: aynan darsdagi belgilar. Yuqorisi — sizdagi (main), pastkisi — kelayotgan (salom-branch).

B qism — qochish yo'lini sinab ko'ramiz

Hal qilishdan oldin, orqaga qaytish ishlashiga ishonch hosil qilamiz. Kelajakda chalkashib qolsangiz, shu buyruq sizni qutqaradi.

  1. Merge'ni bekor qiling

    Konflikt o'rtasida turibsiz — chiqib ketamiz.

    git merge --abort && git status On branch main nothing to commit, working tree clean

    Kutilgan natija: «working tree clean» — konflikt yo'q, hammasi tinch. cat salom.txt deng: belgilar yo'q, faqat sizning variantingiz. 2-g'alaba. 🎉

  2. Endi qaytadan merge qiling

    Konflikt yana chiqadi — bu ham normal. Bu safar hal qilamiz.

    git merge salom-branch CONFLICT (content): Merge conflict in salom.txt

    Kutilgan natija: yana CONFLICT. Endi qo'rqinchli emas, to'g'rimi?

C qism — hal qilamiz

  1. Yakuniy matnni yozing

    Bu yerda men uchinchi variantni tanladim — ikkalasini birlashtirgan. Siz xohlagan matnni yozishingiz mumkin: bu sizning qaroringiz.

    echo "Assalomu alaykum, aziz dunyo!" > salom.txt && cat salom.txt Assalomu alaykum, aziz dunyo!

    Kutilgan natija: faqat bitta qator — belgilar yo'q. Fayl yakuniy holatida.

  2. Git'ga «hal qildim» deng

    Konflikt paytida git add aynan shuni bildiradi.

    git add salom.txt && git status All conflicts fixed but you are still merging. (use "git commit" to conclude merge)

    Kutilgan natija: «All conflicts fixed» — Git rozi. U hatto keyingi qadamni ham aytib turibdi.

  3. Merge'ni yakunlang

    --no-edit — tahrirlagich ochilmasin (7-darsdagidek).

    git commit --no-edit [main 8d9e0f1] Merge branch 'salom-branch'

    Kutilgan natija: merge commit yaratildi. Konfliktni to'liq hal qildingiz. 3-g'alaba! 🎉🎉

  4. Natijani ko'ring

    Tarixda ajralish va birlashish ko'rinadi.

    git log --oneline --graph -4 && cat salom.txt * 8d9e0f1 (HEAD -> main) Merge branch 'salom-branch' |\ | * 5a6b7c8 (salom-branch) Salomlashish uzaytirildi * | 2d3e4f5 Salomlashishga dunyo qo'shildi |/ Assalomu alaykum, aziz dunyo!

    Kutilgan natija: grafikda ikki yo'l birlashgan va faylda siz yozgan matn turibdi.

  5. Tozalab qo'ying

    git branch -d salom-branch Deleted branch salom-branch (was 5a6b7c8).

    Kutilgan natija: «Deleted branch». Mashq tugadi — va siz endi konfliktdan qo'rqmaysiz. 😌

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyot uch qismli. A: bitta faylning bitta qatorini ikki tomondan o'zgartirib, konfliktni ataylab yasaysiz va belgilarni o'z ko'zingiz bilan ko'rasiz. B: git merge --abort bilan orqaga qaytishni sinab ko'rasiz — qochish yo'li ishlashiga ishonch hosil qilasiz. C: yakuniy matnni yozib, add → commit bilan hal qilasiz. 13 qadam.

Tekshirib ko'ramiz (quiz)

SAVOL 1 Merge conflict qachon chiqadi?

To'g'ri. Turli fayllar yoki bitta faylning turli joylari bo'lsa — Git o'zi uddalaydi. Faqat aynan bir xil qatorlar to'qnashsa so'raydi.

SAVOL 2 <<<<<<< HEAD ostidagi matn kimniki?

To'g'ri — HEAD «men hozir qayerdaman» (6-dars). Pastki qism esa >>>>>>> dan oldingi — kelayotgan branch'niki.

SAVOL 3 Konfliktni hal qilganda belgilarni nima qilasiz?

To'g'ri — bular Git yozgan vaqtinchalik belgilar. Qolib ketsa, kodingizga axlat qatorlar tushadi va odatda dastur ishlamay qoladi.

SAVOL 4 Konflikt o'rtasida chalkashib ketdingiz. Nima qilasiz?

To'g'ri — bu sizning xavfsizlik tugmangiz. Hech narsa yo'qolmaydi, merge boshlangunga qadar bo'lgan holat qaytadi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — oldingi darslarni takrorlash.

Nega Git konflikt paytida o'zi tanlab qo'ymaydi?

Chunki qay biri to'g'ri ekanini faqat odam biladi. O'zi tanlaganida, kimningdir ishi jimgina yo'qolardi. Konflikt — himoya.

Uchta belgi nimani anglatadi?

<<<<<<< HEAD — bu yerdan sizdagi variant · ======= — ajratuvchi chiziq · >>>>>>> branch-nomi — bu yergacha kelayotgan variant.

Ikkitasidan birini tanlash shartmi?

Yo'q! Git sizdan yakuniy matnni so'rayapti. O'zingiznikini, kelayotganini, ikkalasini, yoki butunlay yangi matnni yozishingiz mumkin.

Hal qilishning uch qadami?

1) Faylni tahrirla, belgilarni o'chir · 2) git add fayl («hal qildim» signali) · 3) git commit.

Chalkashib ketsangiz — qaysi buyruq?

git merge --abort. Merge boshlangunga qadar bo'lgan holat qaytadi, hech narsa yo'qolmaydi.

↩︎ Takrorlash: merge'dan oldin qaysi branch'da turasiz?

Qabul qiluvchida: git switch main, keyin git merge login. (Dars 07)

↩︎ Takrorlash: konfliktlarni kichik saqlash uchun nima qilasiz?

Muntazam git pull — ish boshlashdan oldin. Eskirgan kod ustida ishlash konfliktning asosiy sababi. (Dars 05)

Cho'ntak xulosasi
  • Konflikt = xato emas. Git o'zi tanlamaydi, chunki faqat odam biladi.
  • Chiqadi: bitta fayl, bitta joy, ikki xil o'zgarish. Boshqa hollarda yo'q.
  • Belgilar: <<<<<<< HEAD sizdagi · ======= chegara · >>>>>>> branch kelayotgan.
  • Belgilarni albatta o'chiring — ular matnning qismi emas.
  • Tanlash emas — yakuniy matn: sizniki / ularniki / ikkalasi / yangisi.
  • Hal qilish: tahrirla → git add fayl → git commit.
  • Qochish yo'li: git merge --abort — istalgan vaqt, xavfsiz.
  • Kompas: git status — konflikt paytida ham nima qilishni aytadi.
🎓 Modul C tugadi

Branch (06) → merge (07) → conflict (08). Endi sizda jamoada ishlash uchun kerak bo'lgan butun texnik poydevor bor: alohida yo'lda ishlash, ishni qaytarib qo'shish va to'qnashuvni hal qilish.
