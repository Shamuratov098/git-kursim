DARS 09 · MODUL D · JAMOA

Pull request: taklif, review, merge

Bu darsdan keyin siz haqiqiy pull request ochasiz, uni ko'rib chiqasiz va merge qilasiz. Bu — ish joyidagi kundalik amal: jamoada kod aynan shu yo'l bilan qo'shiladi.

📱 O'qish ≈ 8 daqiqa 💻 Amaliyot ≈ 15 daqiqa Kerak: Dars 08

Nega bu muhim

Bu — missiyangizning markazi. Ish joyida hech kim to'g'ridan-to'g'ri mainga push qilmaydi: har bir o'zgarish pull request orqali o'tadi. PR ocha bilish va boshqalarnikini ko'rib chiqa bilish — jamoaga qo'shilganingizdan keyingi birinchi kundan kerak bo'ladi.

Pull request nima — va nima emas

Diqqat: bu Git buyrug'i EMAS

git pull request degan buyruq yo'q. Pull request — GitHub'ning (va GitLab, Bitbucket kabi saytlarning) imkoniyati. Git — kompyuteringizdagi dastur; PR — internetdagi muhokama sahifasi. Ikkalasi turli narsa, va bu chalkashlik juda ko'p uchraydi.

Pull request — bu taklif: «mening branch'imdagi o'zgarishlarni mainga qo'shaylik. Mana nima qildim, mana nega. Ko'rib chiqing.»1

PR sahifasi uch narsani bir joyga to'playdi:

  • O'zgarishlar — satrma-satr, qaysi faylda nima o'zgargani;
  • Muhokama — savollar, takliflar, tasdiq;
  • Yozuv — bu o'zgarish nega qilingani abadiy saqlanadi.

Oxirgisi ko'pincha e'tibordan chetda qoladi, lekin eng qimmatlisi shu. Bir yildan keyin «bu kod nega bunday yozilgan?» degan savol tug'ilsa — javob PR muhokamasida turgan bo'ladi.

1 va 2-bosqich — sizga tanish (6-dars va 4-dars). Bugun 3 va 4-bosqichni qo'shamiz.

Nihoyat -u kerak bo'ladi

4-darsda git push -u origin main dagi -u ni o'rgangan edik, lekin sizda u allaqachon sozlangan edi. Bugun yangi branchni birinchi marta jo'natasiz — GitHub uni hali bilmaydi. Mana shu yerda -u rostdan kerak bo'ladi:

git push -u origin mening-branchim

PR sahifasidagi bo'limlar

PR ochilgach, to'rtta yorliq (tab) ko'rasiz. Ish joyida ularning barchasini ishlatasiz:

Bo'limNima uchun
Conversation Umumiy muhokama: tavsif, izohlar, qaror. PR ochilganda shu yerga tushasiz.
Commits Qaysi commitlar kirayotgani. Bu yerda commit izohlaringiz ko'rinadi — yaxshi izoh yozish shuning uchun ham muhim.
Files changed Eng muhim bo'lim. Satrma-satr farq ( git diff ning brauzerdagi ko'rinishi). Review aynan shu yerda qilinadi: har qaysi satrga izoh qoldirish mumkin.
Checks Avtomatik testlar (agar loyihada sozlangan bo'lsa). Kursimizda yo'q — ish joyingizda ehtimol bo'ladi.

Yaxshi pull request qanday bo'ladi

Bu — texnika emas, odob. Hamkasblaringiz sizni aynan shu bo'yicha baholaydi:

  • Kichik bo'lsin. 20 satrlik PR bir necha daqiqada ko'rib chiqiladi; 2000 satrlik PR bir hafta kutadi va yuzaki o'qiladi. Katta ishni bir necha PR'ga bo'ling.
  • Sarlavha — nima qilingani: «Login sahifasiga parolni tiklash qo'shildi».
  • Tavsif — nega va qanday tekshirish: muammo nima edi, qanday yechdingiz, ko'rib chiquvchi buni qanday sinab ko'rsin.
  • Bitta PR = bitta mavzu. Xuddi commit kabi (2-dars) — aralashtirmang.

Review qilish — boshqalarning PR'ini ko'rish

Jamoada siz faqat PR ochmaysiz, boshqalarnikini ham ko'rib chiqasiz. Files changed bo'limida istalgan satr yoniga izoh qoldirasiz, keyin uchta javobdan birini tanlaysiz:2

JavobQachon
Approve Hammasi joyida — qo'shilsin.
Request changes Tuzatish kerak. Nimani va nega — aniq yozing.
Comment Savol yoki fikr bor, lekin to'sqinlik qilmaydi.
Review odobi

Buyruq emas, savol bering. «Buni o'zgartir» o'rniga «bu yerda null kelsa nima bo'ladi?» — ohang butunlay boshqacha, natija bir xil. Va kod haqida gapiring, odam haqida emas: «bu funksiya uzun» ✓, «sen chalkash yozibsan» ✗. Yaxshi joyni ko'rsangiz — maqtang, bu ham review'ning qismi.

Merge qilingandan keyin — eng ko'p unutiladigan qadam

Mahalliy main hali eski!

PR GitHub'da merge qilinadi — ya'ni internetda. Sizning kompyuteringizdagi main bundan bexabar qolaveradi (5-dars: origin/main — bu shunchaki xatcho'p). Shuning uchun merge'dan keyin darhol:

git switch main && git pull

Buni unutsangiz, keyingi ishni eskirgan kod ustida boshlaysiz — va konflikt chiqadi.

Amaliyot: haqiqiy pull request ochamiz

Bu safar mashq haqiqiy kurs repongizda (~/Projects/Learn/Git) bo'ladi — chunki PR GitHub'da ochiladi. Nusxa papka bugun kerak emas.

Yolg'iz ishlayapsiz — bu normal

Ish joyida PR'ingizni hamkasbingiz ko'rib chiqadi. Bugun ikkala rolni ham o'zingiz o'ynaysiz: avval muallif, keyin ko'rib chiquvchi. Tugmalar va tartib — aynan bir xil, shuning uchun mashq to'liq haqiqiy.

A qism — kompyuterda: branch va push

  1. Toza holatdan boshlang

    Kundalik odat (5-dars): yangi ish har doim eng yangi main ustida boshlanadi.

    cd ~/Projects/Learn/Git && git switch main && git pull Already up to date.

    Kutilgan natija: «Already up to date» yoki yangi commitlar tushadi. Ikkalasi ham yaxshi.

  2. Ish uchun branch oching

    Nom mazmunli bo'lsin (6-dars).

    git switch -c mening-birinchi-pr Switched to a new branch 'mening-birinchi-pr'

    Kutilgan natija: «Switched to a new branch».

  3. O'zgarish qiling va commit qiling

    Bu fayl kursingizda qoladi — o'z yo'lingiz haqidagi eslatma. Matnni o'zingiznikiga almashtirsangiz ham bo'ladi.

    echo "# Mening Git yo'lim" > mening-yolim.md && echo "Bugun birinchi pull request'imni ochdim." >> mening-yolim.md && git add mening-yolim.md && git commit -m "Mening yo'lim eslatmasi qo'shildi"

    Kutilgan natija: 1 file changed, 2 insertions(+).

  4. Branch'ni GitHub'ga jo'nating

    Mana shu yerda -u rostdan kerak: GitHub bu branch'ni hali bilmaydi.

    git push -u origin mening-birinchi-pr remote: Create a pull request for 'mening-birinchi-pr' on GitHub by visiting: remote: https://github.com/Shamuratov098/git-kursim/pull/new/mening-birinchi-pr * [new branch] mening-birinchi-pr -> mening-birinchi-pr

    Kutilgan natija: «[new branch]» va GitHub bergan havola. Git sizga PR ochish uchun to'g'ridan-to'g'ri link beryapti! 1-g'alaba. 🎉

B qism — brauzerda: PR ochish, review, merge

  1. Repongizni brauzerda oching

    Yuqoridagi havolani bosishingiz ham mumkin.

    xdg-open https://github.com/Shamuratov098/git-kursim

    Kutilgan natija: sahifa tepasida sariq chiziq va Compare & pull request tugmasi ko'rinadi.

  2. Compare & pull request tugmasini bosing

    Bu tugma yangi push qilingan branch uchun avtomatik chiqadi. Ko'rinmasa: Pull requests → New pull request.

    Kutilgan natija: PR yaratish sahifasi ochiladi. Tepada yo'nalish yozilgan: base: main ← compare: mening-birinchi-pr. Ya'ni «main'ga qo'shamiz» — 7-darsdagi yo'nalish qoidasi, brauzerdagi ko'rinishi.

  3. Sarlavha va tavsif yozing

    Sarlavha — nima qilingani, tavsif — nega. Hamkasbingiz shuni birinchi o'qiydi.

    Yozing:
    Sarlavha: Mening yo'lim eslatmasi qo'shildi
    Tavsif: Kursdagi o'z natijalarimni yozib boradigan fayl. Birinchi PR mashqi.

  4. Create pull request ni bosing

    Kutilgan natija: PR ochildi va unga raqam berildi (masalan #1). 2-g'alaba — birinchi pull request'ingiz! 🎉

  5. Endi «ko'rib chiquvchi» rolini o'ynang

    Ish joyida bu qismni hamkasbingiz qiladi — mexanika bir xil.

    Bajaring: Files changed bo'limiga o'ting. Qo'shilgan satrlar yashil va + bilan ko'rsatilgan — bu git diff ning brauzerdagi ko'rinishi. Satr ustiga sichqonchani olib boring va chapdagi ko'k «+» tugmasini bosib izoh qoldiring, masalan: Yaxshi boshlanish!

  6. Merge qiling

    Bu — taklifning qabul qilinishi.

    Bajaring: Conversation ga qayting → Merge pull request → Confirm merge.
    Kutilgan natija: binafsha rangda «Merged» yozuvi paydo bo'ladi. 3-g'alaba. 🎉

  7. Branch'ni o'chiring

    Ish qo'shildi — yorliq keraksiz (7-dars). GitHub o'zi taklif qiladi.

    Bajaring: Delete branch tugmasini bosing. Xavotir olmang — commitlar main ichida qoldi.

C qism — kompyuterga qaytish

  1. Merge'ni o'zingizga tortib oling

    Eng ko'p unutiladigan qadam. Merge GitHub'da bo'ldi — kompyuteringizdagi main hali bexabar.

    git switch main && git pull Updating f1fb65f..7c8d9e0 Fast-forward mening-yolim.md | 2 +

    Kutilgan natija: mening-yolim.md endi mainda. ls bilan tekshiring.

  2. Mahalliy branch'ni ham tozalang

    GitHub'dagisini o'chirdik, mahalliy nusxasi hali turibdi.

    git branch -d mening-birinchi-pr && git branch Deleted branch mening-birinchi-pr (was 3a4b5c6). * main

    Kutilgan natija: faqat main qoldi. To'liq aylana yakunlandi. 4-g'alaba! 🎉

  3. Natijani ko'ring

    git log --oneline -3 7c8d9e0 (HEAD -> main, origin/main) Merge pull request #1 from ... 3a4b5c6 Mening yo'lim eslatmasi qo'shildi

    Kutilgan natija: «Merge pull request #1» — GitHub yozgan commit izohi. Bu sizning birinchi PR'ingizning izi. 🏅

B — brauzerda GitHub'da haqiqiy PR ochasiz, Files changed da izoh qoldirasiz va merge qilasiz. C — terminalga qaytib git pull bilan natijani olasiz. Tekshirib ko'ramiz (quiz)

SAVOL 1 Pull request qayerda mavjud?

To'g'ri. Git — kompyuteringizdagi dastur; pull request — GitHub'dagi muhokama sahifasi. git pull request degan buyruq yo'q.

SAVOL 2 Yangi branch'ni birinchi marta jo'natyapsiz. Qaysi buyruq?

To'g'ri — GitHub bu branch'ni hali bilmaydi. -u bog'lanishni o'rnatadi; shundan keyin qisqa git push yetarli bo'ladi.

SAVOL 3 PR'da kod review qaysi bo'limda qilinadi?

To'g'ri — Files changed bu git diff ning brauzerdagi ko'rinishi. Har qaysi satrga alohida izoh qoldirish mumkin.

SAVOL 4 PR GitHub'da merge qilindi. Kompyuteringizda nima qilasiz?

To'g'ri, va bu eng ko'p unutiladigan qadam. Merge internetda bo'ldi; mahalliy main bexabar qoladi. Unutsangiz, keyingi ishni eskirgan kod ustida boshlaysiz.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — oldingi darslarni takrorlash.

Pull request bir jumlada nima?

«Mening branch'imdagi o'zgarishlarni mainga qo'shaylik — ko'rib chiqing» degan taklif. GitHub'ning imkoniyati, Git buyrug'i emas.

PR ning to'rt bosqichi?

1) Branch ochish · 2) git push -u · 3) PR ochish va review · 4) Merge.

PR sahifasida review qayerda qilinadi?

Files changed bo'limida — satrma-satr farq. Har qaysi satrga izoh qoldirish mumkin. Javob turlari: Approve, Request changes, Comment.

Yaxshi PR ning eng muhim xususiyati?

Kichik bo'lishi. Kichik PR tez va diqqat bilan ko'riladi; katta PR uzoq kutadi va yuzaki o'qiladi. Yana: bitta PR = bitta mavzu, tavsifda nega yozilgan bo'lsin.

Merge'dan keyingi eng ko'p unutiladigan qadam?

git switch main && git pull — merge internetda bo'ldi, mahalliy main hali eski.

↩︎ Takrorlash: konflikt chiqsa qochish yo'li qaysi?

git merge --abort — merge boshlangunga qadar bo'lgan holatga qaytaradi. (Dars 08)

↩︎ Takrorlash: branch nima — bir jumlada?

Bitta commitga ishora qiluvchi ko'chib yuruvchi yorliq, nusxa emas. (Dars 06)

Cho'ntak xulosasi
  • PR — GitHub imkoniyati, Git buyrug'i emas. git pull request yo'q.
  • To'rt bosqich: branch → git push -u origin nom → PR + review → merge.
  • Bo'limlar: Conversation (muhokama) · Commits · Files changed (review shu yerda) · Checks.
  • Review javoblari: Approve · Request changes · Comment.
  • Yaxshi PR: kichik, bitta mavzu, tavsifda nega yozilgan.
  • Review odobi: buyruq emas savol; kod haqida, odam haqida emas.
  • Merge'dan keyin: git switch main && git pull — unutmang!
