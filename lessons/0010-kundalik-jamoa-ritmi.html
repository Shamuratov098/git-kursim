DARS 10 · MODUL D · JAMOA

Kundalik jamoa ritmi

Bu darsda yangi buyruq deyarli yo'q. Buning o'rniga siz o'rgangan hamma narsani bitta takrorlanadigan tartibga bog'laymiz — va jamoada chindan uchraydigan uchta vaziyatni hal qilishni o'rganamiz.

📱 O'qish ≈ 9 daqiqa 💻 Amaliyot ≈ 14 daqiqa Kerak: Dars 09

Nega bu muhim

Hozirgacha har bir ko'nikmani alohida o'rgandingiz. Ish joyida esa ular bitta oqim bo'lib keladi — va o'ylab o'tirishga vaqt bo'lmaydi. Maqsad: bu tartib avtomatik bo'lib qolsin, xuddi mashina haydashdek. Shunda diqqatingiz Git'ga emas, ishingizga qaratiladi.

Aylana: bir ish, besh qadam

Bu — GitHub'ning o'zi tavsiya qiladigan tartib, «GitHub flow» deb ataladi.1 Millionlab jamoa shu bo'yicha ishlaydi:

1. Yangilan

git pull
Eng yangi maindan boshla
→switch -c

2. Branch

o'z yo'ling
Har ish uchun alohida
→add+commit

3. Ishla

kichik commitlar
Tez-tez saqlab bor
→push + PR

4–5. Taklif

PR → merge
Ko'rib chiqiladi va qo'shiladi

…va merge'dan keyin yana 1-qadamga qaytasiz: git switch main && git pull.

Kunni vaqt bo'yicha ko'ramiz

Aylanani eslab qolishning eng oson yo'li — uni kun tartibiga bog'lash.

☀️ Kun boshi — ikki buyruq

git switch main && git pull

Har kuni, ishni boshlashdan oldin. Sabab (5-dars): kecha siz uyquda bo'lganingizda hamkasblaringiz ish qo'shgan bo'lishi mumkin. Eskirgan kod ustida ishlash — konfliktning asosiy sababi.

Keyin darhol yangi ish uchun branch:

git switch -c email-xatosini-tuzatish

🛠️ Ish davomida — kichik commitlar

git add . && git commit -m "Bo'sh email tekshiruvi qo'shildi"

Har mantiqiy qadamdan keyin commit qiling — kunning oxirida bitta ulkan commit emas. Sabab 3-darsdagi oltin qoida: commit qilingan narsa xavfsiz.

Kun davomida push ham qiling

Branch'ingizni GitHub'ga jo'natib turish — bepul zaxira nusxa. Kompyuteringiz buzilsa, ishingiz internetda turadi. Birinchi marta git push -u origin branch-nomi, keyin oddiy git push.

🌙 Ish tugagach — PR

git push

Keyin GitHub'da PR ochasiz, ko'rib chiqiladi, merge qilinadi. Va oxirida — aylananing yopilishi:

git switch main && git pull && git branch -d email-xatosini-tuzatish

Jamoada chindan uchraydigan uch vaziyat

Yolg'iz ishlaganda bular chiqmaydi. Jamoada esa — har hafta. Uchalasi ham oddiy, agar oldindan bilsangiz.

1️⃣ «Branch'im eskirib qoldi»

Siz uch kun bitta branch'da ishladingiz. Shu orada mainga boshqalarning ishi qo'shildi. Sizning branch'ingiz eskirgan poydevorda turibdi.

Yechim — mainni o'z branch'ingizga qo'shish:

git switch main && git pull && git switch mening-branchim && git merge main --no-edit

Odatda bu merge commit yaratadi («Merge made by...»), chunki ikkala tomon ham siljigan bo'ladi — 7-darsdagi ikkinchi holat. --no-edit esa tahrirlagich ochilib qolishining oldini oladi.

Yo'nalishga e'tibor bering

7-darsda loginni mainga qo'shgan edik. Bu safar teskarisi: mainni loginga qo'shyapmiz. Bu — «ishimni eng yangi poydevorga ko'chirish» degani. Qoida o'zgarmadi: qabul qiluvchida turasiz, ya'ni o'z branch'ingizda.

Buni tez-tez qiling — har kuni bo'lsa ideal. Sababi sodda: kichik farqlar oson birlashadi, katta farqlar og'riqli konflikt beradi.

2️⃣ «Push rad etildi»

Siz push qilmoqchisiz, lekin Git rad etadi:

git push ! [rejected] main -> main (fetch first) error: failed to push some refs to '...' hint: Updates were rejected because the remote contains work that you do hint: not have locally.
Bu xato emas — himoya

Ma'nosi: sizdan oldin kimdir push qilgan. Agar Git sizni o'tkazib yuborganida, o'sha odamning ishi yo'q bo'lardi. Shuning uchun u to'xtatadi.

Yechim ikki buyruq — avval oling, keyin jo'nating:

git pull
git push

Agar pull paytida konflikt chiqsa — hal qilasiz (8-dars) va keyin push qilasiz. Boshqa hech narsa kerak emas.

Bir martalik sozlama — buni hozir bajaring

Shu holatda git pull ba'zan ishlamay, shunday yozadi:

git pull fatal: Need to specify how to reconcile divergent branches.

Sabab: ikkala tomonda ham yangi commit bor va Git ularni qanday birlashtirishni so'rayapti — merge bilanmi yoki rebase bilanmi. Biz kurs davomida merge ishlatamiz, shuning uchun bir marta aytib qo'yamiz:

git config --global pull.rebase false

Ma'nosi: «pull qilganda merge ishlat». Bir marta yozasiz — kompyuteringizdagi barcha loyihalar uchun (--global). Shundan keyin git pull har doim ishlaydi.3

3️⃣ «Branch ochishni unutib, mainda commit qilib qo'ydim»

Juda ko'p uchraydigan holat. Yaxshi xabar: hali push qilmagan bo'lsangiz, bu osongina tuzatiladi.

1-qadam — ishingizni branch'ga «ko'chirib oling». Aslida ko'chirilmaydi: shu joyda yangi yorliq yaratasiz (6-dars: branch = yorliq):

git switch -c ishim-uchun-branch

Endi commitlaringiz shu branch'da xavfsiz. Tekshiring: git log --oneline -3.

2-qadam — mainni GitHub'dagi holatga qaytaring:

git switch main && git reset --hard origin/main
⚠️ reset --hard — kursdagi eng xavfli buyruq

U so'ramasdan o'chiradi. Uch shart:

1. Yuqoridagi 1-qadamni albatta bajarib bo'lgan bo'ling — aks holda commitlaringiz qoladigan joy yo'q.
2. Faqat mainda turib bajaring.
3. Saqlanmagan o'zgarishlaringiz bo'lmasin (git status bilan tekshiring).

Shubhangiz bo'lsa — bajarmang, menga yozing. Birga qilamiz. Bu buyruqni bilib qo'yish kerak, lekin shoshilib ishlatish kerak emas.

Ritm bo'yicha uch maslahat

  • Branch uzoq yashamasin. 1–3 kun ideal. Qancha uzoq yashasa, shuncha ko'p konflikt to'planadi va PR shuncha katta bo'lib ketadi.
  • Kuniga kamida bir marta push qiling. Bu zaxira nusxa; hamkasblaringiz ham nima ustida ishlayotganingizni ko'radi.
  • Chalkashsangiz — git status. Birinchi darsdan oxirgisigacha o'zgarmagan yagona maslahat. U hech narsani buzmaydi va deyarli har doim keyingi qadamni aytib beradi.

Amaliyot: bir ish kunini boshdan oxir o'ynaymiz

Mashq haqiqiy repongizda. «Hamkasbingiz» rolini bu safar GitHub'ning o'zida fayl tahrirlab o'ynaymiz — bu ham foydali ko'nikma.

A qism — kun boshi va ish

  1. Bir martalik sozlama

    Bu bo'lmasa, keyinroq git pull «Need to specify how to reconcile divergent branches» deb to'xtab qolishi mumkin. Bir marta yozasiz — umrbod yetadi.

    git config --global pull.rebase false

    Kutilgan natija: jimlik (= muvaffaqiyat). Tekshirish: git config --global --get pull.rebase → false.

  2. Kunni yangilanishdan boshlang

    Har kungi birinchi ikki buyruq.

    cd ~/Projects/Learn/Git && git switch main && git pull Already up to date.

    Kutilgan natija: «Already up to date» yoki yangi commitlar tushadi.

  3. Ish uchun branch oching va commit qiling

    Odatiy ish boshlanishi.

    git switch -c kunlik-ritm-mashqi && echo "Kunlik ritm mashqi." > ritm.txt && git add ritm.txt && git commit -m "Ritm mashq fayli qo'shildi"

    Kutilgan natija: yangi branch va 1 file changed.

  4. Branch'ni GitHub'ga jo'nating (zaxira)

    Yangi branch — shuning uchun -u.

    git push -u origin kunlik-ritm-mashqi * [new branch] kunlik-ritm-mashqi -> kunlik-ritm-mashqi

    Kutilgan natija: «[new branch]». Ishingiz endi internetda ham bor.

B qism — «hamkasbingiz» main'ga ish qo'shdi

  1. GitHub'da repongizni oching

    xdg-open https://github.com/Shamuratov098/git-kursim

    Kutilgan natija: repo sahifasi ochiladi, main branch ko'rinib turadi.

  2. Brauzerning o'zida yangi fayl yarating

    GitHub'da to'g'ridan-to'g'ri tahrirlash mumkin — kichik tuzatishlar uchun juda qulay ko'nikma.

    Bajaring: Add file → Create new file. Fayl nomi: hamkasb-ishi.txt, ichiga bir qator yozing (masalan Hamkasbim qo'shgan fayl.). Pastga tushib Commit changes → yana Commit changes.
    Kutilgan natija: fayl mainda paydo bo'ldi — ya'ni GitHub'dagi main endi sizning mahalliy nusxangizdan oldinda.

C qism — branch'ingizni yangilang

  1. Mahalliy mainni yangilang

    Avval o'zingizda eng yangi main bo'lsin.

    git switch main && git pull Updating 7c8d9e0..b4c5d6e Fast-forward hamkasb-ishi.txt | 1 +

    Kutilgan natija: «Fast-forward» va yangi fayl tushdi. ls bilan tekshiring. 1-g'alaba. 🎉

  2. Branch'ingizga qayting va uni ko'ring

    Bu yerda hamkasbingizning ishi hali yo'q — branch eskirgan.

    git switch kunlik-ritm-mashqi && ls

    Kutilgan natija: hamkasb-ishi.txt yo'q. Branch'ingiz eski poydevorda turibdi.

  3. 🔑 mainni branch'ingizga qo'shing

    Darsning asosiy yangi ko'nikmasi. Diqqat: yo'nalish teskari — main'ni o'zimizga olyapmiz. --no-edit — tahrirlagich ochilmasin (7-dars).

    git merge main --no-edit Merge made by the 'ort' strategy. hamkasb-ishi.txt | 1 +

    Kutilgan natija: «Merge made by...» — ya'ni merge commit yaratildi. ls deng: hamkasb-ishi.txt endi branch'ingizda ham bor, va sizning ritm.txt ham joyida. 2-g'alaba. 🎉

    Nega Fast-forward emas? Chunki ikkala tomon ham siljigan edi: siz ritm.txt qo'shdingiz, «hamkasbingiz» hamkasb-ishi.txt. Aynan 7-darsdagi ikkinchi holat — Git yorliqni sura olmaydi, shuning uchun ikkita ota-onali commit yaratadi.

  4. Yangilangan branch'ni jo'nating

    Endi -u kerak emas — bog'lanish o'rnatilgan.

    git push

    Kutilgan natija: qisqa git push ishladi. Branch GitHub'da ham yangilandi.

D qism — aylanani yoping

  1. PR ochib merge qiling

    9-darsdagi tartib — bu safar o'zingiz bajarasiz.

    Bajaring: GitHub'da Compare & pull request → sarlavha yozing → Create pull request → Merge pull request → Delete branch.

  2. Aylanani yoping

    Merge internetda bo'ldi — o'zingizga tortib olasiz va tozalaysiz. Bu — ertangi kunning 1-qadami ham.

    git switch main && git pull && git branch -d kunlik-ritm-mashqi Deleted branch kunlik-ritm-mashqi (was 9f0a1b2).

    Kutilgan natija: main yangilandi va branch tozalandi. To'liq bir ish kunini bajardingiz. 3-g'alaba! 🎉🎉

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda (va brauzerda)

Amaliyotda bir ish kunini boshdan oxir o'ynaysiz: kun boshi pull → branch → commit → push. Keyin «hamkasbingiz» rolida GitHub'ning o'zida fayl yaratasiz (bu ham foydali ko'nikma), branch'ingiz eskirganini ko'rasiz va uni git merge main bilan yangilaysiz — bu darsning asosiy yangi ko'nikmasi. Tekshirib ko'ramiz (quiz)

SAVOL 1 Ish kunini nimadan boshlaysiz?

To'g'ri. Kecha hamkasblaringiz ish qo'shgan bo'lishi mumkin. Eskirgan kod ustida ishlash — konfliktning asosiy sababi.

SAVOL 2 Branch'ingiz eskirdi — mainga yangi ish qo'shilgan. Nima qilasiz?

To'g'ri — yo'nalish bu safar teskari: mainni o'zingizga olyapsiz. Qoida esa o'zgarmadi: qabul qiluvchida turasiz, ya'ni o'z branch'ingizda.

SAVOL 3 git push «rejected» dedi. Bu nima degani?

To'g'ri, va bu himoya: Git sizni o'tkazib yuborganida, o'sha odamning ishi yo'q bo'lardi. Yechim: git pull, keyin git push.

SAVOL 4 Nega branch uzoq yashamasligi kerak?

To'g'ri. Kichik farqlar oson birlashadi, katta farqlar og'riqli konflikt beradi. 1–3 kunlik branch ideal.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — oldingi darslarni takrorlash.

Kundalik aylananing besh qadami?

1) pull — yangilan · 2) branch och · 3) ishla + kichik commitlar · 4) push · 5) PR → merge. Keyin yana 1-qadamga.

Kun boshidagi ikki buyruq?

git switch main && git pull.

Branch eskirsa — buyruq va yo'nalish?

O'z branch'ingizda turib git merge main. Ya'ni mainni o'zingizga olasiz — 7-darsdagining teskarisi. Qoida esa bir xil: qabul qiluvchida turasiz.

! [rejected] ko'rsangiz nima qilasiz?

git pull, keyin git push. Ma'nosi: sizdan oldin kimdir push qilgan.

mainda commit qilib qo'ydingiz. Birinchi qadam qaysi?

git switch -c ishim-uchun-branch — ishingiz shu yerda xavfsiz bo'ladi. Faqat shundan keyin mainni git reset --hard origin/main bilan qaytarasiz.

↩︎ Takrorlash: PR merge qilingandan keyin nima qilasiz?

git switch main && git pull — merge internetda bo'ldi. (Dars 09)

↩︎ Takrorlash: chalkashib qolsangiz birinchi buyruq?

git status — 2-darsdan beri o'zgarmagan javob. U hech narsani buzmaydi. (Dars 02)

Cho'ntak xulosasi
  • Aylana: pull → branch → ishla+commit → push → PR → merge → pull…
  • Kun boshi: git switch main && git pull.
  • Ish davomida: kichik commitlar, kuniga kamida bir marta push.
  • Branch eskirsa: o'z branch'ingizda git merge main --no-edit.
  • Push rad etilsa: git pull → git push.
  • mainda commit qilsangiz: avval git switch -c ..., keyin git reset --hard origin/main ⚠️.
  • Branch 1–3 kun yashasin — uzoq yashagani konflikt to'playdi.
  • Chalkashsangiz: git status.
