DARS 14 · QO'SHIMCHA · KURSDAN KEYIN

git reflog: yo'qolgan ishni qaytarish

Bu darsdan keyin siz «hammasini yo'qotdim» degan holatdan chiqa olasiz. Va nihoyat bilasiz: 3-darsdagi oltin qoida nega rostdan ishlaydi.

📱 O'qish ≈ 8 daqiqa 💻 Amaliyot ≈ 12 daqiqa Kerak: Dars 10, 13

Nega bu dars aynan hozir

Siz endi xavfli buyruqlarni bilasiz: reset --hard, rebase, branch -D, commit --amend. Ularning hammasi tarixni o'zgartiradi.

reflog — mana shu buyruqlarning hammasi ostida yotgan himoya to'ri. Uni bilsangiz, ulardan qo'rqmaysiz.

reflog nima

Git siz qayerda bo'lganingizni jimgina yozib boradi. Har bir commit, switch, merge, rebase, reset — hammasi qayd qilinadi. Bu yozuv reflog (reference log) deb ataladi.1

Asosiy g'oya

Commit «o'chirilganda» ham u repozitoriyda qolaveradi — faqat unga ishora qiluvchi yorliq yo'qoladi. Reflog esa o'sha yo'qolgan ishorani saqlab turadi. Ya'ni siz commitni emas, faqat unga olib boradigan yo'lni yo'qotgansiz.

Reflog o'sha yo'lni qaytarib beradi.

Nihoyat: 3-darsdagi oltin qoida nega ishlaydi

3-darsda shunday degandim: «commit qilingan narsani yo'qotish juda qiyin, commit qilinmaganini esa oson». Endi sababi ma'lum — reflog. Commit qilingan har bir narsa reflogda iz qoldiradi. Commit qilinmagan o'zgarish esa hech qayerda yozilmagan, shuning uchun uni hech narsa qaytara olmaydi.

Chiqishini o'qishni o'rganamiz

Har qatorda uch narsa bor:

QismMa'nosi
5b7c611 Commit hashi — qaytarish uchun kerak bo'ladigan narsa.
HEAD@{1} «1 qadam oldin». HEAD@{0} — hozirgi joy, HEAD@{1} — undan oldingisi va hokazo. Hash o'rniga shuni ham yozsa bo'ladi.
commit: / reset: / rebase: Nima qilganingiz. Falokatdan oldingi qatorni topish uchun eng foydali ustun.
Qanday o'qiladi

Yuqoridan pastga — yangidan eskiga. «Falokat»ni topib (masalan reset: qatori), undan bir qator pastdagi holatga qaytasiz.

To'rtta qutqarish retsepti

FalokatYechim
reset --hard bilan commitlarni yo'qotdim git reflog → falokatdan oldingi qatorni toping → git reset --hard HEAD@{1} Yoki hash bilan: git reset --hard 5b7c611
Branch'ni o'chirib yubordim git switch -c branch-nomi <hash> — o'sha commitda branch'ni qayta yaratadi. Hash o'chirish xabarida ham bor: «Deleted branch X (was e6c0d99)».
rebase buzildi Reflogda rebase (start) qatorini toping → undan oldingi holatga git reset --hard HEAD@{N}. Rebase hali tugamagan bo'lsa — git rebase --abort osonroq.
--amend bilan eski commitni yo'qotdim Reflogda commit (amend) dan oldingi qatorni toping — eski commit o'sha yerda turibdi.
Umumiy tartib — har doim bir xil

1. git reflog → 2. yaxshi holatning hash'ini toping → 3. o'sha yerga qayting yoki branch yarating.

Shoshilmang: git reflog hech narsani o'zgartirmaydi, xohlagancha qarayvering.

Chegaralari — buni bilib qo'ying

Reflog nimani QAYTARA OLMAYDI

Commit qilinmagan o'zgarishni. Agar faylni tahrirlab, commit qilmasdan git restore yoki reset --hard qilsangiz — u hech qayerda yozilmagan va reflog ham yordam bera olmaydi.

Mana shuning uchun tez-tez commit qiling. Har commit — reflogga tushadigan qutqaruv nuqtasi.

Reflog — zaxira nusxa EMAS

Xuddi stash kabi, u faqat sizning kompyuteringizda. Push qilinmaydi, clone bilan ko'chmaydi, hamkasbingizda yo'q. Kompyuteringiz buzilsa — reflog ham ketadi.

Haqiqiy zaxira — git push.

Muddat: taxminan 90 kun

Git reflog yozuvlarini standart holatda 90 kun saqlaydi (hech qaysi branch'ga ulanmagan commitlar — 30 kun), keyin tozalab yuboradi.2 Amalda bu juda yetarli: falokat odatda o'sha kuni sezildi.

Amaliyot: ataylab yo'qotib, qaytaramiz

Mashq nusxa papkada (~/Projects/Learn/Git-nusxa). Ataylab falokat yasaymiz — va ikkala holatda ham hammasini qaytaramiz.

A qism — reset --hard dan qaytarish

  1. Uchta commit yarating

    Uchinchisi — «muhim ish», uni yo'qotib ko'ramiz.

    cd ~/Projects/Learn/Git-nusxa && git switch main && echo "1" > rl.txt && git add rl.txt && git commit -m "Reflog mashqi: birinchi" && echo "2" >> rl.txt && git commit -am "Reflog mashqi: ikkinchi" && echo "3" >> rl.txt && git commit -am "Reflog mashqi: MUHIM ISH"

    Kutilgan natija: uchta commit. git log --oneline -3 bilan tekshiring.

  2. 💥 Falokat: ikkita commitni o'chiring

    HEAD~2 = «ikki qadam orqaga». Bu — 10-darsdagi xavfli buyruq.

    git reset --hard HEAD~2 HEAD is now at 49dd82e Reflog mashqi: birinchi

    Kutilgan natija: git log --oneline -3 deng — ikkita commit yo'q. cat rl.txt deng — faqat 1. «Muhim ish» yo'qoldi. 😱

  3. Vahima qilmang — reflogga qarang

    Bu buyruq hech narsani o'zgartirmaydi.

    git reflog -5 49dd82e HEAD@{0}: reset: moving to HEAD~2 5b7c611 HEAD@{1}: commit: Reflog mashqi: MUHIM ISH b881146 HEAD@{2}: commit: Reflog mashqi: ikkinchi

    Kutilgan natija: HEAD@{0} — falokat (reset:), HEAD@{1} — yo'qolgan «MUHIM ISH». U yo'qolmagan ekan! 1-g'alaba. 🎉

  4. Qaytaring

    Falokatdan bir qadam oldingi holatga qaytamiz.

    git reset --hard HEAD@{1} HEAD is now at 5b7c611 Reflog mashqi: MUHIM ISH

    Kutilgan natija: git log --oneline -3 — uchala commit ham joyida. cat rl.txt — 1 2 3. To'liq tiklandi. 2-g'alaba. 🎉

B qism — o'chirilgan branch'ni qaytarish

  1. Branch yaratib, unda ish qiling

    git switch -c muhim-branch && echo "juda muhim ish" > muhim.txt && git add muhim.txt && git commit -m "Juda muhim ish"

    Kutilgan natija: yangi branch va commit.

  2. 💥 Falokat: branch'ni majburan o'chiring

    -D (katta harf) — «merge qilinmagan bo'lsa ham o'chir». -d bunday holatda ruxsat bermagan bo'lardi (7-dars).

    git switch main && git branch -D muhim-branch Deleted branch muhim-branch (was e6c0d99).

    Kutilgan natija: git branch deng — branch yo'q. ls muhim.txt — fayl ham yo'q. 😱
    Lekin diqqat: Git «was e6c0d99» deb hash'ni o'zi aytib turibdi — qutqarish kaliti shu yerda.

  3. Hash'ni toping

    Yuqoridagi xabarni o'tkazib yuborgan bo'lsangiz — reflogda ham bor.

    git reflog -4 5b7c611 HEAD@{0}: checkout: moving from muhim-branch to main e6c0d99 HEAD@{1}: commit: Juda muhim ish

    Kutilgan natija: HEAD@{1} da «Juda muhim ish» va uning hash'i. Sizdagi hash boshqacha bo'ladi — o'zingiznikini yozing.

  4. Branch'ni qayta tiklang

    Branch — bu shunchaki yorliq (6-dars). Uni istalgan commitda qayta yaratish mumkin.

    git switch -c muhim-branch e6c0d99 Switched to a new branch 'muhim-branch'

    Kutilgan natija: ⚠️ e6c0d99 o'rniga o'zingizning hash'ingizni yozing. Keyin ls muhim.txt deng — fayl qaytdi! 3-g'alaba. 🎉🎉

Endi nimani his qilishingiz kerak

Siz ikki marta «yo'qotdim» deb o'ylagan ishni qaytardingiz. Bundan keyin reset --hard ham, rebase ham sizni qo'rqitmasligi kerak — chunki ostingizda to'r bor.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda ataylab ikki marta falokat yasaysiz va ikkalasidan ham chiqasiz: reset --hard HEAD~2 bilan ikkita commitni yo'qotib, reflogdan topib qaytarasiz; keyin branch'ni -D bilan o'chirib, hash orqali qayta tiklaysiz. 8 qadam, hammasi nusxa papkada.

Tekshirib ko'ramiz (quiz)

SAVOL 1 reset --hard bilan commitlarni yo'qotdingiz. Birinchi buyruq?

To'g'ri. Reflog — HEAD qayerda bo'lganining yozuvi. U hech narsani o'zgartirmaydi, shuning uchun bemalol qarayvering.

SAVOL 2 HEAD@{1} nimani anglatadi?

To'g'ri. HEAD@{0} — hozirgi joy, HEAD@{1} — undan oldingisi. Hash o'rniga shuni yozsa ham bo'ladi.

SAVOL 3 Reflog nimani qaytara OLMAYDI?

To'g'ri, va bu 3-darsdagi oltin qoidaning sababi: commit qilingan narsa xavfsiz, chunki u reflogda iz qoldiradi. Commit qilinmagani esa hech qayerda yo'q.

SAVOL 4 Reflog zaxira nusxa vazifasini o'taydimi?

To'g'ri. Reflog — stash kabi mahalliy. Haqiqiy zaxira — git push.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring.

Reflog nima yozib boradi?

HEAD qayerda bo'lganini — har bir commit, switch, merge, rebase, reset. Ya'ni siz bosib o'tgan yo'l.

Nega «o'chirilgan» commit qaytariladi?

Chunki commit repozitoriyada qolaveradi — faqat unga ishora qiluvchi yorliq yo'qoladi. Reflog o'sha ishorani saqlaydi.

Qutqarishning uch qadami?

1. git reflog · 2. yaxshi holatning hash'ini toping · 3. git reset --hard <hash> yoki git switch -c nom <hash>.

O'chirilgan branch'ni qanday tiklaysiz?

git switch -c branch-nomi <hash>. Hash o'chirish xabarida ham bor: «Deleted branch X (was e6c0d99)».

Reflogning ikkita chegarasi?

1. Commit qilinmagan ishni qaytara olmaydi · 2. Faqat mahalliy — push qilinmaydi, zaxira emas. Muddat ~90 kun.

↩︎ Takrorlash: 3-darsdagi oltin qoida — va endi uning sababi?

«Commit qilingan narsani yo'qotish juda qiyin». Sababi — reflog: har commit unda iz qoldiradi. (Dars 03)

Cho'ntak xulosasi
  • Reflog = HEAD qayerda bo'lganining mahalliy yozuvi. Himoya to'ri.
  • Falokat bo'lsa birinchi buyruq: git reflog (u hech narsani o'zgartirmaydi).
  • HEAD@{1} = bir qadam oldin. Hash o'rniga ishlatsa bo'ladi.
  • reset --hard dan qaytish: git reset --hard HEAD@{1}
  • O'chirilgan branch: git switch -c nom <hash> (hash o'chirish xabarida ham bor).
  • ⚠️ Commit qilinmagan ishni qaytara olmaydi → tez-tez commit qiling.
  • ⚠️ Mahalliy va ~90 kunlik. Haqiqiy zaxira — git push.
