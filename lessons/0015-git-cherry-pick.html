DARS 15 · QO'SHIMCHA · KURSDAN KEYIN

git cherry-pick: bitta commitni tanlab olish

Bu darsdan keyin siz butun branch'ni emas, aynan kerakli commitni boshqa joydan olib kelasiz — shoshilinch tuzatishni tarqatish yoki noto'g'ri branch'ga tushib qolgan ishni ko'chirish uchun.

📱 O'qish ≈ 8 daqiqa 💻 Amaliyot ≈ 13 daqiqa Kerak: Dars 13, 14

Nega bu kerak

Shu paytgacha ishni ko'chirishning ikki yo'lini bildingiz: merge va rebase. Ikkalasi ham butun branchni olib keladi.

Lekin ba'zan sizga faqat bittasi kerak: hamkasbingiz uzun branch'ida ishlayapti, ichida bitta shoshilinch xato tuzatilgan — sizga o'sha kerak, qolgan yarim ishlar emas. Mana shu — cherry-pickning ishi.

Nomi ma'noni aytib turibdi

Cherry-picking — «gilosni tanlab uzish». Butun daraxtni emas, faqat pishganini. Git'da ham xuddi shunday: butun branch'ni emas, bitta commitni olib, o'z branch'ingizga qo'yasiz.1

Faqat tuzatish commiti mainga ko'chdi — «yarim ish» o'z joyida qoldi.

Nusxa — asli emas

Rebase kabi, cherry-pick ham commitni ko'chirmaydi — o'sha o'zgarish bilan yangi commit yaratadi. Asl commit o'z branch'ida qolaveradi.

Odatda yangi hash chiqadi (ota-ona boshqa bo'lgani uchun). Agar ikkala branch ham bir xil joydan chiqqan bo'lsa, hash bir xil ham bo'lishi mumkin — bu normal.

Buyruqlar

BuyruqNima qiladi
git cherry-pick <hash> O'sha commitni joriy branch'ga qo'shadi. Avval kerakli branch'ga o'ting — merge'dagi kabi.
git cherry-pick <h1> <h2> Bir nechta commitni ketma-ket qo'shadi.
git cherry-pick -x <hash> Izohga «(cherry picked from commit …)» qatorini qo'shadi. Jamoada tavsiya qilinadi: nusxa qayerdan kelganini keyin topish oson bo'ladi.
git cherry-pick --abort Qochish yo'li — boshlangunga qadar bo'lgan holatga qaytaradi.
git cherry-pick --continue Konfliktni hal qilib git add qilgandan keyin davom ettiradi.

Hash'ni qayerdan olaman?

git log --oneline ishlar b9cd95c Yarim tugagan boshqa ish 2e4e07d Shoshilinch xato tuzatildi ← shu kerak

Boshqa branch'ning tarixiga qarash uchun uning nomini yozasiz. Kerakli qatorning boshidagi 7 belgi — hash.

Uch xil «noto'g'ri joyga ishlab qo'ydim» holati

Endi sizda bu muammoning to'liq oilasi uchun yechim bor. Qaysi biri kerakligini ish qanday holatda ekani belgilaydi:

HolatYechim
Hali commit qilmadim git stash → switch → git stash pop Dars 12
Commit qildim, hammasi ko'chsin git switch -c yangi-branch → git switch main → git reset --hard origin/main Dars 10
Commit qildim, faqat bittasi ko'chsin git switch to-g-ri-branch → git cherry-pick <hash> → keyin asl joydan olib tashlash Shu dars

Konflikt bo'lsa

Bo'lishi mumkin — chunki commit boshqa muhitga qo'yilyapti. Hal qilish 8-darsdagi kabi, faqat oxirgi buyruq boshqa:

  1. Faylni tahrirlang, belgilarni o'chiring;
  2. git add <fayl>;
  3. git cherry-pick --continue (commit emas).
Yaxshi xabar: belgilar TESKARI emas

Rebase'da belgilar teskari bo'lardi. Cherry-pick'da esa hammasi odatdagidek: <<<<<<< HEAD = siz turgan branch, pastdagisi = olib kelinayotgan commit. Xuddi merge'dagidek.

Ehtiyot bo'ling: takroriy commitlar

Cherry-pick — merge'ning o'rnini bosmaydi

Cherry-pick nusxa yaratadi. Ya'ni bir xil o'zgarish endi ikki joyda, ikki xil commit sifatida turadi. Keyin o'sha branch'ni baribir merge qilsangiz, Git chalkashishi yoki keraksiz konflikt chiqishi mumkin.

Qoida: butun branch kerak bo'lsa — merge. Cherry-pick faqat alohida, aniq bir commit kerak bo'lganda.

Amaliyot: gilosni tanlab uzamiz

Mashq nusxa papkada (~/Projects/Learn/Git-nusxa), push yo'q.

A qism — ikkitadan bittasini olish

  1. Branch yaratib, ikkita har xil commit qiling

    Biri — shoshilinch tuzatish, ikkinchisi — yarim ish. Bizga faqat birinchisi kerak bo'ladi.

    cd ~/Projects/Learn/Git-nusxa && git switch main && git switch -c cp-ishlar && echo "muhim tuzatish" > cp-tuzatish.txt && git add cp-tuzatish.txt && git commit -m "Shoshilinch xato tuzatildi" && echo "yarim ish" > cp-yarim.txt && git add cp-yarim.txt && git commit -m "Yarim tugagan boshqa ish"

    Kutilgan natija: ikkita commit yaratildi.

  2. Kerakli commitning hash'ini toping

    «Shoshilinch xato tuzatildi» qatoridagi 7 belgi.

    git log --oneline -2 b9cd95c Yarim tugagan boshqa ish 2e4e07d Shoshilinch xato tuzatildi

    Kutilgan natija: ikki qator. Ikkinchi qatordagi hash'ni yozib oling — sizda boshqacha bo'ladi.

  3. mainga qaytib, u yerda ham ish qiling

    Bu ajralish yaratadi — shunda nusxaning hash'i o'zgarganini ko'rasiz.

    git switch main && echo "main ishi" > cp-main.txt && git add cp-main.txt && git commit -m "Main da boshqa ish"

    Kutilgan natija: commit yaratildi.

  4. 🍒 Faqat tuzatishni oling

    -x — nusxa qayerdan kelganini izohga yozadi. ⚠️ 2e4e07d o'rniga o'z hash'ingizni yozing.

    git cherry-pick -x 2e4e07d [main 4490a6b] Shoshilinch xato tuzatildi 1 file changed, 1 insertion(+)

    Kutilgan natija: commit qo'shildi va hash boshqa (2e4e07d → 4490a6b) — bu nusxa. 1-g'alaba. 🎉

  5. Nima kelganini tekshiring

    Eng muhim tasdiq: «yarim ish» kelmagan bo'lishi kerak.

    ls cp-*.txt && git log -1 --format=%B cp-main.txt cp-tuzatish.txt Shoshilinch xato tuzatildi (cherry picked from commit 2e4e07d...)

    Kutilgan natija: cp-tuzatish.txt bor, cp-yarim.txt yo'q — aynan kerakli commit keldi. Va -x qo'shgan iz izohda ko'rinadi. 2-g'alaba. 🎉

B qism — noto'g'ri branch'ga commit qilib qo'ydim

  1. Bo'sh xususiyat branch yarating

    git branch (switch'siz) — yaratadi, lekin o'tmaydi.

    git branch cp-xususiyat && git branch * main cp-xususiyat

    Kutilgan natija: yulduzcha hali mainda.

  2. 💥 mainda adashib commit qiling

    Bu ish aslida branch'da bo'lishi kerak edi.

    echo "bu branchda bolishi kerak edi" > cp-xus.txt && git add cp-xus.txt && git commit -m "Xususiyat ishi (adashib main da)" && git log --oneline -1

    Kutilgan natija: commit mainda. Chiqqan hash'ni yozib oling.

  3. To'g'ri branch'ga ko'chiring

    ⚠️ Hash o'rniga o'zingiznikini yozing.

    git switch cp-xususiyat && git cherry-pick HASHNI-BU-YERGA

    Kutilgan natija: commit branch'ga qo'shildi. ls cp-xus.txt deng — fayl shu yerda.

  4. maindan olib tashlang

    10-darsdagi buyruq. Xavfsiz, chunki ish allaqachon branch'da saqlangan.

    git switch main && git reset --hard HEAD~1 && git log --oneline -2

    Kutilgan natija: mainda adashgan commit yo'q, ls cp-xus.txt ham topilmaydi. Ish esa branch'da turibdi. 3-g'alaba. 🎉

  5. Xotirjamlik uchun: himoya to'ri joyidami?

    14-dars — adashsangiz ham qaytarish mumkin.

    git reflog -4

    Kutilgan natija: reset:, checkout:, cherry-pick: qatorlari — barcha harakatlaringiz yozilgan.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda branch'da ikkita commit yaratasiz va mainga faqat bittasini olasiz — ikkinchisi kelmaganini o'z ko'zingiz bilan tekshirasiz. Keyin klassik holat: mainga adashib qilingan commitni to'g'ri branch'ga ko'chirib, asl joydan olib tashlaysiz. 10 qadam, nusxa papkada.

Tekshirib ko'ramiz (quiz)

SAVOL 1 Cherry-pick mergedan nimasi bilan farq qiladi?

To'g'ri. Merge butun branch'ni olib keladi, cherry-pick esa aniq bir commitni. Nomi ham shundan: gilosni tanlab uzish.

SAVOL 2 Cherry-pick'dan keyin asl commitga nima bo'ladi?

To'g'ri. Cherry-pick nusxa yaratadi. Aynan shuning uchun keyinchalik takroriy commitlar chalkashlik keltirishi mumkin.

SAVOL 3 Qaysi branch'da turib cherry-pick qilasiz?

To'g'ri — merge'dagi kabi: qabul qiluvchi branch'ga o'tib, keyin manba commitning hash'ini yozasiz.

SAVOL 4 Hamkasbingizning butun branch'i sizga kerak. Nima qilasiz?

To'g'ri. Butun branch kerak bo'lsa — merge. Hammasini cherry-pick qilish takroriy commitlar yaratadi va keyin chalkashlik keltiradi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring.

Cherry-pick bir jumlada nima qiladi?

Boshqa branch'dagi bitta commitni olib, joriy branch'ga nusxa sifatida qo'shadi. Asl commit o'z joyida qoladi.

Qaysi branch'da turasiz — va hash kimniki?

Qabul qiluvchi branch'da turasiz, hash esa manba commitniki. Merge'dagi yo'nalish qoidasi bilan bir xil.

-x nima uchun kerak?

Izohga «(cherry picked from commit …)» qatorini qo'shadi — nusxa qayerdan kelgani keyin ma'lum bo'ladi. Jamoada tavsiya qilinadi.

Konfliktda belgilar rebase'dagidek teskarimi?

Yo'q — odatdagidek: HEAD = siz turgan branch, pastdagisi = olib kelinayotgan commit. Xuddi merge'dagidek.

Uch xil «noto'g'ri joyda ishlab qo'ydim» — yechimlari?

Commit qilmagan → stash (Dars 12) · Commit qilingan, hammasi ko'chsin → switch -c + reset --hard (Dars 10) · Faqat bittasi ko'chsin → cherry-pick (shu dars).

↩︎ Takrorlash: adashsangiz nima sizni qutqaradi?

git reflog — barcha harakatlaringiz yozilgan. (Dars 14)

Cho'ntak xulosasi
  • Cherry-pick = boshqa branch'dan bitta commitni tanlab olish.
  • Yangi nusxa yaratadi — asl commit o'z branch'ida qolaveradi.
  • Avval qabul qiluvchi branch'ga o'ting, keyin manba hash'ini yozing.
  • git cherry-pick -x <hash> — jamoada, iz qolishi uchun.
  • Konflikt: add → git cherry-pick --continue · qochish: --abort. Belgilar odatdagidek (teskari emas).
  • ⚠️ Butun branch kerak bo'lsa — merge. Cherry-pick takroriy commitlar yaratadi.
  • Hash'ni ko'rish: git log --oneline <branch-nomi>.
