DARS 16 · QO'SHIMCHA · KURSDAN KEYIN

Fork: birovning loyihasiga hissa qo'shish

Bu darsdan keyin siz o'zingizniki bo'lmagan loyihaga o'zgarish taklif qila olasiz — ya'ni open source'ga birinchi hissangizni qo'shasiz.

📱 O'qish ≈ 8 daqiqa 💻 Amaliyot ≈ 20 daqiqa Kerak: Dars 09

Nega bu dars qo'shildi

11-darsda sizga «real loyihaga birinchi PR'ingizni oching» deb tavsiya qilgandim. Lekin buning yo'lini o'rgatmagan ekanman — bu mening kamchiligim edi. Mana shu dars o'sha bo'shliqni yopadi.

Muammo: birovning repo'siga push qila olmaysiz

9-darsda PR ochgan edingiz — lekin u o'z repongizda edi. U yerda sizda yozish huquqi bor.

Endi tasavvur qiling: sizga yoqqan loyihada kichik xato ko'rdingiz. Odatdagi yo'l bilan boshlaysiz:

git push origin mening-tuzatishim remote: Permission to boshqa-odam/loyiha.git denied to Shamuratov098. fatal: unable to access ... 403

Va shu yerda to'xtaysiz. Chunki o'sha repo sizniki emas — hech kim begonaga o'z loyihasiga yozishga ruxsat bermaydi.

Yechim: fork

Fork — birovning repo'sidan o'z GitHub akkauntingizga to'liq nusxa olish. Nusxa sizniki, ya'ni unga bemalol push qilasiz. Keyin asl loyiha egasiga «mening nusxamdagi o'zgarishni oling» deb PR ochasiz.1

Yangi tushuncha: ikkita remote

Bu darsning yagona qiyin joyi shu — lekin tushunsangiz, qolgani oson. Endi sizda ikkita internetdagi manzil bo'ladi:

Bu yerda ishlaysiz

4-darsdan origin tanish — «asosiy manzil». Fork qilinganda esa u sizning nusxangizga ishora qiladi. Asl loyiha uchun ikkinchi nom qo'shiladi: upstream («yuqori oqim» — kelib chiqish joyi).

AmalQayerga boradi
git push origin — sizning forkingizga. Bu yerda to'liq huquqingiz bor.
Pull request Forkingizdan upstreamga — GitHub'da ochiladi. Bu «taklif», ya'ni egasi qaror qiladi.
git fetch upstream Asl loyihadagi yangiliklarni olib keladi. Fork o'zi yangilanmaydi — buni siz qilasiz.
Fork o'z-o'zidan yangilanmaydi

Bu ko'p odam adashadigan joy. Siz fork qilgan kundan boshlab asl loyiha oldinga ketaveradi, sizning nusxangiz esa o'sha kunda qotib qoladi.

Yangi ish boshlashdan oldin har safar yangilang (10-darsdagi «kun boshi pull»ning fork versiyasi):

git switch main && git fetch upstream && git merge upstream/main

To'liq oqim — olti qadam

  1. Fork — GitHub'da tugma bosasiz (bir marta);
  2. Clone — o'z forkingizni kompyuteringizga olasiz;
  3. upstream qo'shasiz — asl loyihaga ulanish (bir marta);
  4. Branch + ish + commit — tanish qism (6-dars);
  5. Push — o'z forkingizga;
  6. PR — forkingizdan asl loyihaga.

1–3-qadamlar har loyiha uchun bir marta. Keyingi hissalaringizda to'g'ridan-to'g'ri 4-qadamdan boshlaysiz.

Odob: hissa qo'shishning yozilmagan qoidalari

Texnikadan muhimroq qismi shu. Loyiha egalari sizni shu bo'yicha baholaydi:

  • Avval CONTRIBUTING.md ni o'qing. Ko'p loyihada u bor va unda «bizda qanday qilinadi» yozilgan. O'qimasdan PR ochish — hurmatsizlik belgisi.
  • Kichikdan boshlang. Birinchi PR'ingiz imlo xatosi tuzatishi bo'lsa — bu ajoyib. Katta o'zgarishni hech kim begonadan qabul qilmaydi.
  • Avval issue oching yoki mavjudini toping. «Men shuni tuzatsam bo'ladimi?» deb so'rash — bir necha kunlik behuda ishdan saqlaydi.
  • Bitta PR = bitta narsa. Xuddi commit kabi (2-dars).
  • Javobni sabr bilan kuting. Ko'p loyiha bepul, bo'sh vaqtda yuritiladi. Bir hafta — normal.
Birinchi ishni qayerdan topaman?

GitHub'da good first issue degan yorliq bor — u aynan yangi kelganlar uchun ajratilgan vazifalarni bildiradi. Qidiruvda: label:"good first issue" state:open. O'zingizga tanish til yoki ishlatadigan kutubxonangizdan boshlang.

Amaliyot: haqiqiy open source PR ochamiz

Bu mashq emas — haqiqiy hissa

Biz first-contributions loyihasidan foydalanamiz (github.com/firstcontributions/first-contributions) — 55 000 yulduz, 100 000 dan ortiq fork. U aynan shu maqsad uchun yaratilgan: yangi boshlovchilar birinchi PR'ini xotirjam mashq qilishi uchun. PR'ingiz haqiqatan ko'rib chiqiladi va qabul qilinadi.

Ya'ni bu darsdan keyin sizning GitHub profilingizda real open source hissangiz qoladi.

A qism — fork va sozlash

  1. Loyihani oching va fork qiling

    Fork tugmasi sahifaning yuqori o'ng burchagida.

    xdg-open https://github.com/firstcontributions/first-contributions

    Bajaring: yuqori o'ngdagi Fork → Create fork.
    Kutilgan natija: brauzer github.com/Shamuratov098/first-contributions ga o'tadi — endi bu sizning nusxangiz. 1-g'alaba. 🎉

  1. O'z forkingizni clone qiling

    Diqqat: manzilda sizning username'ingiz bo'lishi kerak, asl egasiniki emas.

    cd ~/Projects && git clone https://github.com/Shamuratov098/first-contributions.git && cd first-contributions

    Kutilgan natija: «Cloning into...» va papka yaratildi.

  2. Hozircha bitta remote borligini ko'ring

    git remote -v origin https://github.com/Shamuratov098/first-contributions.git (fetch) origin https://github.com/Shamuratov098/first-contributions.git (push)

    Kutilgan natija: faqat origin — va u sizning forkingiz. Asl loyiha hali ulanmagan.

  3. upstream qo'shing

    Asl loyihaga ulanish. Bu bir marta qilinadi. E'tibor bering: manzilda endi asl egasining nomi.

    git remote add upstream https://github.com/firstcontributions/first-contributions.git && git remote -v origin https://github.com/Shamuratov098/... (fetch) upstream https://github.com/firstcontributions/... (fetch)

    Kutilgan natija: endi to'rt qator — ikkita manzil, har biri fetch va push uchun. 2-g'alaba. 🎉

B qism — hissangizni qo'shing

  1. Branch oching

    Nom o'zingiznikiga o'zgartiring — bu odat.

    git switch -c ismimni-qoshish

    Kutilgan natija: «Switched to a new branch».

  2. Avval loyiha ko'rsatmasini o'qing

    Har doim shunday qiling — bu birinchi qoida edi.

    head -30 README.md

    Kutilgan natija: loyiha nima qilishni tushuntiradi — Contributors.md fayliga ismingizni qo'shish.

  3. Ismingizni qo'shing

    >> — oxiriga qo'shadi, boshqalarning ismini o'chirmaydi. Matnni o'zingiznikiga almashtiring.

    echo "- [Dostonbek Shamuratov](https://github.com/Shamuratov098)" >> Contributors.md && tail -3 Contributors.md

    Kutilgan natija: faylning oxirida sizning ismingiz. git diff bilan ham tekshiring — faqat bitta qator qo'shilgan bo'lishi kerak.

  4. Commit qiling

    Izoh aniq bo'lsin (11-dars).

    git add Contributors.md && git commit -m "Add Dostonbek Shamuratov to Contributors"

    Kutilgan natija: 1 file changed. Diqqat: xalqaro loyihada izohni inglizcha yozish odat.

  5. O'z forkingizga push qiling

    origin = sizning forkingiz. Bu yerda huquqingiz bor, shuning uchun ishlaydi.

    git push -u origin ismimni-qoshish * [new branch] ismimni-qoshish -> ismimni-qoshish

    Kutilgan natija: «[new branch]» va PR ochish uchun havola. 3-g'alaba. 🎉

C qism — PR oching

  1. Forkingizni brauzerda oching

    xdg-open https://github.com/Shamuratov098/first-contributions

    Kutilgan natija: sariq chiziq va Compare & pull request tugmasi.

  2. 🔑 PR yo'nalishini diqqat bilan tekshiring

    Bu darsdagi eng muhim tekshiruv. Odatdagi PR'dan farqi shu.

    Tugmani bosing va tepadagi qatorni o'qing:
    base repository: firstcontributions/first-contributions ← asl loyiha
    head repository: Shamuratov098/first-contributions ← sizning forkingiz
    Ya'ni: sizning forkingizdan asl loyihaga. GitHub buni odatda o'zi to'g'ri qo'yadi — lekin har doim tekshiring.

  3. Sarlavha va tavsif yozib, PR'ni oching

    Begona odam o'qiydi — shuning uchun aniq va xushmuomala.

    Yozing (inglizcha):
    Sarlavha: Add Dostonbek Shamuratov to Contributors
    Tavsif: Added my name to Contributors.md as part of the first contribution tutorial. Thank you!
    Keyin Create pull request.
    Kutilgan natija: PR ochildi va raqam berildi. 4-g'alaba — birinchi open source hissangiz! 🎉🎉

Endi nima bo'ladi?

Loyiha egalari PR'ingizni ko'rib chiqadi va qabul qiladi. Bu bir necha soatdan bir necha kungacha vaqt olishi mumkin — sabr qiling, eslatma yozmang. Merge qilinganda GitHub sizga xabar yuboradi.

Shundan keyin profilingizda «Contributed to firstcontributions/first-contributions» yozuvi paydo bo'ladi.

D qism — forkni yangilash (kelajak uchun)

  1. Asl loyihadagi yangiliklarni oling

    Keyingi safar hissa qo'shishdan oldin shuni qiling — aks holda eskirgan kod ustida ishlaysiz.

    git switch main && git fetch upstream && git merge upstream/main

    Kutilgan natija: «Fast-forward» yoki «Already up to date». Endi mahalliy main asl loyiha bilan bir xil.

  2. Forkingizni GitHub'da ham yangilang

    Mahalliy yangilandi — endi internetdagi nusxangizni ham.

    git push origin main

    Kutilgan natija: forkingiz asl loyiha bilan tenglashdi. 5-g'alaba. 🎉

Yodda tuting (checklist)

Amaliyotda haqiqiy open source PR ochasiz — first-contributions loyihasiga (u aynan boshlovchilar mashqi uchun yaratilgan, 100 000+ fork). Fork qilasiz, clone qilasiz, upstream qo'shasiz, ismingizni Contributors.md ga qo'shib PR ochasiz. Oxirida forkni yangilashni ham o'rganasiz. 12 qadam.

Tekshirib ko'ramiz (quiz)

SAVOL 1 Nega birovning loyihasida fork kerak?

To'g'ri. Yozish huquqi bo'lsa (masalan o'z jamoangiz repo'sida) fork kerak emas — to'g'ridan-to'g'ri branch ochasiz (9-dars).

SAVOL 2 Fork qilingandan keyin origin nimaga ishora qiladi?

To'g'ri — siz o'z forkingizni clone qilgansiz, shuning uchun origin o'shanga ishora qiladi. Asl loyiha esa upstream nomi bilan qo'lda qo'shiladi.

SAVOL 3 Fork qilganingizdan bir oy o'tdi. Nusxangiz o'zi yangilandimi?

To'g'ri, va bu ko'p adashiladigan joy. Yangilash sizning ishingiz: git fetch upstream → git merge upstream/main.

SAVOL 4 Birinchi hissangiz qanday bo'lgani ma'qul?

To'g'ri. Kichik PR tez ko'riladi va qabul qilinadi. Katta o'zgarishni begonadan hech kim qabul qilmaydi — avval ishonch qozoniladi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring.

Fork nima — bir jumlada?

Birovning repo'sidan o'z GitHub akkauntingizga to'liq nusxa olish. Nusxa sizniki, shuning uchun unga push qila olasiz.

origin va upstream — qaysi biri kimniki?

origin = sizning forkingiz (push qilasiz) · upstream = asl loyiha (faqat o'qiysiz).

PR qaysi yo'nalishda ochiladi?

Sizning forkingizdagi branchdan asl loyihaning mainiga. GitHub'da: base = asl loyiha, head = sizning forkingiz.

Forkni qanday yangilaysiz?

git fetch upstream → git merge upstream/main → git push origin main. Fork o'zi yangilanmaydi.

PR ochishdan oldin qaysi faylni o'qiysiz?

CONTRIBUTING.md — loyihaning o'z qoidalari. Bo'lmasa, README.md.

↩︎ Takrorlash: o'z jamoangiz repo'sida fork kerakmi?

Yo'q — u yerda yozish huquqingiz bor, to'g'ridan-to'g'ri branch ochasiz. (Dars 09)

Cho'ntak xulosasi
  • Fork = birovning repo'sidan o'z akkauntingizga nusxa. Yozish huquqi yo'q joyda ishlash uchun.
  • Ikki remote: origin = mening forkim (push) · upstream = asl loyiha (faqat o'qish).
  • Bir marta: git remote add upstream <asl-url>
  • Oqim: fork → clone → upstream qo'sh → branch + commit → push origin → PR.
  • PR yo'nalishi: mening forkimdan asl loyihaga. Har doim tekshiring.
  • ⚠️ Fork o'zi yangilanmaydi: fetch upstream → merge upstream/main.
  • Odob: CONTRIBUTING.md ni o'qing · kichikdan boshlang · bitta PR = bitta narsa · sabr qiling.
