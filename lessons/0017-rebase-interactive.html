DARS 17 · QO'SHIMCHA · KURSDAN KEYIN

rebase -i: commitlarni birlashtirish va tozalash

Bu darsdan keyin siz PR ochishdan oldin chalkash commitlaringizni tartibga solasiz — bir nechtasini bittaga birlashtirasiz, izohlarni tuzatasiz, keraksizini olib tashlaysiz.

📱 O'qish ≈ 9 daqiqa 💻 Amaliyot ≈ 15 daqiqa Kerak: Dars 13

Tanish holat

Ish ustida ishlayapsiz va yo'l-yo'lakay commit qilib borasiz — bu to'g'ri odat. Lekin PR ochish payti kelganda tarixingiz shunday ko'rinadi:

git log --oneline main..login e32ba17 yana bir tuzatish ee121b6 typo tuzatildi 3742500 wip eb7f337 Login formasi qo'shildi

Ko'rib chiquvchi uchun bu shovqin: to'rt commitning uchtasi hech narsa aytmaydi. Aslida bu bitta ish edi — bitta commit bo'lishi kerak.

Uch yo'l — eng osonidan boshlaymiz

1. GitHub tugmasi — ko'pincha shuning o'zi yetarli

PR merge qilishda GitHub uchta variant taklif qiladi. Ulardan biri — Squash and merge. U butun PR'ni bitta commitga birlashtirib mainga qo'shadi.1

Avval shuni sinang

Hech qanday buyruq yo'q, xavf yo'q, tarixni qayta yozish yo'q. Ko'p jamoada aynan shu ishlatiladi — chalkash commitlaringiz sizning branch'ingizda qoladi, mainga esa toza bitta commit tushadi.

Agar jamoangizda shu tartib bo'lsa — bu darsning qolgani sizga kerak emas. Lekin bilib qo'ygan yaxshi.

2. reset --soft — tahrirlagichsiz, oddiy

Butun branch'ni bitta commitga siqmoqchi bo'lsangiz, eng sodda yo'l:

git reset --soft main
git commit -m "Login formasi qo'shildi"

Nima bo'ldi? --soft — yumshoq: u branch yorlig'ini mainga qaytaradi, lekin hamma o'zgarishlaringizni saqlab qoladi (ular saralash joyida turadi). Keyin bitta yangi commit qilasiz.

--soft va --hard farqi

10-darsda reset --hard ni ko'rgandik — u hamma narsani o'chiradi. --soft esa faqat yorliqni ko'chiradi, fayllaringizga tegmaydi. Shuning uchun u ancha xavfsiz.

3. rebase -i — to'liq nazorat

Hammasini bittaga siqish emas, balki tanlab ishlash kerak bo'lsa: ikkitasini birlashtirib, uchinchisining izohini tuzatib, to'rtinchisini o'chirish. Mana shunda interaktiv rebase kerak.

git rebase -i main

Bu buyruq matn tahrirlagichini ochadi va sizga reja ko'rsatadi.

Todo ro'yxatini o'qish

Tahrirlagichda shunday ko'rasiz (yuqoridagi to'rtta commit uchun):

rebase todo ro'yxati
pick eb7f337 Login formasi qo'shildieng eski
pick 3742500 wip
pick ee121b6 typo tuzatildi
pick e32ba17 yana bir tuzatisheng yangi
# Commands:
# p, pick = use commit
# r, reword = use commit, but edit the commit message
# s, squash = use commit, but meld into previous commit
# f, fixup = like squash but keep only the previous commit's message
# d, drop = remove commit

Git yo'riqnomani faylning o'zida beradi (# bilan boshlangan qatorlar — izoh, ular bajarilmaydi). Sizning ishingiz: chap tomondagi pick so'zini kerakli buyruqqa almashtirish.

BuyruqNima qiladi
pick Commitni o'z holicha qoldirish (standart).
squash (s) Yuqoridagi commitga qo'shib yuborish. Izohlar birlashtiriladi va tahrirlagich ochilib, yakuniy izohni yozasiz.
fixup (f) Xuddi squash, lekin bu commitning izohi tashlab yuboriladi. «wip» kabi keraksiz izohlar uchun eng qulayi.
reword (r) Commitni qoldirib, faqat izohini tuzatish.
drop (d) Commitni butunlay o'chirish. Qatorni o'chirib tashlash ham xuddi shu ta'sirni beradi.

Bizning misolda

To'rt qatorni shunday o'zgartiramiz:

tahrirlangan todo ro'yxati
pick eb7f337 Login formasi qo'shildiqoladi
fixup 3742500 wipyuqoriga qo'shiladi
fixup ee121b6 typo tuzatildiyuqoriga qo'shiladi
fixup e32ba17 yana bir tuzatishyuqoriga qo'shiladi

Saqlab chiqasiz — va to'rtta commit bittaga aylanadi, izohi esa «Login formasi qo'shildi» bo'lib qoladi.

Ikkita tuzoq

1. Tartib teskari — eng eski YUQORIDA

git log da eng yangi commit yuqorida turadi. Todo ro'yxatida esa aksincha: yuqorida eng eski, pastda eng yangi.

Sabab mantiqiy: Git ularni yuqoridan pastga bajarib chiqadi, ya'ni eskisidan boshlaydi.

2. Birinchi qator pick bo'lib qolsin

squash va fixup — «yuqoridagiga qo'shib yubor» degani. Birinchi qatorning esa yuqorisida hech narsa yo'q. Uni o'zgartirsangiz:

git rebase -i main error: cannot 'squash' without a previous commit

Chiqish yo'li: git rebase --abort, keyin qaytadan.

🔴 Oltin qoida — o'zgarmadi

13-darsdagi qoida bu yerda ham amal qiladi: push qilingan commitlarni qayta yozmang. Interaktiv rebase ham yangi commitlar yaratadi.

Xavfsiz shakl: PR ochishdan oldin, o'z branch'ingiz hali hech kimga ko'rinmagan paytda tozalang.

Amaliyot: chalkash tarixni tozalaymiz

Mashq nusxa papkada, push yo'q.

Avval tahrirlagichni sozlang

rebase -i tahrirlagich ochadi. Sozlanmagan bo'lsa vim ochilishi mumkin — u boshlovchi uchun qiyin. Bir martalik yechim (nano kompyuteringizda bor):

git config --global core.editor nano

nano'da ishlash: o'q tugmalari bilan yurasiz, matnni oddiy yozasiz. Saqlash va chiqish: Ctrl+O → Enter → Ctrl+X. Bekor qilish: Ctrl+X (o'zgartirmasdan).

A qism — reset --soft bilan (tahrirlagichsiz)

  1. Chalkash tarix yarating

    Ataylab yomon izohlar bilan — haqiqiy ishdagidek.

    cd ~/Projects/Learn/Git-nusxa && git switch main && git switch -c ri-login && for m in "Login formasi qo'shildi" "wip" "typo" "yana tuzatish"; do echo "$m" >> ri-login.txt; git add ri-login.txt; git commit -q -m "$m"; done && git log --oneline main..ri-login

    Kutilgan natija: to'rtta commit — uchtasi ma'nosiz izoh bilan.

  2. Bitta commitga siqing

    --soft — yorliqni qaytaradi, fayllarni saqlab qoladi.

    git reset --soft main && git status --short A ri-login.txt

    Kutilgan natija: A — fayl saralash joyida turibdi, ya'ni ish yo'qolmadi. git log --oneline main..ri-login deng — bo'sh (commitlar olib tashlandi).

  3. Bitta toza commit qiling

    git commit -m "Login formasi qo'shildi" && git log --oneline main..ri-login

    Kutilgan natija: bitta commit. cat ri-login.txt deng — to'rtala qator ham joyida. 1-g'alaba. 🎉

B qism — rebase -i bilan (tanlab)

  1. Yangi chalkash tarix yarating

    git switch main && git switch -c ri-profil && for m in "Profil sahifasi qo'shildi" "wip" "kichik tuzatish"; do echo "$m" >> ri-profil.txt; git add ri-profil.txt; git commit -q -m "$m"; done && git log --oneline main..ri-profil

    Kutilgan natija: uchta commit.

  2. Interaktiv rebase'ni boshlang

    nano ochiladi — vahima qilmang, quyida nima qilishni aytaman.

    git rebase -i main

    Kutilgan natija: nano ochiladi va uchta pick qatorini ko'rasiz. Yuqorida eng eski («Profil sahifasi qo'shildi»).

  3. 🔑 2 va 3-qatorlarni fixup ga o'zgartiring

    Birinchi qator tegilmaydi — u asos.

    nano'da bajaring:
    1. O'q tugmalari bilan ikkinchi qator boshiga boring
    2. pick so'zini o'chirib (Delete 4 marta), o'rniga fixup yozing
    3. Uchinchi qatorda ham shunday
    4. Saqlang: Ctrl+O → Enter → Ctrl+X

    natijada shunday bo'lishi kerak
    pick abc1234 Profil sahifasi qo'shildi
    fixup def5678 wip
    fixup ghi9012 kichik tuzatish

  4. Natijani ko'ring

    git log --oneline main..ri-profil && cat ri-profil.txt 4bc62ec Profil sahifasi qo'shildi

    Kutilgan natija: uchta commit bittaga aylandi, izohi toza, faylda esa uchala qator ham bor. 2-g'alaba. 🎉

  5. Adashsangiz — chiqish yo'li

    Bu buyruqni bilib qo'ying: rebase o'rtasida chalkashsangiz yoki xato chiqsa, shu sizni qutqaradi.

    git rebase --abort

    Eslatma: rebase allaqachon tugagan bo'lsa bu buyruq «no rebase in progress» deydi — bu normal. Tugagandan keyin qaytarish uchun git reflog ishlatiladi.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda ataylab chalkash tarix yaratasiz («wip», «typo») va uni ikki xil usulda tozalaysiz: A — reset --soft bilan (tahrirlagichsiz, hammasi bittaga), B — rebase -i bilan (nano'da pick → fixup). 8 qadam, nusxa papkada.

Tekshirib ko'ramiz (quiz)

SAVOL 1 Todo ro'yxatida qaysi commit yuqorida turadi?

To'g'ri — git log ning aksi. Sabab mantiqiy: Git rejani yuqoridan boshlab bajaradi, ya'ni eskisidan.

SAVOL 2 squash va fixup farqi nimada?

To'g'ri. Ikkalasi ham o'zgarishni yuqoridagi commitga qo'shadi; farq izohda. «wip» kabi keraksiz izohlar uchun fixup qulayroq.

SAVOL 3 Birinchi qatorni squash qilsangiz nima bo'ladi?

To'g'ri. squash = «yuqoridagiga qo'sh», birinchi qatorning esa yuqorisida hech narsa yo'q. Chiqish: git rebase --abort.

SAVOL 4 Butun branch'ni bitta commitga siqmoqchisiz. Eng oson yo'l?

To'g'ri — tahrirlagich ochilmaydi, ish yo'qolmaydi. ⚠️ --hard esa hamma narsani o'chiradi — bu yerda ishlatilmaydi.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring.

Commitlarni tozalashning uch yo'li?

1. GitHub'ning Squash and merge tugmasi (eng oson) · 2. git reset --soft main + bitta commit · 3. git rebase -i main (to'liq nazorat).

Todo ro'yxatidagi to'rt asosiy buyruq?

pick (qoldir) · squash (yuqoridagiga qo'sh, izohlar birlashadi) · fixup (qo'sh, izohni tashla) · reword (faqat izohni tuzat). Yana drop — o'chirish.

Ikkita tuzoq qaysilar?

1. Tartib teskari — eng eski yuqorida · 2. Birinchi qator pick bo'lib qolishi kerak.

reset --soft va reset --hard farqi?

--soft faqat yorliqni ko'chiradi, o'zgarishlaringiz saralash joyida qoladi. --hard esa hamma narsani o'chiradi.

↩︎ Takrorlash: rebase'ning oltin qoidasi?

Push qilingan commitlarni qayta yozmang. Interaktiv rebase ham yangi commitlar yaratadi. (Dars 13)

Cho'ntak xulosasi
  • Eng oson: GitHub'da Squash and merge — buyruqsiz, xavfsiz.
  • Hammasi bittaga: git reset --soft main → git commit -m "...".
  • Tanlab: git rebase -i main → todo ro'yxatini tahrirlash.
  • Buyruqlar: pick · squash · fixup · reword · drop.
  • ⚠️ Tartib teskari: eng eski yuqorida.
  • ⚠️ Birinchi qator pick bo'lib qolsin.
  • 🔴 Push qilingandan keyin qayta yozmang — PR'dan oldin tozalang.
  • Chiqish: git rebase --abort · tugagandan keyin — git reflog.
