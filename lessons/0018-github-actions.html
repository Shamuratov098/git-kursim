GitHub Actions: PR'dagi yashil va qizil belgilar

Bu darsdan keyin siz PR'dagi ✓ va ✗ belgilar nima ekanini bilasiz — va o'z repongizga ishlaydigan avtomatik tekshiruv qo'shasiz.

📱 O'qish ≈ 8 daqiqa 💻 Amaliyot ≈ 18 daqiqa Kerak: Dars 09

Ochilmagan savol

9-darsda PR sahifasining to'rt bo'limini ko'rgandik va Checks haqida shunday deb qo'ygandim: «avtomatik testlar — kursimizda yo'q, ish joyingizda ehtimol bo'ladi».

Mana shu dars o'sha bo'limni ochadi. Ish joyingizda PR ochganingizda pastda yashil ✓ yoki qizil ✗ chiqadi — nima ekanini bilishingiz kerak.

CI nima — bir jumlada

Asosiy g'oya

Har safar kod jo'natilganda, robot uni tekshirib chiqadi. Testlar ishlaydimi? Kod uslubi to'g'rimi? Loyiha yig'iladimi? Javob — PR sahifasida yashil yoki qizil belgi bo'lib chiqadi.

Buni CI deyishadi — continuous integration, «uzluksiz birlashtirish». GitHub'dagi vositasi esa GitHub Actions.1

Nega jamoalar buni ishlatadi:

  • Buzuq kod mainga yetib bormaydi. Test yiqilsa, PR qizil bo'ladi va merge tugmasi ogohlantirish beradi.
  • «Menda ishlayapti-ku» tugaydi. Robot har doim toza muhitda tekshiradi.
  • Ko'rib chiquvchi vaqti tejaladi. Mayda narsalarni robot topadi, odam esa mantiqqa qaraydi.

Workflow fayli qayerda turadi

GitHub bitta aniq joyga qaraydi:

.github/workflows/tekshiruv.yml

Shu papkadagi har bir .yml fayl — bitta workflow, ya'ni «qachon nima qilinsin» degan reja. Papka nomi aynan shunday bo'lishi shart, aks holda GitHub uni ko'rmaydi.

YAML haqida qisqacha

.yml — sozlama fayllari formati. Uning yagona qat'iy qoidasi: bo'sh joylar (indent) muhim. Tab emas, probel ishlatiladi va har daraja odatda 2 probel. Nusxa olganingizda bo'sh joylarni buzmang.

Workflow tuzilishi

Mana amaliyotda yozadigan faylimiz — atigi 9 qator:

.github/workflows/tekshiruv.yml
name: Tekshiruvnomi
on: [push, pull_request]qachon
jobs:
kirill:ish nomi
runs-on: ubuntu-latestqayerda
steps:
- uses: actions/checkout@v4tayyor amal
- run: python3 .github/tekshir.pyo'z buyrug'im
KalitMa'nosi
name Workflow nomi — GitHub'da shu ko'rinadi.
on Qachon ishga tushsin. push — har jo'natishda, pull_request — har PR'da.
jobs Bajariladigan ishlar ro'yxati. Bitta yoki bir nechta bo'lishi mumkin.
runs-on Qayerda ishlasin. ubuntu-latest — GitHub bepul beradigan toza Linux mashinasi. Har safar noldan yaratiladi — ya'ni «menda ishlayapti» bahonasi yo'q.
steps Ketma-ket bajariladigan qadamlar.
uses: Tayyor amal ishlatish. actions/checkout@v4 — kodingizni o'sha mashinaga yuklaydi. Deyarli har workflow shundan boshlanadi.
run: O'z buyrug'ingiz — terminalda yozgandek.
YAML'ni yupqa saqlang

Mantiqni YAML ichiga tiqishtirmang — alohida skriptga chiqaring (bizda: .github/tekshir.py). Sabab: YAML'da indent xatosi juda oson bo'ladi, skriptni esa kompyuteringizda ham sinab ko'ra olasiz.

Robot qanday «yiqiladi»

Bu — CI'ning yuragi va juda sodda qoida:

Chiqish kodi

Har bir buyruq tugaganda raqam qaytaradi. 0 — hammasi yaxshi. Noldan farqli har qanday raqam — xato.

Qadam xato qaytarsa, workflow to'xtaydi va PR'da qizil ✗ chiqadi.

Shuning uchun bizning skriptimiz oxirida shunday yozilgan:

sys.exit(1 if xato else 0)

Ya'ni: xato topilsa 1 qaytar (robot yiqilsin), toza bo'lsa 0.

Natijani o'qish

Public repo uchun bepul

GitHub Actions ochiq repolarda cheklovsiz bepul. Sizning kurs repongiz public, ya'ni hech qanday xarajat yo'q.2

Amaliyot: repongizga haqiqiy tekshiruv qo'shamiz

Bu foydali ish — o'yinchoq emas

Biz men har dars yozgandan keyin qo'lda bajaradigan tekshiruvni avtomatlashtiramiz: darslarda lotin harflari orasiga kirill harfi tushib qolmaganini tekshirish. Bu haqiqiy muammo edi — 2-darsda 8 joyda uchragan.

Bundan keyin robot buni siz uchun har push'da tekshiradi.

Ishni kundalik ritm bo'yicha qilamiz — ya'ni branch va PR bilan.

A qism — workflow yaratish

  1. Toza holatdan boshlang

    cd ~/Projects/Learn/Git && git switch main && git pull && git switch -c actions-qoshish

    Kutilgan natija: yangi branch.

  2. Papkani yarating

    Nomi aynan shunday bo'lishi shart — GitHub shu joyga qaraydi.

    mkdir -p .github/workflows && ls -a .github

    Kutilgan natija: workflows papkasi ko'rinadi.

  3. Tekshiruv skriptini yozing

    8 qator. Mantiq shu yerda — YAML'da emas.

    cat > .github/tekshir.py << "EOF" import re, glob, pathlib, sys ... (8 qator — Copy tugmasida to'liq) EOF

    Kutilgan natija: jimlik. Agar terminal > bilan kutib qolsa: EOF deb yozib Enter bosing.

  4. Skriptni kompyuteringizda sinab ko'ring

    Muhim odat: GitHub'ga jo'natishdan oldin mahalliy sinang. Aks holda har tuzatish uchun push qilib kutasiz.

    python3 .github/tekshir.py; echo "chiqish kodi: $?" Hammasi toza chiqish kodi: 0

    Kutilgan natija: «Hammasi toza» va chiqish kodi 0. 1-g'alaba. 🎉

  5. Workflow faylini yozing

    9 qator YAML. Bo'sh joylarni buzmang — Copy tugmasidan foydalaning.

    cat > .github/workflows/tekshiruv.yml << "EOF" name: Tekshiruv ... (9 qator — Copy tugmasida to'liq) EOF

    Kutilgan natija: jimlik. cat .github/workflows/tekshiruv.yml bilan tekshiring.

  6. Commit qilib, forkga emas — o'z repongizga push qiling

    git add .github && git commit -m "Kirill harflarini tekshiruvchi workflow qo'shildi" && git push -u origin actions-qoshish

    Kutilgan natija: 2 files changed va «[new branch]».

B qism — robotni ishda ko'ring

  1. PR oching

    xdg-open https://github.com/Shamuratov098/git-kursim

    Bajaring: Compare & pull request → Create pull request.

  2. 🤖 Robotni kuzating

    Mana o'sha 9-darsda ochilmagan qism.

    Kutilgan natija: PR sahifasining pastida Tekshiruv nomli qator paydo bo'ladi. Avval 🟡 sariq (ishlayapti), keyin 20–40 soniyada ✅ yashil. 2-g'alaba — birinchi CI'ingiz ishladi! 🎉

  3. Logni ochib ko'ring

    Robot nima qilganini o'z ko'zingiz bilan ko'rasiz.

    Bajaring: Details ni bosing → qadamlar ro'yxati ochiladi → Run python3 .github/tekshir.py qatorini bosing.
    Kutilgan natija: «Hammasi toza» — sizning skriptingizning chiqishi, GitHub serverida ishlagan.

C qism — ataylab buzib, qizil belgini ko'ring

  1. Kirill harfi qo'shing

    Aynan robot topishi kerak bo'lgan xato.

    echo "<!-- тест -->" >> index.html && python3 .github/tekshir.py; echo "chiqish kodi: $?" XATO index.html:122 — kirill harfi 1 ta xato topildi chiqish kodi: 1

    Kutilgan natija: xato topildi va chiqish kodi 1 — ya'ni robot ham yiqiladi.

  2. Push qiling va qizil belgini ko'ring

    git commit -am "Ataylab xato (CI sinovi)" && git push

    Kutilgan natija: PR sahifasida bir necha soniyadan keyin ❌ qizil belgi. Details ni oching — logda aynan qaysi fayl va qaysi qator ekani yozilgan. 3-g'alaba — robot xatoni tutdi! 🎉

  3. Tuzatib, yashilga qaytaring

    sed oxirgi qatorni o'chiradi. Yoki faylni muharrirda ochib qo'lda o'chiring.

    sed -i "$ d" index.html && python3 .github/tekshir.py && git commit -am "Ataylab qilingan xato tuzatildi" && git push

    Kutilgan natija: «Hammasi toza», keyin push. PR'da belgi yana ✅ yashil bo'ladi. 4-g'alaba. 🎉

  4. PR'ni merge qilib, aylanani yoping

    Endi har push'da robot ishlaydi — men uchun ham, siz uchun ham.

    git switch main && git pull && git branch -d actions-qoshish

    Avval GitHub'da: Merge pull request → Delete branch. Keyin yuqoridagi buyruq.
    Kutilgan natija: workflow endi mainda.

Tekshirib ko'ramiz (quiz)

SAVOL 1 Workflow fayli qayerda turishi kerak?

To'g'ri. GitHub aynan shu papkaga qaraydi. Nomi noto'g'ri bo'lsa, workflow umuman ishga tushmaydi — va hech qanday xato ham chiqmaydi.

SAVOL 2 Robot qachon «yiqiladi» (qizil bo'ladi)?

To'g'ri — qoida shunchaki: 0 = yaxshi, boshqa har qanday raqam = xato. Shuning uchun skriptimizda sys.exit(1) yozilgan.

SAVOL 3 uses va run farqi?

To'g'ri. actions/checkout@v4 — boshqalar yozgan tayyor amal (kodni yuklaydi). run esa terminalda yozgandek o'z buyruq'ingiz.

SAVOL 4 PR qizil bo'ldi. Birinchi nima qilasiz?

To'g'ri. Qizil belgi — ma'lumot, jazo emas. Sabab deyarli har doim log'ning oxirida yozilgan bo'ladi.

Eslab ayting (o'zingizni sinang)

CI nima — bir jumlada?

Har safar kod jo'natilganda robot uni tekshirib chiqadi — testlar, uslub, yig'ilish. Natija PR'da yashil yoki qizil belgi bo'lib chiqadi.

Workflow faylining to'rt asosiy kaliti?

on (qachon) · jobs (nima ishlar) · runs-on (qaysi mashinada) · steps (qadamlar).

Robot qanday «yiqiladi»?

Qadam noldan farqli chiqish kodi qaytarsa. 0 = hammasi yaxshi, boshqasi = xato.

Nega mantiqni YAML'ga emas, skriptga yozamiz?

YAML'da indent xatosi oson bo'ladi, va skriptni kompyuteringizda sinab ko'ra olasiz — har tuzatish uchun push qilib kutmaysiz.

↩︎ Takrorlash: PR sahifasining to'rt bo'limi?

Conversation · Commits · Files changed (review shu yerda) · Checks (mana shu dars). (Dars 09)

Cho'ntak xulosasi
  • CI = har push'da robot kodni tekshiradi. GitHub'da: Actions.
  • Joyi: .github/workflows/*.yml — nomi aynan shunday bo'lsin.
  • Kalitlar: on (qachon) · jobs · runs-on (qaysi mashina) · steps.
  • uses: = tayyor amal (actions/checkout@v4) · run: = o'z buyrug'ingiz.
  • Chiqish kodi: 0 = ✅ · noldan farqli = ❌.
  • Mantiqni alohida skriptga chiqaring — mahalliy sinash uchun.
  • Qizil bo'lsa: Details → log'ning oxiri.
  • Public repolarda bepul.
