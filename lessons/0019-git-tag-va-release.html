Nega bu kerak

Ish joyida muqarrar savollar tug'iladi: «serverda qaysi versiya turibdi?», «o'tgan haftagi ishlaydigan holatga qaytaraylik», «mijozga qaysi versiyani berdik?»

Commit hash (a1b2c3d) bu savollarga javob bera olmaydi — uni hech kim eslay olmaydi. v1.4.2 esa aytadi.

Tag nima — branch bilan taqqoslab

6-darsda branch — ko'chib yuruvchi yorliq deb o'rgangandik. Tag esa uning aksi:

branchtag

Bir jumlada

Branch — harakatlanadigan yorliq, tag — doimiy yorliq. Tag qo'yilgan commit hech qachon «adashib qolmaydi»: bir yildan keyin ham v1.0.0 deb o'sha nuqtani topasiz.

Versiya raqami qanday o'qiladi

Eng keng tarqalgan tartib — semantik versiyalash (semver): vMAJOR.MINOR.PATCH1

Ya'ni v1.2.5 dan v2.0.0 ga o'tish — ehtiyot bo'lish kerak degan ogohlantirish. Bu shunchaki raqam emas, xabar.

Ikki xil tag — biri yetarli

TuriQachon
Annotated

Qoida sodda

Boshqalar ko'radigan har qanday tag — annotated (-a) bo'lsin. Farqni eslab qolish qiyin bo'lsa: shunchaki har doim -a -m yozing.

⚠️ Eng katta tuzoq: teglar push qilinmaydi

Oddiy git push teglarni jo'natmaydi

Tag yaratib, git push qilsangiz — tag kompyuteringizda qoladi. GitHub'da hech narsa ko'rinmaydi va hech qanday xato ham chiqmaydi.

Tegni alohida jo'natasiz:

git push origin v1.0.0

Yoki hammasini birdan: git push --tags.

git push origin --delete v1.0.0 GitHub'dagisini ham o'chiradi. Ikkalasi alohida — bu ham tuzoq.
git switch --detach v1.0.0 O'sha versiyaning kodini ko'rish uchun vaqtincha o'tish. Qaytish: git switch main

GitHub Release — tegning ko'rinadigan yuzi

Tag GitHub'ga yetib borgach, undan Release yasash mumkin. Release — bu tegning ustiga qurilgan sahifa:2

  • Izoh (release notes) — bu versiyada nima o'zgargani;
  • Avtomatik arxiv — GitHub o'zi .zip va .tar.gz yaratib qo'yadi;
  • Doimiy havola — «bizga v1.2.0 ni bering» deyish oson.
Tag ≠ Release

Tag — Git tushunchasi, kompyuteringizda ham bor. Release — GitHub tushunchasi, tegning ustiga qo'shiladi. Xuddi PR kabi: Git buyrug'i emas, sayt imkoniyati.

Amaliyot: kursingizni v1.0.0 qilib chiqaramiz

Bu munosib payt

Kursingizda endi 19 ta dars bor: 11 asosiy + 8 qo'shimcha. README yozilgan, CI ishlab turibdi. Bu — haqiqiy v1.0.0.

A qism — tag qo'yish

  1. Toza va yangi holatda ekaningizni tekshiring

    Tag hozirgi commitga qo'yiladi — shuning uchun avval to'g'ri joyda turganingizga ishonch hosil qiling.

    cd ~/Projects/Learn/Git && git switch main && git pull && git log --oneline -1

    Kutilgan natija: «Already up to date» va oxirgi commit ko'rinadi. Shu commit v1.0.0 bo'ladi.

  2. Annotated tag qo'ying

    -a = annotated, -m = izoh. Izoh bu versiyada nima borligini aytsin.

    git tag -a v1.0.0 -m "Birinchi to'liq versiya: 11 asosiy + 8 qo'shimcha dars, README va CI"

    Kutilgan natija: jimlik (= muvaffaqiyat).

  3. Tekshiring

    git tag && git show v1.0.0 | head -6 v1.0.0 tag v1.0.0 Tagger: dostonbek <...> Birinchi to'liq versiya: ...

    Kutilgan natija: tag nomi, kim qo'ygani, sanasi va izohi. Chiqish: q. 1-g'alaba. 🎉

  4. 🪤 Tuzoqni o'z ko'zingiz bilan ko'ring

    Oddiy push teglarni olib ketmasligini isbotlaymiz.

    git push && git ls-remote --tags origin

    Kutilgan natija: «Everything up-to-date» va ls-remote chiqishi bo'sh — ya'ni GitHub'da tag yo'q. Mana o'sha tuzoq.

  5. Endi tegni alohida jo'nating

    git push origin v1.0.0 && git ls-remote --tags origin * [new tag] v1.0.0 -> v1.0.0 ... refs/tags/v1.0.0

    Kutilgan natija: «[new tag]» va endi ls-remote tegni ko'rsatadi. 2-g'alaba. 🎉

B qism — GitHub'da Release yasash

  1. Relizlar sahifasini oching

    xdg-open https://github.com/Shamuratov098/git-kursim/releases/new

    Kutilgan natija: yangi reliz yaratish sahifasi.

  2. Tegni tanlang va reliz yozing

    Tag allaqachon GitHub'da — shunchaki tanlaysiz.

    Bajaring:
    1. Choose a tag → ro'yxatdan v1.0.0 ni tanlang
    2. Sarlavha: v1.0.0 — birinchi to'liq versiya
    3. Tavsifga nima borligini yozing, masalan:
    - 11 ta asosiy dars (Git asoslaridan pull request'gacha)
    - 8 ta qo'shimcha dars (stash, rebase, reflog, cherry-pick...)
    - Ikki rejim: telefonda o'qish, kompyuterda amaliyot
    4. Publish release

  3. Natijani ko'ring

    Endi loyihangizda rasmiy versiya bor.

    Kutilgan natija: reliz sahifasi ochiladi va pastda GitHub o'zi yaratgan Source code (zip) va (tar.gz) havolalari turadi. Repo bosh sahifasining o'ng tomonida ham Releases bo'limi paydo bo'ladi. 3-g'alaba. 🎉🎉

C qism — eski versiyaga qarash

  1. Tag'dagi kodni ko'rish

    «O'sha versiyada nima bor edi?» degan savolga javob. --detach — «vaqtincha qarayman, ishlamayman» degani.

    git switch --detach v1.0.0 && git log --oneline -1

    Kutilgan natija: Git ogohlantiradi («detached HEAD») — bu normal, siz shunchaki tarixning bir nuqtasiga qarab turibsiz.

  2. Ishga qayting

    Bu qadamni unutmang — aks holda «detached» holatda qolib ketasiz.

    git switch main && git status -sb | head -1

    Kutilgan natija: ## main...origin/main — odatdagi holatga qaytdingiz. 4-g'alaba. 🎉

Tekshirib ko'ramiz (quiz)

SAVOL 1 Tag va branch farqi nimada?

To'g'ri. Branch — «bu yerda ishlayapman» (siljiydi), tag — «bu muhim nuqta edi» (qotib qoladi).

SAVOL 2 Tag yaratib git push qildingiz. GitHub'da tag bormi?

To'g'ri, va bu eng katta tuzoq: Git xato ham bermaydi. git push origin v1.0.0 yoki git push --tags kerak.

SAVOL 3 Kodda buzuvchi o'zgarish qildingiz. Qaysi raqam oshadi?

To'g'ri. MAJOR oshishi — «ehtiyot bo'ling, eski kod ishlamasligi mumkin» degan xabar.

SAVOL 4 Reliz uchun qaysi turdagi tag ishlatiladi?

To'g'ri. Boshqalar ko'radigan har qanday tag — annotated bo'lsin. Oson qoida: har doim -a -m yozing.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring.

Tag va branch — bir jumlada farqi?

Branch — harakatlanadigan yorliq («bu yerda ishlayapman»), tag — doimiy yorliq («bu muhim nuqta edi»).

v2.3.1 — har bir raqam nimani bildiradi?

2 = MAJOR (buzuvchi o'zgarish) · 3 = MINOR (yangi imkoniyat) · 1 = PATCH (xato tuzatildi).

Eng katta tuzoq nima edi?

git push teglarni jo'natmaydi va xato ham bermaydi. git push origin v1.0.0 yoki git push --tags kerak.

Tag va Release farqi?

Tag — Git tushunchasi (kompyuteringizda ham bor). Release — GitHub sahifasi: izoh, avtomatik zip arxivi, doimiy havola. Xuddi PR kabi — sayt imkoniyati.

Cho'ntak xulosasi
  • Tag = doimiy yorliq (branch esa siljiydi).
  • semver: vMAJOR.MINOR.PATCH — buzuvchi / yangi / tuzatish.
  • Relizlar uchun annotated: git tag -a v1.0.0 -m "izoh".
  • ⚠️ git push teglarni jo'natmaydi → git push origin v1.0.0 (yoki --tags).
  • O'chirish ham ikki joyda: git tag -d + git push origin --delete v1.0.0.
  • Ko'rish: git tag · git show v1.0.0 · git switch --detach v1.0.0 (qaytish: git switch main).
  • Release — GitHub'da tegning ustiga qurilgan sahifa: izoh + avtomatik zip.
