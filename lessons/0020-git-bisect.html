DARS 20 · QO'SHIMCHA · KURSDAN KEYIN

git bisect: xatoni kiritgan commitni topish

Bu darsdan keyin siz «o'tgan hafta ishlayotgan edi, endi buzuq» degan holatda aynan qaysi commit aybdor ekanini bir necha daqiqada topasiz — yuzlab commit bo'lsa ham.

📱 O'qish ≈ 7 daqiqa 💻 Amaliyot ≈ 14 daqiqa Kerak: Dars 02, 18

Tanish holat

Dushanba kuni dastur ishlayotgan edi. Juma kuni mijoz «ishlamayapti» deb yozdi. Shu orada jamoangiz 200 ta commit qilgan.

Qaysi biri buzdi? Birma-bir tekshirsangiz — 200 marta sinov. Bir kunlik ish.

Yechim: har safar yarmini tashlab yuborish

bisect — «ikkiga bo'lish» degani. G'oya juda sodda: o'rtadagi commitni sinaysiz. Agar u yaxshi bo'lsa — xato undan keyin kiritilgan, ya'ni birinchi yarmini butunlay tashlaysiz. Yomon bo'lsa — oldin.

Har qadamda qidiruv maydoni ikki barobar kichrayadi:

QadamQolgan commitlar
Boshlanish1000
1-sinov500
2-sinov250
3-sinov125
……
10-sinov1 — topildi
Mana shu — butun sehr

1000 ta commit → atigi 10 ta sinov. 200 ta commit → 8 ta sinov. Git o'zi hisoblab, har safar sizni to'g'ri joyga olib boradi.

Bitta shart: «buzuqmi?» degan savolga javob bera olishingiz kerak

bisect siz uchun commitlarni almashtirib beradi, lekin tekshirishni siz qilasiz. Shuning uchun oldindan aniq bilishingiz kerak:

  • Qanday tekshiraman? (dasturni ishga tushirish, testni yurgizish, sahifani ochish)
  • Natija qanday bo'lsa yaxshi, qanday bo'lsa yomon?

Javob noaniq bo'lsa, bisect ham noaniq natija beradi. Tekshiruv takrorlanadigan bo'lsin.

Qo'lda: besh buyruq

BuyruqNima qiladi
git bisect start Qidiruvni boshlaydi.
git bisect bad «Hozirgi holat buzuq» — odatda birinchi shuni aytasiz.
git bisect good <hash> «Bu eski commit ishlagan» — ishonchingiz komil bo'lgan nuqta. Shundan keyin Git sizni o'rtaga olib boradi.
git bisect good / bad Har sinovdan keyin javobingiz. Git keyingi commitga o'tkazadi.
git bisect reset ⚠️ Qidiruvni tugatib, odatdagi holatga qaytaradi. Buni unutmang!

Git har qadamda yo'l ko'rsatib turadi

git bisect good Bisecting: 2 revisions left to test after this (roughly 2 steps) [a31fb9c] O'zgarish 9

Ya'ni: «yana taxminan 2 qadam qoldi, hozir 9-commitdasiz». Adashib qolmaysiz.

Oxirida esa javob:

git bisect bad cd500ab... is the first bad commit O'zgarish 8
git bisect reset ni unutmang

Bisect paytida Git sizni tarixning turli nuqtalariga olib yuradi — ya'ni detached HEAD holatida bo'lasiz (19-darsda ko'rgandik). reset qilmasangiz o'sha yerda qolib ketasiz va yangi ishingiz adashadi.

Chalkashsangiz ham xuddi shu buyruq — u har doim xavfsiz orqaga qaytaradi.

Avtomatik: bisect run

Agar tekshiruvni skript qila olsa, butun jarayonni Git o'zi bajaradi:

git bisect run ./sinov.sh

Siz choy ichib turasiz, Git esa 10 qadamni bir necha soniyada bosib o'tadi.

Qoida tanish bo'lishi kerak

Skript chiqish kodi bilan javob beradi: 0 = yaxshi, noldan farqli = yomon.

Bu aynan 18-darsdagi qoida — GitHub Actions ham shunday ishlaydi. Bir marta o'rgangan narsangiz ikkinchi joyda ishlayapti.

Loyihangizda test bo'lsa, skript ham kerak emas:

git bisect run npm test
git bisect run pytest

Amaliyot: yashiringan xatoni ovlaymiz

Mashq nusxa papkada. 12 ta commitlik tarix yaratamiz va ulardan birida xato bo'ladi — qaysi birida ekanini bilmagandek qidiramiz.

A qism — «buzuq» tarix yaratish

  1. Toza branch oching

    cd ~/Projects/Learn/Git-nusxa && git switch main && git switch -c bisect-mashqi

    Kutilgan natija: yangi branch.

  2. 12 ta commit yarating

    Skript hisob.py ni yaratadi. Boshida u 4 chiqaradi, keyin «kimdir» buzadi. Qaysi commitda ekanini o'zingiz ham ko'rmang — mashq shirin bo'lsin.

    for i in $(seq 1 12); do if [ $i -lt 8 ]; then echo "print(2 + 2)" > hisob.py; else echo "print(2 + 3)" > hisob.py; fi; echo "qator $i" >> jurnal.txt; git add hisob.py jurnal.txt; git commit -q -m "O'zgarish $i"; done && git log --oneline | head -3

    Kutilgan natija: «O'zgarish 12», «11», «10» commitlari ko'rinadi.

  3. Xatoni tasdiqlang

    Tekshiruvimiz shu: 4 chiqsa yaxshi, 5 chiqsa buzuq.

    python3 hisob.py 5

    Kutilgan natija: 5 — ya'ni buzuq. 4 bo'lishi kerak edi.

  4. Eng eski commitning hash'ini oling

    Bu bizning «ishonchli yaxshi» nuqtamiz bo'ladi.

    git log --oneline | tail -1

    Kutilgan natija: eng eski commit. Uning hash'ini yozib oling — keyingi qadamda kerak.

B qism — qo'lda ovlash

  1. Qidiruvni boshlang

    ⚠️ ESKI-HASH o'rniga oldingi qadamdagi hash'ni yozing.

    git bisect start && git bisect bad && git bisect good ESKI-HASH Bisecting: 5 revisions left to test after this (roughly 3 steps)

    Kutilgan natija: «roughly 3 steps» — Git 12 ta commitni 3 qadamda qidirib beradi. 1-g'alaba. 🎉

  2. Sinang va javob bering

    Git sizni o'rtadagi commitga olib keldi. Endi tekshirasiz.

    python3 hisob.py

    Bajaring: natijaga qarab bittasini yozing —
    4 chiqsa → git bisect good
    5 chiqsa → git bisect bad
    Kutilgan natija: Git keyingi commitga o'tkazadi va necha qadam qolganini aytadi.

  3. Takrorlang — Git «topildi» degunicha

    Har safar: python3 hisob.py → natijaga qarab good yoki bad. Bor-yo'g'i 3–4 marta.

    python3 hisob.py # keyin: git bisect good yoki git bisect bad

    Kutilgan natija: oxirida shunday chiqadi:
    ... is the first bad commit
        O'zgarish 8
    Aybdor topildi — 8-commit. 2-g'alaba. 🎉

  4. ⚠️ Qidiruvni yoping

    Eng ko'p unutiladigan qadam. Busiz «detached HEAD»da qolib ketasiz.

    git bisect reset && git log --oneline -1 Switched to branch 'bisect-mashqi'

    Kutilgan natija: branch'ingizga qaytdingiz va python3 hisob.py yana 5 chiqaradi (oxirgi holat).

C qism — avtomatik ovlash

  1. Tekshiruv skriptini yozing

    Skript hech narsa chop etmaydi — faqat chiqish kodi bilan javob beradi: 4 bo'lsa 0, aks holda 1.

    cat > sinov.sh << "EOF" #!/bin/sh [ "$(python3 hisob.py)" = "4" ] EOF chmod +x sinov.sh && ./sinov.sh; echo "chiqish kodi: $?"

    Kutilgan natija: chiqish kodi: 1 — hozir buzuq, ya'ni skript to'g'ri ishlayapti.

  2. 🤖 Git o'zi topsin

    Endi hech narsa yozmaysiz — faqat kuzatasiz.

    git bisect start && git bisect bad && git bisect good ESKI-HASH && git bisect run ./sinov.sh running './sinov.sh' ... bisect found first bad commit

    Kutilgan natija: Git bir necha soniyada o'sha 8-commitni topadi — qo'lda qilganingiz bilan bir xil javob. 3-g'alaba. 🎉🎉

  3. Yoping va tozalang

    git bisect reset && git switch main && git branch -D bisect-mashqi

    Kutilgan natija: mashq branch o'chirildi. -D ishlatildi, chunki u merge qilinmagan (14-dars). Kerak bo'lsa reflog qaytaradi.

Yodda tuting (checklist)

💻 Amaliy qism kompyuterda

Amaliyotda 12 ta commitlik «buzuq» tarix yaratasiz va aybdorni ikki xil usulda topasiz: qo'lda (Git sizni har safar o'rtaga olib boradi, siz good/bad deysiz — atigi 3–4 qadam) va avtomatik (git bisect run bilan — Git o'zi bajaradi). 11 qadam.

Tekshirib ko'ramiz (quiz)

SAVOL 1 1000 ta commit bor. Bisect necha sinovda topadi?

To'g'ri — bu butun sehr. Har sinov qidiruv maydonini ikki barobar kichraytiradi: 1000 → 500 → 250 → … → 1.

SAVOL 2 Bisect ishlashi uchun nima shart?

To'g'ri. Test bo'lsa yaxshi (avtomatlashtirasiz), lekin shart emas — qo'lda ham tekshirish mumkin. Muhimi: tekshiruv takrorlanadigan bo'lsin.

SAVOL 3 Bisect tugagach nima qilish shart?

To'g'ri. Bisect paytida detached HEADdasiz. reset qilmasangiz o'sha yerda qolib ketasiz. Chalkashsangiz ham xuddi shu buyruq qutqaradi.

SAVOL 4 git bisect run skriptdan nimani kutadi?

To'g'ri — 18-darsdagi GitHub Actions bilan aynan bir xil qoida. Bir marta o'rgangan tushuncha ikkinchi joyda ishlayapti.

Eslab ayting (o'zingizni sinang)

Avval o'zingiz javob bering, keyin ochib tekshiring.

Bisect'ning asosiy g'oyasi?

Har sinovda qidiruv maydonining yarmini tashlab yuborish. Shuning uchun 1000 ta commit atigi ~10 ta sinovda tekshiriladi.

Boshlashning uch buyrug'i?

git bisect start → git bisect bad (hozirgi buzuq) → git bisect good <eski-hash> (ishlagan nuqta).

Eng ko'p unutiladigan qadam?

git bisect reset — busiz detached HEADda qolib ketasiz. U chalkashganda ham xavfsiz qutqaruv buyrug'i.

bisect run skriptdan nimani kutadi?

Chiqish kodini: 0 = yaxshi, noldan farqli = yomon. Xuddi GitHub Actionsdagi kabi.

↩︎ Takrorlash: aybdor commitni topdingiz. Endi uni qanday o'rganasiz?

git show <hash> — o'sha commitda aynan nima o'zgarganini satrma-satr ko'rsatadi. (Dars 03)

Cho'ntak xulosasi
  • Bisect = ikkiga bo'lib qidirish. 1000 commit → ~10 sinov.
  • Shart: «buzuqmi?» degan savolga takrorlanadigan javob.
  • Boshlash: git bisect start → bad → good <eski-hash>.
  • Har sinovdan keyin: git bisect good yoki bad. Git necha qadam qolganini aytib turadi.
  • Javob: ... is the first bad commit.
  • ⚠️ Oxirida har doim git bisect reset — aks holda detached HEAD'da qolasiz.
  • Avtomatik: git bisect run ./sinov.sh (yoki npm test, pytest) — 0 = yaxshi, noldan farqli = yomon.
  • Topilgach: git show <hash> bilan nima o'zgarganini ko'ring.
