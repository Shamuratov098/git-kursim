REFERENCE · BUYRUQLAR VARAQASI

Git buyruqlari — cho'ntak varaqasi

Faqat o'rganilgan buyruqlar. Amaliyot paytida shu sahifani ochib qo'ying. Kurs o'sgani sari bu varaqa ham to'ldirib boriladi.

💻 Amaliyot yonida ochib turing 🖨️ Bosib olsa ham bo'ladi Qamrov: Dars 01–11 (to'liq)

Oltin qoida

Nima qilishni bilmasangiz — git status. U hech narsani buzmaydi, hozirgi holatni ko'rsatadi va keyingi qadamni maslahat beradi.

Kunlik aylana

Tahrirla

Working Directory
Faylni yozasiz / o'zgartirasiz
→git add

Tanla

Staging Area
Commitga nima kirishini tanlaysiz
→git commit

Saqla

Repository
Tarixga doimiy yoziladi

1. Sozlash (bir marta)

BuyruqNima qiladi
git --version Git o'rnatilganini va versiyasini ko'rsatadi.
git config --global user.name "Ism" Commit muallifining ismini belgilaydi.
git config --global user.email "siz@..." Commit muallifining emailini belgilaydi. GitHub email'ingiz bilan bir xil bo'lsin.
git config --global init.defaultBranch main Yangi repolarda asosiy branch nomi main bo'lsin.
git config --global pull.rebase false git pull ajralgan branch'larda merge ishlatsin. Bu bo'lmasa pull «Need to specify how to reconcile divergent branches» deb to'xtaydi (Dars 10).
git config --global --list Barcha global sozlamalarni ko'rish. Chiqish: q

2. Repo boshlash

BuyruqNima qiladi
git init Joriy papkani Git repo'siga aylantiradi (yashirin .git yaratiladi).
git init -b main Xuddi shu, lekin asosiy branch nomi darhol main bo'ladi.

3. Kuzatish va tarix — «ko'zoynagingiz»

BuyruqNima qiladi
git status Fayllar qaysi hududda: untracked / modified / staged.
git status -s Qisqa ko'rinish. ?? untracked · A added · M modified
git log Commitlar tarixi (to'liq: hash, muallif, sana, izoh).
git log --oneline Tarix qisqa ko'rinishda — har commit bitta qatorda.
git diff Hali add qilinmagan o'zgarishlar (working ↔ staging farqi).
git diff --staged Allaqachon add qilingan o'zgarishlar (staging ↔ oxirgi commit).
git show Oxirgi commit ichida nima bo'lgani (ma'lumot + satrma-satr farq).
git show a1b2c3d Aniq bir commitning ichini ko'rish.
diff chiqishini o'qish

+ — qo'shilgan qator (yashil) · - — o'chirilgan qator (qizil). Uzun chiqishdan q bilan chiqasiz.

4. Saqlash: add va commit

BuyruqNima qiladi
git add fayl.txt Bitta faylni saralash joyiga qo'yadi.
git add . Joriy papkadagi hamma o'zgarishni qo'shadi. Tez, lekin avval git status bilan tekshiring.
git commit -m "izoh" Saralangan o'zgarishlarni tarixga yozadi.
git commit -am "izoh" add + commit birga. Faqat allaqachon kuzatilayotgan fayllar uchun — yangi fayl tushmaydi.

5. «Xato qildim» — orqaga qaytarish

Qoida: xato qaysi hududda bo'lsa — o'sha hududning buyrug'i. Va har doim avval git diff bilan ko'ring. (Dars 03)

BuyruqNima qiladi
git restore fayl.txt Ish papkasi. Fayldagi saqlanmagan o'zgarishlarni bekor qiladi. ⚠️ Yagona xavfli buyruq — o'zgarishlar butunlay yo'qoladi. Avval git diff!
git restore --staged fayl.txt Staging. Noto'g'ri add qilingan faylni podnosdan qaytaradi. ✓ Xavfsiz — matn joyida qoladi, faqat holati staged → modified.
git commit --amend -m "yangi izoh" Oxirgi commit. Izohini tuzatadi yoki unutilgan faylni qo'shadi (avval git add). ✓ Xavfsiz — lekin faqat hali push qilinmagan commit uchun.

6. GitHub bilan ishlash

To'liq yo'l: Working →add→ Staging →commit→ Local repo →push→ GitHub. (Dars 04)

BuyruqNima qiladi
git remote -v Qaysi internetdagi manzil bilan bog'langanini ko'rsatadi.
git push Mahalliy commitlarni GitHub'ga jo'natadi. ⚠️ Faqat commit qilingan narsani jo'natadi — tahrirlangan, commit qilinmagan fayl ketmaydi.
git push -u origin main Birinchi marta uchun: qayerga push qilishni eslab qoladi. Keyin doim qisqa git push yetarli.
git status «ahead of 'origin/main' by N commits» — nechta commit hali jo'natilmagani.
git log --oneline Tarixda origin/main xatcho'pi qayerda turganini ko'rsatadi.

GitHub'dan olish (Dars 05)

BuyruqNima qiladi
git clone <url> Loyiha sizda yo'q edi — noldan oladi. Papka + butun tarix + origin + bog'lanish, hammasi birdan. Papkaga nom berish: git clone <url> yangi-nom
git fetch origin/main xatcho'pini yangilaydi. ✓ Xavfsiz — fayllaringizga tegmaydi.
git pull fetch + merge. Yangiliklarni olib, ishingizga qo'shadi. Kundalik odat: ish boshlashdan oldin commit → pull.
git log --oneline main..origin/main fetch dan keyin: sizda yo'q, GitHub'da bor commitlar — ya'ni nima kelayotgani.
Push'dan keyin

--amend — faqat push'gacha. Push qilingan commit boshqalarda ham bor; uni almashtirsangiz tarix ikkiga bo'linadi. Push'dan keyin tuzatishni yangi commit bilan qo'shasiz.

7. Branch bilan ishlash (Dars 06)

Branch — bitta commitga ishora qiluvchi ko'chib yuruvchi yorliq, nusxa emas. Shuning uchun yaratish bir zumda bo'ladi.

BuyruqNima qiladi
git branch Branch'lar ro'yxati. * — hozir qaysi birida turganingiz. ✓ Xavfsiz, faqat ko'rsatadi.
git switch -c login Yaratadi va darhol o'tadi (-c = create).
git switch main Mavjud branch'ga o'tadi. ⚠️ Papkangiz o'sha branch holatiga aylanadi — fayllar ko'rinmay qolishi mumkin. Bu normal.
git switch - Oldingi branch'ga qaytadi.
git branch -d login Branch yorlig'ini o'chiradi (merge qilingandan keyin).
git log --oneline main..mening-branch «Mening branch'imda mainda yo'q nima bor?»
Branch almashishdan oldin

Ishingizni commit qiling. Saqlanmagan o'zgarish bo'lsa, Git ba'zan almashishga ruxsat bermaydi. Eski maqolalardagi git checkout <branch> — xuddi shu ish, eski usul.

8. Merge — ishni asosiyga qo'shish (Dars 07)

Yo'nalishni chalkashtirmang

Merge har doim siz turgan branch'ga qo'shadi. Avval qabul qiluvchiga o'ting: git switch main → keyin git merge login.

BuyruqNima qiladi
git merge login loginni joriy branch'ga qo'shadi. Chiqishda «Fast-forward» yoki «Merge made by...» yoziladi.
git merge login --no-edit Xuddi shu, lekin merge izohi uchun tahrirlagich ochilmaydi. Boshlovchi uchun qulay.
git log --oneline --graph Tarixni grafik ko'rinishda: |\ ajralish, |/ birlashish.
git branch -d login Tugagan branch yorlig'ini o'chiradi. ✓ Xavfsiz: merge qilinmagan bo'lsa o'chirmaydi. Commitlar main ichida qoladi.
git merge --abort Merge chala qolgan bo'lsa, boshlangunidagi holatga qaytaradi. Dars 08 da kerak bo'ladi.

Ikki xil merge — farqi

ChiqishNima bo'ldi
Fast-forward main siz branch ochganingizdan beri qimirlamagan → Git yorliqni oldinga surdi. Yangi commit yaratilmadi.
Merge made by... Ikkala tomon ham siljigan → Git ikkita ota-onali yangi merge commit yaratdi.

9. Merge conflict (Dars 08)

Konflikt faqat bitta faylning bitta joyi ikki tomondan boshqacha o'zgartirilganda chiqadi. Bu xato emas — Git o'zi tanlab qo'ymaydi.

Buyruq / belgiNima qiladi
git merge --abort Qochish yo'li. Merge boshlangunga qadar bo'lgan holatga qaytaradi. ✓ Istalgan vaqt, xavfsiz. Hech narsa yo'qolmaydi.
git status «both modified» — qaysi fayllarda konflikt borligini ko'rsatadi va keyingi qadamni aytadi.
git add fayl.txt Konflikt paytida ma'nosi: «bu fayldagi ziddiyat hal qilindi».
git commit --no-edit Merge'ni yakunlaydi (tahrirlagich ochilmasdan).
<<<<<<< HEAD Bu yerdan boshlab — siz turgan branch'dagi variant.
======= Ikki variantni ajratuvchi chiziq (matnning qismi emas).
>>>>>>> branch-nomi Bu yergacha — kelayotgan branch'dagi variant.
Hal qilish — 3 qadam

1. Faylni tahrirlang va belgilarni butunlay o'chiring (ular Git yozgan vaqtinchalik qatorlar) → 2. git add fayl → 3. git commit.

Sizdan tanlash emas, yakuniy matn so'ralyapti: sizniki, ularniki, ikkalasi yoki butunlay yangisi.

10. Pull request aylanasi (Dars 09)

PR — GitHub imkoniyati, Git buyrug'i emas (git pull request yo'q). To'liq aylana: branch → push → PR → review → merge → pull.

QadamNima qilinadi
git switch -c ish-nomi Ish uchun branch ochasiz. Avval git switch main && git pull — eng yangi holatdan boshlang.
git push -u origin ish-nomi Branch'ni birinchi marta GitHub'ga jo'natasiz. Git chiqishda PR ochish havolasini beradi.
GitHub: Compare & pull request PR ochasiz: sarlavha (nima) + tavsif (nega).
GitHub: Files changed Review shu yerda — satrma-satr farq, har satrga izoh. Javoblar: Approve · Request changes · Comment.
GitHub: Merge pull request Qo'shiladi, keyin Delete branch.
git switch main && git pull ⚠️ Eng ko'p unutiladigan qadam. Merge internetda bo'ldi — mahalliy main hali eski.
git branch -d ish-nomi Mahalliy branch'ni ham tozalaysiz.
Yaxshi PR

Kichik bo'lsin (katta PR yuzaki o'qiladi) · bitta PR = bitta mavzu · sarlavhada nima, tavsifda nega · review'da buyruq emas savol bering, kod haqida gapiring — odam haqida emas.

11. Kundalik jamoa ritmi (Dars 10)

Aylana: pull → branch → ishla+commit → push → PR → merge → pull…

QachonBuyruq
☀️ Kun boshi git switch main && git pull Keyin darhol: git switch -c ish-nomi
🛠️ Ish davomida git add . && git commit -m "..." Kichik commitlar; kuniga kamida bir marta git push.
🌙 Ish tugagach git push → GitHub'da PR → merge → git switch main && git pull && git branch -d ish-nomi

Muammo → yechim

Ko'rgan narsangizNima qilasiz
! [rejected] (fetch first) Sizdan oldin kimdir push qilgan (bu himoya).
git pull → git push.
Need to specify how to reconcile divergent branches Git «merge bilanmi yoki rebase bilanmi?» deb so'rayapti. Bir martalik sozlama: git config --global pull.rebase false Keyin git pull har doim ishlaydi.
Branch eskirib qoldi git switch main && git pull → git switch mening-branchim && git merge main --no-edit Yo'nalish teskari: main'ni o'zingizga olasiz. Har kuni qiling — konflikt kichik qoladi.
mainda commit qilib qo'ydim (push qilmagan) 1. git switch -c ishim-uchun-branch → 2. git switch main && git reset --hard origin/main ⚠️ reset --hard so'ramasdan o'chiradi. 1-qadamsiz bajarmang. Shubha bo'lsa — so'rang.
Noto'g'ri branch'daman (commit qilmagan) git switch to-g-ri-branch. Git ruxsat bermasa — avval commit qiling.
Umuman chalkashib ketdim git status — va natijani o'qing (yoki menga tashlang).

12. .gitignore (Dars 11)

Git kuzatmasligi kerak bo'lgan fayllar ro'yxati. Loyihaning ildizida turadi va Git tomonidan kuzatiladi — ya'ni jamoa bilan birga ishlaydi.

Belgi / buyruqMa'nosi
# izohIzoh qatori.
*.log* = istalgan matn — barcha .log fayllar.
node_modules/Oxiridagi / = butun papka.
!muhim.log! = istisno (rad etilganni qaytarish).
git rm --cached fayl.log Allaqachon kuzatilayotgan faylni kuzatuvdan chiqaradi. ⚠️ --cached yozmasangiz fayl o'chib ketadi. U bilan — fayl diskda qoladi.
git add -f fayl Ignore qilingan faylni majburan qo'shish (kamdan-kam kerak).
Ikkita muhim nuqta

1. .gitignore allaqachon commit qilingan faylga ta'sir qilmaydi → avval git rm --cached.
2. Sir (parol, .env, API kalit) bir marta push qilinsa, u tarixda qoladi — faylni o'chirish yetarli emas, parolni almashtiring.

Tayyor shablonlar: github.com/github/gitignore.

Yaxshi commit izohi qanday bo'ladi?

Asosiy qoida

Diff nima o'zgarganini ko'rsatadi — izoh nega o'zgarganini aytadi.

  • Qisqa va aniq: "Login sahifasi qo'shildi", "Bo'sh email xatosi tuzatildi".
  • "update", "fix", "asdf" — hamkasbingizga hech narsa aytmaydi.
  • Bir commit = bir fikr. Ikki xil ish qilgan bo'lsangiz — ikki commit.
  • Uzunroq izoh: git commit -m "sarlavha" -m "tavsif" (birinchisi log --onelineda, ikkinchisi git showda).
