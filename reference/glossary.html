repository (repo) — loyiha ombori
Loyihangiz va uning butun tarixi saqlanadigan joy. Texnik jihatdan — loyiha papkasidagi yashirin .git papkasi. git init → repo yaratiladi
working directory (working tree) — ish papkasi
Siz hozir ko'rib, tahrirlab turgan fayllar. Git "kuzatadigan" papkaning ko'rinadigan qismi. papkadagi .py, .txt, .js fayllaringiz
staging area (index) — saralash joyi
Keyingi commitga aynan qaysi o'zgarishlar kirishini tanlaydigan "oraliq savat". git add fayllarni shu yerga qo'yadi. git add file.txt → staging'ga tushadi
untracked — kuzatilmayotgan fayl
Yangi yaratilgan fayl: Git uni ko'radi, lekin hali kuzatmaydi — tarixga kiritmagan. git add qilinsa kuzatiladigan bo'ladi. git status → "Untracked files"
modified — o'zgargan fayl
Git kuzatadigan fayl tahrirlangan, lekin hali stagingga qo'yilmagan. git status → "Changes not staged for commit"
staged — saralangan / tayyorlangan
Fayl git add qilingan va keyingi commitga kirishga tayyor. Hali tarixga yozilmagan. git status → "Changes to be committed"
committed — tarixga yozilgan
O'zgarish repository'ga doimiy saqlandi. Bunda ish papkangiz "toza" bo'ladi. git status → "working tree clean"
commit — saqlangan holat / "nuqta"
Loyihaning ma'lum bir ondagi snapshoti: kim, qachon, nima o'zgartirgani yozib qo'yiladi. Tarixning bir "qadami". git commit -m "Login sahifasi qo'shildi"
snapshot — holat nusxasi
Git har commitda fayllaringizning o'sha ondagi to'liq holatini rasmga olgandek saqlaydi (faqat farqni emas — shuning uchun tezda istalgan holatga qaytasiz).
commit message — commit izohi
Har commitga yoziladigan qisqa tushuntirish: nima va nega o'zgardi. Jamoada juda muhim. "Fix: bo'sh email xatosi tuzatildi"
branch — shox / tarmoq
Bitta commitga ishora qiluvchi ko'chib yuruvchi yorliq (pointer) — nusxa emas. Shuning uchun yaratish bir zumda bo'ladi. Unda commit qilsangiz, faqat o'sha yorliq siljiydi; main joyida qoladi. Ish tugagach asosiyga merge qilinadi. git switch -c login-sahifasi
switch — branch almashtirish
HEADni boshqa branch'ga ko'chiradi. Shu bilan birga ish papkangiz o'sha branch holatiga aylanadi — fayllar ko'rinmay qolishi mumkin (normal holat). -c = yarat va o't; - = oldingisiga qayt. git switch -c login · git switch main · git switch -
feature branch — ish uchun branch
Jamoadagi odatiy tartib: har bir yangi ish (funksiya yoki tuzatish) uchun alohida branch ochiladi, main esa doim ishlaydigan holatda qoladi. Pull request aynan shu branch ustida ochiladi. feature/login · fix/email-xatosi
HEAD — "men hozir qayerdaman"
Hozir qaysi branch/commitda turganingizni ko'rsatuvchi belgi (ko'rsatkich).
main / master — asosiy branch
Odatdagi asosiy branch nomi. Yangi loyihalarda main, eskilarda ko'pincha master. Ikkalasi ham shunchaki nom.
merge — birlashtirish
Bir branchdagi o'zgarishlarni boshqasiga qo'shish. Har doim siz turgan branch'ga qo'shadi — shuning uchun avval qabul qiluvchiga o'tasiz. Ikki xil bo'ladi: fast-forward yoki merge commit. git switch main → git merge login
merge commit — birlashtiruvchi commit
Ikkita ota-onasi (parent) bo'lgan maxsus commit — ikki tarixni bog'laydi. Ikkala branch ham ajralganidan keyin siljigan bo'lsa yaratiladi. Merge made by the 'ort' strategy.
merge conflict — birlashtirish ziddiyati
Ikki tomon bitta faylning bitta joyini har xil o'zgartirsa, Git qaysi birini olishni bilmaydi va sizdan hal qilishni so'raydi. Xato emas — himoya: Git o'zi tanlaganida kimningdir ishi jimgina yo'qolardi. Hal qilish: faylni tahrirla → git add → git commit. Qochish yo'li — git merge --abort. CONFLICT (content): Merge conflict in salom.txt
conflict markers — konflikt belgilari
Git konflikt paytida fayl ichiga yozadigan vaqtinchalik qatorlar: <<<<<<< HEAD (bu yerdan — sizdagi variant), ======= (ajratuvchi chiziq), >>>>>>> branch-nomi (bu yergacha — kelayotgan variant). Ularni albatta o'chirish kerak — matnning qismi emas.
remote — masofaviy repo
Internetdagi nusxa (masalan GitHub'da). Jamoa shu orqali kod almashadi.
origin — asosiy remote nomi
remotening odatdagi nomi — odatda sizning GitHub repongiz. git push origin main
clone — nusxa ko'chirib olish
Internetdagi repo'ni butun tarixi bilan kompyuteringizga ko'chirish. git clone https://github.com/user/repo.git
push — yuklash (yuqoriga)
Kompyuteringizdagi commitlarni remotega (GitHub'ga) jo'natish. git push
pull — tortib olish (pastga)
Remote'dagi yangi o'zgarishlarni o'zingizga olib, qo'shib qo'yish (fetch + merge). git pull
fetch — yangiliklarni keltirish
Remote'dagi o'zgarishlarni ko'rib chiqish uchun keltiradi, lekin kodingizga hali qo'shmaydi. pull = fetch + merge.
pull request (PR) — qo'shish so'rovi
GitHub'da: «mening branch'imdagi o'zgarishlarni asosiy kodga qo'shaylik» degan taklif. Jamoa ko'rib chiqadi (review) va tasdiqlaydi. Jamoa ishining yuragi. ⚠️ Bu Git buyrug'i emas — git pull request degan buyruq yo'q. git push -u origin login → GitHub'da PR ochiladi
code review — kodni ko'rib chiqish
Hamkasbingiz PRingizdagi o'zgarishlarni satrma-satr o'qib, izoh qoldirishi. GitHub'da Files changed bo'limida qilinadi. Uch xil javob: Approve (joyida), Request changes (tuzatish kerak), Comment (fikr yoki savol).
fork — o'z nusxangizga ko'chirish
Birovning GitHub repo'sini o'z akkauntingizga nusxalash. Open source'ga hissa qo'shishda ishlatiladi.
.gitignore — e'tibor bermaslik ro'yxati
Git kuzatmasligi kerak bo'lgan fayllar ro'yxati: sirlar (.env, parollar), yaratiladigan fayllar (node_modules/, build/), shaxsiy sozlamalar (.idea/). Belgilar: # izoh · * namuna · / papka · ! istisno. ⚠️ Allaqachon commit qilingan faylga ta'sir qilmaydi — avval git rm --cached fayl. *.log · .env · node_modules/
cherry-pick — bitta commitni tanlab olish
Boshqa branchdagi aynan bir commitni joriy branch'ga nusxa qilib qo'shadi (asl commit o'z joyida qoladi). Butun branch kerak bo'lsa — merge. -x bilan izohga «cherry picked from…» yozuvi qo'shiladi. git switch main → git cherry-pick -x 2e4e07d
reflog — bosib o'tgan yo'l yozuvi
Git HEAD qayerda bo'lganini yozib boradigan mahalliy jurnal: har commit, switch, merge, rebase, reset. «O'chirilgan» commit repozitoriyada qolaveradi — faqat yorliq yo'qoladi, reflog esa uni topib beradi. Falokat bo'lsa birinchi buyruq. ⚠️ Commit qilinmagan ishni qaytara olmaydi; mahalliy va ~90 kunlik. git reflog → git reset --hard HEAD@{1}
rebase — poydevorni almashtirish
Commitlaringizni «ko'tarib olib», eng yangi main ustiga qayta qo'yish. Natijada tarix merge commitsiz, to'g'ri chiziq bo'ladi. ⚠️ Commitlarni ko'chirmaydi — yangisini yaratadi (hash o'zgaradi). 🔴 Oltin qoida: push qilingan commitlarni rebase qilmang. Shubha bo'lsa — merge. git rebase main · --continue · --abort
stash — javon / vaqtinchalik joy
Tugallanmagan ishni commit qilmasdan olib qo'yadigan alohida joy. Ish papkangiz tozalanadi, tarixga esa hech narsa yozilmaydi. Branchga bog'lanmagan — bir joyda qo'yib, boshqasida olish mumkin. ⚠️ Faqat mahalliy: push qilinmaydi, ya'ni zaxira nusxa emas. git stash push -m "yarim ish" → git stash pop
README.md — loyihaning yuzi
GitHub repo sahifasida avtomatik ko'rsatiladigan fayl. Uch savolga javob bersin: bu nima · qanday ishga tushiraman · qanday hissa qo'shaman. .md = Markdown.
Markdown — oddiy matnni bezash usuli
Bir necha belgi bilan matnni sarlavha, ro'yxat va havolaga aylantiradi. GitHub README, PR tavsifi va izohlarda ishlatiladi. # Sarlavha · **qalin** · - ro'yxat · [matn](havola)
commit hash (SHA) — commit "passporti"
Har commitning takrorlanmas uzun ID'si. Odatda dastlabki 7 belgisi yetarli. a1b2c3d
git config — sozlamalar
Git'ning xulq-atvorini sozlash buyrug'i. --global = shu kompyuterdagi barcha loyihalar uchun (~/.gitconfig fayliga yoziladi); --globalsiz = faqat joriy loyiha uchun. git config --global user.name "Ism"
diff — farq
Ikki holat orasidagi satrma-satr farq. + qo'shilgan qator, - o'chirilgan qator. git diff — hali staged bo'lmagan o'zgarishlar; git diff --staged — staged bo'lganlari. git diff mashq.txt
restore — qaytarish
Ikki xil vazifasi bor: git restore fayl — fayldagi saqlanmagan o'zgarishni bekor qiladi (⚠️ yo'qoladi); git restore --staged fayl — faylni staging'dan chiqaradi (✓ xavfsiz, matn qoladi). Git 2.23+ · eskisi: checkout / reset
amend — oxirgi commitni tuzatish
Oxirgi commitni yangisi bilan almashtiradi — izohini tuzatish yoki unutilgan faylni qo'shish uchun. Faqat hali push qilinmagan commitda ishlatiladi. git commit --amend -m "to'g'ri izoh"
upstream — branch'ning «uyi»
Mahalliy branch qaysi remote branch bilan bog'langani. Bir marta -u bilan o'rnatiladi, keyin qisqa git push / git pull yetarli bo'ladi. git push -u origin main
GitHub flow — kundalik jamoa ritmi
Jamoalarda eng keng tarqalgan ish tartibi: pull → branch → ishla va commit → push → PR → merge → yana pull. main doim ishlaydigan holatda qoladi. Kun boshi: git switch main && git pull
rejected push — rad etilgan push
! [rejected] (fetch first) — sizdan oldin kimdir push qilgan. Xato emas, himoya: Git o'tkazib yuborganida o'sha odamning ishi yo'qolardi. Yechim: git pull, keyin git push.
fast-forward — shunchaki oldinga siljish
Eng oson merge turi: sizda hech qanday yangi commit yo'q edi, shuning uchun Git birlashtirishning hojati bo'lmay, xatcho'pni oldinga surib qo'yadi. git pull ko'pincha shunday tugaydi. Updating 4c20049..7a8b9c0 · Fast-forward
